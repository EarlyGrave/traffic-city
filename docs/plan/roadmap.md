Цель этапа: 1 000 машин + 10 автобусных маршрутов на процедурном городе, замеры perf и качества трафика.
Каждый шаг = одна PR в `main` (squash), CI зелёный, before/after из bench в описании.

Статусы: `todo` / `wip` / `done` / `blocked`.

# Roadmap — этап 2 (черновик оркестратора, 2026-10-24)

Цель: **s10k ≤ 4 мс tick p95 при полной загрузке (10 000 активных машин)**, 0 B/тик, stuck = 0 за 30 мин;
бюджеты s1k не ухудшаются. Ориентир на будущее: s100k ≤ 15 мс (brief-stage1, дополнение владельца).
Основание — «Предложения на этап 2» в `docs/REPORT-stage1.md`. Порядок владельца после s10k:
пешеходы и пассажиры как агенты → зонирование и спрос → low-poly арт (это этапы 3+).

Исходная точка (REPORT-stage1, шаг 5): s10k p95 4.53 мс при **4 991** активных (рампа не завершена);
s100k p95 27.9 мс при 7 470 активных, A* = 57% CPU; s1k: снапшот 16% (собственное время фазы, копирования нет — ADR-0010).

**Решение владельца (2026-10-24):** проект не в релизе — полный карт-бланш на редизайны (API, формат сценариев,
структуры ядра, совместимость не держим), пока владелец не скажет обратное. Каждый редизайн — ADR.

## Шаг 2.1. Честные замеры — `done` (критерий шума не достижим в общем контейнере)
- Сделано: `--warmup-until-full`, ramp-поля в JSON, compare падает при разном `ramp_complete`; единый `scripts/bench-gate.sh`
  (Stop-хук + CI) с повтором до 3 попыток: ложный FAIL 12% → 0.2% (моделирование на 52 процессах).
- Шум: ~14 вариантов рантайма/планировщика без эффекта; источник — скорость VM (steal) и соседи. Две подряд s1k: 29%/3%/8%.
- **s10k при полной загрузке (10 000 активных): p50 10.2 / p95 13.2 мс** (рампа 5900 тиков) — до цели 4 мс ×3.3.
- Хвосты: пересъём `perf/baseline.json` с ramp-полями на тихой машине (после H3); `demo-grid` всегда 0 активных — проверить;
  детерминированная мера работы (счётчики операций по фазам) как сигнал регрессии без шума — кандидат в 2.4.
- (sonnet) bench: прогрев до завершения рампы (активные = цель или предел тиков), в результате — активные машины
  и признак «рампа завершена»; снижение шума p95 (±13% > допуска compare 10%): медиана повторов, отброс первого
  повтора, пиннинг/приоритет — что реально работает в контейнере. Параметры bench едины во всех местах (lessons.md).
- (haiku) цифры s10k/s100k при полной загрузке → REPORT-stage2 «до».
- (sonnet, после 2.3) время фаз через `Simulation.OnPhaseEnd` (core-api §3, в коде нет) → в JSON bench по фазам:
  честная мера вместо сэмплирующего профиля (он смещён к safe point).
- Критерий: два подряд прогона s1k без изменений кода расходятся по p95 ≤ 5%; s10k меряется при 10 000 активных.
