## Цель этапа (предложение)
**Город требует ухода, и уход упирается в трафик.** Здания ветшают, службы ездят по тем же пробкам, у каждого вида зоны
свой транспорт, жители живут разным ритмом, а облик города складывается из истории его постройки.
Мерило — плейтест владельца: проблема вехи (рассказчик) решается службами, транспортом и планировкой, а не ожиданием на ×4.

## Порядок и зависимости
```
Спеки (по одной, решение владельца):          VC → BL → SR → LP(+ADR) → FR → RA → AP → ST (после ответов владельца, см. ниже)
Реализация ядра (по одному, общие файлы):     VC → BL + ЖКХ (первая выездная служба) → SR остальное (+ RA) → FR → LP
Клиент (параллельно ядру, game/**):           AP (сразу после спеки, поля ядра — малой задачей) → UI служб/зон → кисть/крафт LP
Рассказчик:                                   ST после BL + SR (ему нужны проблемы, которые можно решать)
```
- **VC первым:** класс ТС и ограничения по классу нужны спецмашинам (SR), фурам (FR) и ЖКХ (BL).
- **BL раньше SR:** ЖКХ — первая выездная служба, на ней обкатывается диспетчер; остальные службы — данными поверх.
- **LP последним в ядре:** самая большая переделка (участки, сейв, миграция); ждёт TR6/TR10 этапа 6 (штамп площадок зданий в рельеф
  трогает те же участки) и FR (новые виды зон меняют нарезку).
- **AP не ждёт ядро:** генератор моделей в клиенте можно начинать на нынешних коробках (вид, плотность, seed = индекс участка);
  поля стиля и эпохи — малая задача ядра позже.

## Распределение по средам (предложение)
| Среда | Что | Почему |
|---|---|---|
| **Облако** | реализация ядра: VC, BL, SR, RA, FR, LP, ST-ядро | эталон бенча облачный — DoD по производительности засчитывается только там; ядро и так ведёт облако (TR) |
| **Локал** | спеки (волны 1–2), клиент: AP, UI служб и зон, кисть/крафт LP | клиент Godot — у локала (TC, UI); спеки — `docs/design/**`, с ядром облака не конфликтуют |
Спеки можно писать в обеих средах — каждая в своей ветке, захват в `claims.md`.
> **Решение владельца 2026-10-29:** таблица выше — не правило. Распределение по средам контролирует владелец: задачу, которую он
> ставит в сессии, делают там же, не откладывают «на облако». Цепочка VC1–VC4 — локал. Локальный `bench-gate` — справочно,
> `update-baseline` локально не запускать; подтверждение бюджета на облачном эталоне — по решению владельца.

## Цена и риски (оценка, цифры — после спек)
- **Эталоны:** VC, RA, FR, SR меняют поведение `*-res` → пересборка эталонов и сейв-корпуса; s1k (OD) — проверить в каждой спеке, задевает ли.
- **Бюджет тика:** VC (проверка класса в горячем цикле), SR (диспетчер), FR (грузовые поездки) — s1k p95 ≤ 1 мс и 0 Б/тик, замер в облаке.
- **`world_version`:** несколько блоков пишут новые столбцы сейва — номера версий раздаются при захвате, как в TR (риск гонки ADR-0035/рельеф).
- **LP:** отменяет принятое решение о мировой сетке; риск — дробная геометрия и детерминизм → только целые мм, golden-тест кросс-хэша.
