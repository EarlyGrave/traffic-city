# L88 — YS1: каркас сценариев (секции `meta` и `goals`, `world_version` 15)

Ветка `local/ys1-goals` от `dev` (c317fae). Спека: `docs/design/scenarios-mode.md` §1.2, §1.3, §2.2–§2.3, ADR-0038, решения владельца 2026-10-29 (В1 — А).

## Что сделано
- **Ядро, POD** (`Api/Goals.cs`): `GoalKind` (10 значений, номера закреплены), `GoalCondDesc` (12 Б: `Kind, Kpi, R, Value, HoldHours`),
  `GoalsDesc` (`GraceHours, AfterWin, WinCount, LoseCount, W0..W7, L0..L7`, `Get/Set` по сквозному индексу), `GoalOutcome`, `GoalsInfo`, `GoalCondInfo`.
  `ScenarioDesc.Goals`; `Enabled = WinCount + LoseCount > 0`.
- **Состояние** (`City/Goals.cs`, `CityWorld.Goals`, `null` без секции): 16 слотов условий, `HeldHours[16]`, `HoursElapsed`, `Outcome`, `OutcomeTick`, `LoseIndex`.
  Проверка `OnHourEnd` — фаза 9r на последнем тике игрового часа, **после** KPI, вех и границы суток (`CityPhase.Periodic`). Сначала поражение (только при
  `HoursElapsed > GraceHours`; в грейс счётчики поражения не копятся), потом победа; в один час поражение важнее. После исхода проверок нет. Только целые, 0 Б, O(16)
  (KPI-окно считается один раз за проверку, если есть KPI-условие).
- **Условия:** `population_ge/lt` (живые жители), `treasury_lt` (счёт City), `insolvent` (`CityBudget.Insolvent`), `kpi_le/ge` (24 полных часа кольца, нет данных —
  не выполнено), `milestone` (`Progression.Reached > value`), `day_ge` (`CityWorld.Day`), `prestige_ge` — **разбирается, но не вычисляется до YS2** (никогда не выполнено,
  загрузчик пишет предупреждение).
- **Событие** `SimEventKind.ScenarioOutcome = 68` (A = 1 победа / 2 поражение, B = индекс условия поражения, -1 при победе).
- **API** (`Api/Simulation.Goals.cs`): `HasGoals`, `TryGetGoals(out GoalsInfo)`, `GetGoalCond(int i)` (0..7 победа, 8..15 поражение; `Current` — живое значение).
- **Create:** `WorldBuilder.ValidateGoals` — только при жителях, `GoalsState.Validate` (счётчики ≤ 8, виды, KPI только у `kpi_*`, пустые слоты нулевые) → `InvalidCity`.
- **Хэш:** раздел целей в конце `CityHash.Add`, только при секции; `hash_version` 4 без изменений.
- **Сейв:** `world_version` 15 (Y4 = 13, Y3 = 14 уже в `dev`). Блок `GOAL` (13 столбцов) только при секции; признак секции — наличие блока при жителях
  (`WorldLoader.ExpectedPresent` получил `inFile`), **столбцов `PARM` не добавлено** — сейвы без целей отличаются от w14 только номером версии.
  `MigrationV15` — пустой шаг. Валидатор `SaveValidator.ValidateGoals`.
- **Загрузчик** (`ScenarioLoader.Goals.cs`): `goals` (ключи по спеке, `for_hours`/`for_days` взаимоисключающие, `grace_days` → часы, пороги KPI в единицах показателя
  ×10, как у ворот вех; `insolvent` требует `economy.city_budget`, `milestone` — прогрессию и индекс вехи) и `meta` (`ScenarioMeta`: mode/title/summary/difficulty 1..5/order)
  → `LoadedScenario.Meta`. `ScenarioLocator.List(dir)` / `ReadMeta(path)` — каталог по `meta` без загрузки сети, порядок `order`, затем имя.
- **Сценарии:** `game-city.json` — `meta` (scenario, «Город у колена сети», сложность 1, order 10) + `goals` (грейс 2 сут., поражение `insolvent` 10 сут., победы нет);
  `yuryev-polsky.json` — **только ключ `meta`** (empty_map, order 10), числа не трогал (Y5).
- **Доки:** `scenario-format.md` §2.12, `save-format.md` — журнал w15 и реестр столбцов `GOAL`.

## Отклонения от спеки
- `LoseIndex` хранится как `int` (-1 — нет), а не `byte`.
- Признак секции в сейве — сам блок `GOAL`, без столбца `PARM` (чтобы сейвы без целей не менялись).
- `GoalCondInfo.Current` считается живым при вызове, `Met`/`HeldHours` — на последней проверке часа.
- Пороги KPI в JSON — в единицах показателя (как ворота вех), ×10 делает загрузчик.
- `prestige_ge` — до YS2 никогда не выполнено (см. выше).
