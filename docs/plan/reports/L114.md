## Что сделано
- **Сценарий:** секция `city.age`. Поля и значения по умолчанию:
  - `child_pct` 18, `elderly_pct` 16;
  - `elderly_car_pct` 50, `elderly_asc_freq_s` 120;
  - `elderly_slot` 108, `elderly_step_slots` 48;
  - `pension_day` 30.
- **Проверки загрузчика** (`ScenarioLoader.City.cs`, `ParseAge`):
  - секция требует `demand.model = residents`;
  - `C + E ≤ 100·(1 − L)` с допуском на округление `labour_share` до Q16, иначе `ScenarioException`.
- **Ядро:**
  - `CityAgeDesc` в `CityDesc.Age`, перечисление `ResidentAge` (Adult 0, Child 1, Elderly 2).
  - Бросок `AgeGroups.Roll` (`CityResidents.cs`) использует те же два броска `v`/`u`, что и раньше, а отрезки `u` — по таблице §2.3. Работники и их машины совпадают с прогоном без режима (тест).
  - Пожилой получает машину при `v < car·elderly_car_pct/100`, у ребёнка машины нет.
  - `CityBuild.IsValid`: без режима все поля нулевые; в режиме — диапазоны и `C+E+L ≤ 2¹⁶`.
- **Хэш:** раздел `AddAge` (параметры + `Age` живых) — только при `city.age`. Без режима хэш побитово прежний.
- **API:**
  - `ResidentInfo.Age` (на месте резервного `R0`);
  - `CityStats.PopChild` / `PopElderly` (считаются в `GetCityStats` проходом по жителям).
- **Сейв:**
  - `world_version` 18 → 19 (окно w18 закрыто SR5), `MigrationV19` — `MigrationFailed`;
  - столбцы PARM 316–323 и `RESD 51 Age` (u8);
  - приложение A `save-format.md` пересобрано, абзац про v19 добавлен.
- **Валидатор** (`SaveValidator.City.cs`, `AgeOk`):
  - `Age ≤ 2`, без режима `Age = 0`;
  - для ребёнка и пожилого: нет `Labour`/`InSeekQueue`, `Work = −1`;
  - для ребёнка дополнительно нет `HasCar`.
- **Корпус:** файлы w18 заменены на w19 тех же случаев (small, s1k, terrain-demo, s1k-res-sr). Хэши в .json не изменились, сменился только номер версии. Корпус занимает 32,7 МБ при бюджете 40 МиБ.

## Отклонения от спеки
1. **Группа хранится не в битах 6–7 `Flags`, а отдельным столбцом `RESD 51 Age`.** Бит 64 уже занят `CareRefused` (SR3). Это +1 Б на жителя. Запись добавлена в §2.3 спеки и в `save-format.md`.
2. **Правило «не один ребёнок» в `Populate` проверяется на пачку.** Дом заселяется целиком за раз. Если все заселённые в пустой дом оказались детьми, первый из них становится взрослым неработающим, машина — по его же броску `v`. Новых бросков нет. В `Immigrate` правило работает дословно (`Occupants == 0`).
3. **Доля детей ниже параметра.** На `*-res` в среднем ≈ 2 жителя на дом, и много домов на одного жителя, поэтому правило срезает долю детей:

   | Сценарий | Дословное правило | Правило на пачку | Параметр |
   |---|---|---|---|
   | s1k-res | 8,72 % | 11,50 % (N = 3981) | 18 % |
   | s10k-res | 7,86 % | 11,59 % (N = 11040) | 18 % |

   - Пожилые попадают в цель: ≈ 15,1 % при параметре 16 %.
   - Сам бросок без правила даёт 18 % (тест `Roll_*`, 200k бросков).
   - Тест 2 проверяет пожилых по ±1/±2 п. п., детей — коридором 9 % … 18 % + допуск. Калибровка — в RA5.
4. **`PopChild`/`PopElderly` считаются по запросу**, а не счётчиками дневного прохода (§2.7). На тик это не влияет.
5. **Правило валидатора «в плане ребёнка — только `Care`» не включено**: планы детей появятся в RA2.
