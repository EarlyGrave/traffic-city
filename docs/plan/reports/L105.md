# L105 — BL4: капремонт и чтение жизни здания

Спека: `docs/design/building-lifecycle.md` §2.9, §5, §6.2, §7 тесты 1-3, §8 строка BL4. Памятники, `SetMonument`, `MonumentEligible`, буст — отложены решением владельца, не делались.
Ветка `local/bl4` (от `dev` cfbfafc), коммиты локальные. Режим прототипа: сборка + тесты своей области, бенч не запускался. Окно `w17` закрыто этим коммитом.

## Что сделано
- **`RestoreBuilding = 40`** (`Command.MakeRestoreBuilding`): цена `Capacity · restore_per_unit (150) · (2 − Cond/10 000)` из казны, поток `Restoration` (20), без undo-кредита. `Cond = Ceil = 100 %`, `Signif`, возраст, статус сохраняются. Валидатор `CheckRestoreBuilding` (общий для превью и применения, цена в `PreviewResult`): `NotSupported` без режима; `InvalidHandle`; `InvalidArgument` при `Cond < 50 %`, `Demolishing`, `Constructing`, нечего чинить (`Cond` и `Ceil` = 100 %); `ZoneRule` для заброшенного на `Lost`-участке или с видом ≠ зоне; `InsufficientFunds` через общий `ToolCosts.Resolve`.
- Заброшенное с `Cond ≥ 50 %` — `Abandoned → Active` через `CityLife.Resettle` (стартовый счёт фирме, места открыты); порог рынка 70 % не нужен — «третий путь». Заявка ЖКХ на починенное здание снимается на выезде как «уже в норме» (`ValidTarget`: `Cond < Ceil`).
- **Параметр** `restore_per_unit` (`CityLifecycleDesc.RestorePerUnit`, PARM 299, загрузчик, валидация), счётчик `Restorations` (CNTR 184, в хэше только с режимом, валидатор).
- **API чтения:** `Simulation.TryGetBuildingLife` → `BuildingLifeInfo` (Cond/Ceil, возраст, Signif и уровень, флаги, `RepairState` None/Queued/CrewEnRoute/Working, стадия вреда H1-H3, `CanRestore`/`RestorePrice`, `RepairPrice`, `DemolishPrice`); `Simulation.GetUtilityInfo` → `UtilityInfo` (фонд, тариф/субсидия действующие и ожидающие, предел тарифа, очередь, депо, бригады всего/в выезде, `RepairsDone`, ремонтов в сутки ×100 в среднем с начала игры, средняя задержка, `FundEmpty`).
- **Окно w17 закрыто:** корпус `w17-*` пересобран (`.tcsave`; `.json` с хэшами не менялись), приложение A `save-format.md` пересобрано (PARM 299, CNTR 184). Спека §2.9 обновлена.

## Отклонения от спеки/брифа
1. `Feature.Restoration` не добавлен: новый бит меняет `Features` в хэше прогрессии и список имён загрузчика — это ломает инвариант «без режима хэши прежние» для сценариев с прогрессией. Команда доступна сразу (как снос и депо). Если гейт нужен — отдельная задача с пересборкой эталонов прогрессии.
2. Отказ «нечего чинить» (`Cond` и `Ceil` оба 100 %) добавлен сверх спеки, чтобы не брать деньги за ничего.
3. «Ремонтов в сутки» в `UtilityInfo` — среднее с начала игры (`RepairsDone·100/Day`), отдельного суточного счётчика нет (не добавлял состояние в сейв).
4. `GetUtilityInfo` перебирает здания для счёта депо (O(зданий)), вызывать раз в кадр панели, не на тик.
