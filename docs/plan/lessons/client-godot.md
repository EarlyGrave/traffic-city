## Godot-клиент
- **`dotnet build game/TrafficCity.csproj -warnaserror` работает без Godot-бинаря** (Godot.NET.Sdk 4.7.2 в nuget-кэше). Правила анализатора в game те же: CA1001 на классах с Godot-ресурсами в полях (подавлено pragma), IDE1006 требует `_camelCase` для private static readonly. Проверка стиля: `dotnet format game/TrafficCity.csproj --verify-no-changes` (game не в sln).
- **Семантический конфликт без текстового**: одна ветка перенесла тип в другой namespace, другая добавила файл со старым using → git сливает чисто, падает сборка в pre-commit. → После мержа параллельных веток всегда build до коммита.
- **dotnet-trace/dotnet-counters не стартуют дочерний процесс**: в окружении `DOTNET_ROOT=/root/.dotnet`, а рантайм в
  `/usr/lib/dotnet`. → `DOTNET_ROOT=/usr/lib/dotnet /tmp/dtools/dotnet-trace ...`; профиль `cpu-sampling` в v10 нет —
  `dotnet-sampled-thread-time`, speedscope в evented-формате.
- **`validate` пропускает ёмкости, которые ядро отклоняет** (s1m `max_lane_points` 20M > 2^24) → проверять пределы ядра в загрузчике.
- **compare ложно падает, если baseline и smoke сняты в разных режимах** (baseline: warmup 2400 + repeat 3, после рампы;
  хук/CI: warmup 200, в рампе) → все места, где гоняется bench для compare (stop-verify.sh, ci.yml, update-baseline),
  используют одни и те же параметры: `--ticks 2000 --warmup-ticks 2400 --repeat 3`.
- **Доля ожиданий ≥ 60 с на s10k шумит между seed (25–102 эпизода на 12 000 тиков) и растёт с длиной окна** (601 эпизод на 30 000 тиков у базы)
  → сравнивать изменение поведения MOBIL/маршрутов минимум на 3 seed и на окне ≥ 30 000 тиков, а не одним прогоном 12 000 (см. routing.md 6.4.1).
- **Хук блокирует `sed`/`dotnet` с переменной и `hash` в строке команды в worktree-агенте** → выносить прогон в скрипт в scratchpad и запускать `bash script.sh`.
- **Rust (R1)**: первый `cargo` в `rust/` скачивает закреплённый тулчейн 1.97.0 из `rust-toolchain.toml` (нужен доступ к static.rust-lang.org, ~1 мин); `Cargo.lock` без сети создаётся `cargo generate-lockfile --offline` (пока нет зависимостей), дальше везде `--locked`. Вектора Util из C# генерировались временным консольным проектом в scratchpad с `<AssemblyName>Sim.Bench</AssemblyName>` (доступ к internal `XxHash64`); результат - `rust/crates/tc-core/tests/vectors/mod.rs`, руками не править. Bash агента-worktree отказывает на составных командах (`&&` + heredoc/`$?`/python) - писать файлы Write/Edit.
- **Скриншот s1k «без машин» (агент 93): не баг симуляции.** Карта 3x3 км, камера по умолчанию на ~3.3 км: машина 4.5 м = меньше пикселя, плюс `--write-movie` даёт всего ~4 с симуляции при `spawn_ramp_s = 120`. Лечение в клиенте: ТС/пешеходы масштабируются по расстоянию камеры, аргументы запуска `--warmup-ticks N` (прогнать симуляцию до первого кадра), `--cam x z dist [pitch [yaw]]`, `--hud`, `--select-ped`, `--ped-mode`; в `scripts/godot-shot.sh` они идут через `GAME_ARGS="..."`, имя PNG - `OUT_NAME`. `PerfHud._Ready` сбрасывает `Visible` после `SimHost._Ready` (порядок узлов), поэтому `--hud` включается в первом `_Process`.
- **`SafePath.IsInsideRoot` на несуществующем файле возвращает `false`** (`FileInfo.Attributes` у отсутствующего файла = -1, все флаги, в т.ч. `ReparsePoint`) → сначала проверять наличие файла (по `LoadedPackage.Files`), потом `IsInsideRoot`, иначе вместо «нет файла» получается ложный `PathEscape`.
- **Замеры рендера V1 (агент 110).** `Viewport.GetRenderInfo` отдаёт кадр, дорисованный к `RenderingServer.FramePostDraw` (на `_Process` - предыдущий), поэтому `RenderStats` снимает в обработчике `FramePostDraw`. В Compatibility (opengl3, llvmpipe) заполнены draw calls / примитивы / объекты, `Performance.RenderTotal*` равны основному проходу при выключенных тенях, память `Render*MemUsed` тоже; фолбэк §8.1 не понадобился. Под Xvfb `RtsCamera` с `EdgeScrollMargin` может уехать от позы - при `--pose` камера `Locked`. `perf/results/godot/` в .gitignore, кроме `stats-*.json`. `fps` в JSON на кадре 10 - прогрев, не показатель.
- **HUD `alloc/tick` ≈ 12–14 КБ на крупном плане (P5) - не аллокация на смену прямоугольника вида (агент 115).** HUD показывает среднее с начала (`_allocBytes/_allocTicks`), а первый `Step` после перехода с вида «всё» на `SetRenderView` лениво выделяет массивы `RenderViewState` (сетка полос в `EnsureIndex`, `_written[b] = new int[Vehicles.Capacity]` на каждый из двух буферов снапшота): s1k - 281 312 Б на 1-м тике и 5 144 Б на 2-м, дальше 0 Б (проверено 300 тиков при смене прямоугольника каждый кадр). 286 456 Б / 21 тик = 13 640.8 Б на HUD. `GC.GetAllocatedBytesForCurrentThread` не видит аллокаций воркеров ядра. Отладка: аргумент клиента `--log-step-alloc` печатает тики с аллокациями `Step` и кадры с аллокациями вида/слоя ТС.
- **`MultiMesh.Buffer` в Godot 4.7 требует размер = `InstanceCount x stride`**, поэтому «буфер по числу экземпляров» = ёмкость, привязанная к числу инстансов с гистерезисом (`BoxBatch`), а не точный `count x stride` на кадр. Пустой батч (`VisibleInstanceCount = 0`) draw call не даёт, но `objects` в `GetRenderInfo` его считает.
- **V4: `visibility_range` движка считается до центра AABB узла, а не до ближайшей точки** (агент 117). Чанк 250 м даёт до 177 м ошибки: у края чанка под камерой уже включался LOD1; пороги ближних уровней нужно сдвигать на полудиагональ ячейки, а дальний слой, лежащий под ближним, не должен начинаться с 0 (заполнит зазоры между полосами LOD0) - только с дистанции, где ближний уровень уже грубый. Дальний чанк 2 000 м и ближний LOD1 перекрываем на ≈1 240 м, иначе дыры.
- **V4: `AddSurfaceFromArrays` с `CUSTOM0`** - формат задаётся флагом: `(ArrayFormat)((ulong)FormatCustom0 | ((ulong)ArrayCustomFormat.RFloat << (int)FormatCustom0Shift))` последним аргументом, данные - `float[]` длиной `вершин x компонент`. В шейдере `varying flat` + `#include "res://Shaders/x.gdshaderinc"` работают в Compatibility (opengl3, llvmpipe); `texelFetch` по индексу из `CUSTOM0.x` - `int(idx + 0.5)`.

## VS1: палитра и инфо-режим, Windows-локал (агент L6, 2026-10-27)
- **Глобальные uniform шейдеров работают в Compatibility (opengl3) и Forward+**: `[shader_globals]` в `project.godot` + `global uniform` в `Shaders/world.gdshaderinc` + `RenderingServer.GlobalShaderParameterSet`. Проверено скриншотами `--info traffic|peds|zones` на `gl_compatibility`: беж + heatmap поверх, draw calls/примитивы не изменились (22/3840 на `mid`). `global uniform int` читается как `int`. Значения по умолчанию в `project.godot` нужно держать равными тем, что пишет `InfoMode.Init()`.
- **Скриншоты на Windows без `godot-shot.sh`:** `Start-Process Godot.exe --path <game> --rendering-method gl_compatibility --resolution 1280x720 --position -3000,-3000 --write-movie x.png --fixed-fps 20 --quit-after 40 -- --scenario s1k --warmup-ticks 2400 --pose mid --render-stats stats.json --stats-frame 30 -WindowStyle Hidden -Wait`. `--write-movie` пишет последовательность `x00000000.png...` (+ `.wav`): берём последний кадр, остальное удаляем. Окно вне экрана (`--position -3000,-3000`) рисует нормально; **`-WindowStyle Minimized` даёт чёрный PNG** (свёрнутое окно не рендерится), render-stats при этом заполнены. Импорт и сборка - только `--headless`. Скрипт-обёртка: см. шаги выше, ~7 с на кадр.
- **Освещение:** `SunEnergy 0.7 / AmbientEnergy 0.45` давали ~1.2-1.4 от альбедо на горизонтальной поверхности (измерено по пикселям), светлая палитра (земля `#EEEAE2`, улицы `#FFFFFF`) уходила в белое. Подобрано 0.30 / 0.18 (даёт ~A). Цвета вершин и инстансов в `Palette.cs` - в линейном пространстве (`Lin`), цвета материалов/uniform с `source_color`/окружения - sRGB (`Srgb`).
- **Кириллица в JSON render-stats на Windows** пишется в cp1251 (поле `note`), числа не страдают; читать с `encoding='utf-8', errors='replace'`.
- **Python на Windows пишет файлы с CRLF** (`open(..., 'w')`), `dotnet format` ругается ENDOFLINE: писать с `newline=''` или после правки `sed -i 's/\r$//'`. `.uid` рядом со скриптами не коммитим (локально в `.git/info/exclude`).

## VS3a: сплошной асфальт и линии полос (агент L11, 2026-10-27)
- **Номера полос встречного направления идут от его правой кромки, то есть от внешнего края проезжей части:** в системе A→B позиция полосы BA `j` = `(n - 1 - j) * w`, а не `n1 + j`. Крайняя полоса сегмента при встречном направлении - его `lane 0`; ширина полосы = смещение крайней полосы / (n - 1) измеряется по данным (в сети s1k = 3.5 м), знак стороны - из той же проекции на нормаль `(-dz, dx)`.
- **Площадка перекрёстка стыкуется с лентами без зазора, только если торцы берутся из тех же вершин ленты** (клиентская упрощённая полилиния LOD1/ленты даёт другую нормаль на конце): торцы запоминаются по уровням. Порядок рукавов - по углу торцов с направлением обхода по стороне `RIn` (не по `NodeArms`).
- **Линии без прозрачного прохода:** «полупрозрачность» - смесь цвета асфальта с `Palette.LaneLine` долей alpha в шейдере (разделители полос: целые значения `UV.y` в полосах + `fwidth`; направляющие connector'ов: лента нулевой ширины, кромки раздвигает вершинный шейдер по `PROJECTION_MATRIX[1][1]`). `CUSTOM0` дорог теперь RGBA (x сегмент, y код ленты, zw смещение кромки направляющей), `UV` - только на LOD0.
- **Примитивы:** площадка с кривыми углами на LOD1 (2 точки) и дальней ленте (срез без точек) - иначе мид-поза росла в 2.6 раза.
- **Скорость облачной VM плавает день ото дня в ~1.5 раза** (2026-10-27: один и тот же коммит `e1a396f` дал s1k p95 0.383 мс против 0.23–0.25 у агентов 147/150 двумя днями раньше, при load < 1). Сравнивать с baseline другого дня нельзя: «регрессия» +44% почти целиком оказалась средой. Регрессию искать только бисектом в одной серии, точки вперемешку (A1 B1 C1 A2 B2 C2 …), ≥ 3 прогона на точку; решает разделение множеств прогонов, а не медианы. Счётчики `work_per_tick` детерминированы — отличают «больше работы» от «дороже операция».
- **Снапшот рендера — около трети тика s1k** (`--phases`: snapshot 0.078 из 0.238 мс). Любая правка `SnapshotJob.Slot` (по машине каждый тик) — горячий путь: L3b (двухосная модель) добавила второй `EvaluatePos`, `Atan2` и 7 массивов состояния на машину → s1k p95 +16% при тех же счётчиках работы.
- **Субагент не может записать файл отчёта (2026-10-27):** харнесс отклоняет Write субагента для файлов вида `REPORT-*.md` («Subagents should return findings as text»). Отчёты (`docs/REPORT-*.md`) пишет оркестратор сам; субагенту — только сбор данных с ответом текстом.
- **`size_m` 3040 / `block_m` 152 тянет за собой другие круглые параметры сценариев (RP9, 2026-10-27):** `demand.zone_m` 500 дал бы `ceil(3040/500) = 7` зон на сторону вместо 6 (и `max_zones` 64 -> `InvalidDemand`), `lod.cell_m`/`routing.cell_m` 1000 - сетку 4x4 вместо 3x3 (в юнит-тесте Step3Gate - один stuck-эпизод). Взяты `zone_m` 508 и `cell_m` 1016: `ceil` даёт прежнее число на всех ступенях лестницы (проверка: `GridSnapTests`). Фикстуры тестов с зашитым `CellSize/CellM = 1000f` для s1k правятся так же.

## RP6: сечения дорог в клиенте (агент L22, 2026-10-27)
- **Каталог профилей клиенту ядро не отдаёт** (нет `NetworkView.RoadProfiles`, §3.1 road-profiles.md не реализован): есть только `SegmentData.Profile` и бит `Mirrored`; `SimHost` берёт каталог из `ScenarioDesc.RoadProfiles` (`RoadProfileLayouts.Set`). `Mirrored` разворачивается в клиенте один раз на сечение (порядок элементов, `forward` ↔ `backward`).
- **Сценарий с `road_profiles_file` ломал `BasePackageGoldenTests.UpgradedV2_GivesSameScenarioDesc`** (читатель файлов v3-копии бросал на любой файл): теперь он отдаёт `road-profiles.json` из `scenarios/`. Новые сценарии с внешними файлами — учитывать при добавлении в `scenarios/`.
- **Скриншот `gl_compatibility` выводит вершинные цвета темнее ожидаемого** (асфальт `#8A8884` выходит ~`#2D2B26`, газон тоже темнее и зеленее): цвета в `Palette.cs` — линейные, а compat не кодирует их в sRGB на выходе; `forward_plus` в окне за экраном (`--rendering-method forward_plus`) рисует ближе к задуманному. Сравнивать «до/после» только в одном методе.
- **Перспектива на скриншотах:** линии вдоль Z сходятся к центру кадра (стоп-линия у артерии выглядит косой при `yaw 0`, это не дефект торца).
- **(починено L34, margin = 0) `--pose mid` на мелких картах (демо 480 м) — 300 м от центра:** чанки севернее центра попадают в мёртвую зону `Road0` (конец 427 м) / `Road1` (начало 427 м) и пропадают до асфальта — как до RP6 (воспроизводится на legacy-раскраске демо); для скриншотов демо — `--cam x z dist pitch yaw`.

## VS9: слой земли в клиенте (агент L26, 2026-10-28)
- **Причина «тёмных» вершинных цветов в `gl_compatibility` (RP6) - не вершины, а рабочее пространство:** Compatibility считает освещение в sRGB, ALBEDO не линеаризуется. Константа `ALBEDO = vec3(0.571, 0.686, 0.381)` (линейный `#C7D8A6`) дала в compat те же `#708B48`, что и вершинный цвет, а `source_color`-uniform земли выходил верным. Правка: `Palette.Lin`/`Palette.ToWorld` в compat возвращают исходный sRGB (`RenderingServer.GetCurrentRenderingMethod()`), Forward+ без изменений. Измерено в compat: асфальт `#8A8884` -> `#797876` (было ~`#2D2B26`), парк `#C7D8A6` -> `#9EAF87` (было `#708B4A`), вода `#A9CDE8` -> `#84A5C1` (было `#4879A9`).
- **Compat не держит сантиметровые зазоры по глубине на километрах:** слои земли (-0.15/-0.13/-0.12/-0.11) и дальняя лента дорог (-0.10) на overview дают полосы z-fighting (и у дорог до VS9). Рабочий метод проекта - Forward+, там чисто; в compat слои пришлось бы разносить на метры.
- **`s10k` - 6 080 м, а не 3 040 (`scale 2`):** дальних чанков 2 000 м - 16 (4x4), слой земли `s10k-landuse` - 15 мешей = 15 DC.
- **Скриншоты и `--render-stats` на Windows:** путь `--render-stats` относительный считается от папки проекта (`game/`), нужен абсолютный. s10k с `--warmup-ticks 600` снимается за ~5 с.
- **Участки (`LotCount`) есть только при `demand.model = residents`:** в OD-сценариях тон кварталов не рисуется, только парки/вода. Подложка участка 36 м (участок 40 м) - при крупных `*-res` (100k+) число треугольников слоя земли вырастет (по 2 на участок).

## VS2: ТС в стиле B (агент L28, 2026-10-28)
- **Низ меша ТС теперь на y = 0** (раньше центр на y = h/2): AO-градиент шейдера считает от `VERTEX.y`; инстанс LOD0/LOD1 ставится на `c.Y + 0.05`, LOD2-плоскость и точки - как раньше. `PointBatch` и `BoxBatch` не менялись (ктор с материалом уже был).
- **`BoxBuilder` - грань по часовой стрелке (лицевая в Godot), `u x v = нормаль`;** встроенный `BoxMesh` для рёбер не годится (UV-атлас). Рёбра - `min(u, 1-u) / fwidth(u)` без UV2: отношение то же, что в метрах.
- **Рёбра в `gl_compatibility` и Forward+ без отличий в draw calls/примитивах** (замер s1k: 22/3428 close, 20/1440 lod0, 34/3552 mid в F+; 13/3566, 11/1578, 21/3818 в compat - до и после идентичны).

## VS10: день/ночь светом (агент L30, 2026-10-28)
- **Свет суток меняет только значения существующих объектов** (`Environment`, `ProceduralSkyMaterial`, `DirectionalLight3D`, глобальный `light_tint`) - объекты и меши не пересоздаются, main-проход идентичен (s1k-res: Forward+ 70/10712 `mid`, 32/6104 `close`; compat 60/10922 и 21/6316 - во все часы). Ночью тени выключены (энергия < `MinShadowEnergy`): теневой проход 8 -> 0 DC на Forward+.
- **Unshaded-слои (зебры, точки) ночью умножаются на `light_tint`** (~ту же яркость, что ambient даёт земле), иначе светятся; `vehicle`/`ground`/здания - обычный свет, tint им не нужен.
- **PowerShell 5.1 `Get-Content -Raw` без `-Encoding utf8` читает UTF-8 без BOM как cp1251** - правка `.cs` через `Get-Content | -replace | Set-Content` превращает кириллицу в кракозябры и добавляет BOM. Править через Edit/sed/python.

## VS5: здания в стиле B + минимум V8 (агент L29, 2026-10-28)
- **В клиенте зданий не было вообще** (V8 не делался: нет `BuildingLayer`/`ChunkBuilder`), хотя ядро отдаёт `GetBuildings`/`BuildingsVersion` и в `*-res` застройка есть с первого тика (`initial_fill`). Сделан минимум V8: процедурные боксы по зоне и плотности, три представления одним шейдером. Плотность в `BuildingRenderData` не передаётся (`R0` свободен) - клиент берёт `Type & 1` (у пакета base типы парами низкая/высокая); модам нужен `visual`.
- **`visibility_range` мерит расстояние до центра узла:** чанку 2 000 м пришлось бы быть видимым почти всегда (полудиагональ 1 414 м), поэтому импосторы - ячейки 1 000 м, LOD2 - 250 м, границы расширены на полудиагональ ячейки (иначе дыры). Полосы перекрытия рисуют одинаковые боксы дважды (цвет тот же, z-fighting не виден), плата - примитивы.
- **`MeshBuilder` без нормалей не годится для зданий:** добавлен `useNormal` (`AddLit`); дороги и земля не затронуты (нормаль по умолчанию вверх).
- **`BoxBatch` для кольца зданий:** единичный бокс (низ на y = 0) и масштаб по осям (вдоль курса, вверх, поперёк); AO шейдера считает от мирового `y` (`MODEL_MATRIX`), поэтому работает и у инстансов, и у чанков.
- **Пересборка слоя - целиком** (при `BuildingsVersion`, не чаще раза в 1.5 с): на s10k-res (5 441 здание) незаметно, на s100k+ нужна очередь по чанкам (остаток V8). Версия растёт на каждое здание, поэтому рост застройки пересобирает слой каждые 1.5 с.

## VS6: x-ray ближних высоток (агент L31, 2026-10-28)
- **Тень и `discard` в одном шейдере несовместимы:** Godot гоняет фрагментный шейдер в теневом проходе, если в нём есть `discard`/`ALPHA`, и вырезанное здание перестало бы отбрасывать тень. Метрика - расстояние от камеры до ВЕРХУШКИ здания (до основания на pose `close` 60 м камера на высоте ~49 м, и ничего не гасилось): предел = min(1.5 x `cam_focus_dist`, 200 м), полностью исчезает ближе 0.75 предела, дальше плавный дизеринг. ## UI4: инструмент «Дороги» (агент L55, 2026-10-28)
- **`AcquireExclusive` два раза подряд в одном кадре вешал поток симуляции** (пересборка участков, затем зданий: срабатывает, когда команда меняет `LotsVersion` и `BuildingsVersion`, например `UpgradeRoad` с потерей участков): `_resume.Reset()` нового доступа съедал `Set` предыдущего, пока поток симуляции ещё не проснулся. - **Впрыск мыши в скриптовых прогонах:** `Viewport.GetMousePosition()` берёт настоящий курсор ОС, `Input.ParseInputEvent` его не двигает - перед событием звать `GetViewport().WarpMouse(p)` (координаты вьюпорта), а в самом событии `Position` - в координатах окна: `p * window.Size.X / viewport.GetVisibleRect().Size.X`. При `canvas_items` базовый размер из project.godot (1152x648) растягивается на окно, поэтому вьюпорт 1152x648 при окне 1366x768.
- **Ядро проверяет `Overlap` только у команд с профилем** (`BuildRoadCmd.Profile > 0`, `CheckFootprint`): прежняя команда без профиля (как в `--tool-demo` T13) пересечение середины сегмента принимает. Инструмент «Дороги» всегда шлёт профиль (в сценарии без каталога - legacy-команда без проверки).
- **`R`/`X` и режим «Снос»:** один экземпляр `RoadsTool`, `Id` = `bulldoze` в режиме Remove; повторное нажатие той же клавиши выключает инструмент, другой клавиши - меняет режим. Не жать `X` лишний раз в скриптах.
