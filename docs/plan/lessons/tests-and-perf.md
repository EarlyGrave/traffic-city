## Тесты 0 B и JIT
- **Редкий флейк `Step_Allocates_ZeroBytes_InSteadyState` (~1-2% прогонов `dotnet test traffic-city.sln`, только при параллельной
  загрузке CPU/классов): 3-8 КБ в окне «0 B», по фазам - в произвольной (IntegratePhase, SyncStructuralCounters).** Исходный код
  ядра не аллоцирует: это синхронная OSR/tier-up-компиляция метода с циклом в потоке теста (tier-0 патчпойнты; счётчики общие для
  всех потоков, поэтому момент зависит от соседних тестов), JIT/загрузчик типов кладут объекты в управляемую кучу.
  Прогрев не помогает - момент недетерминирован. → В `Sim.Core.Tests.csproj` `<ConcurrentGarbageCollection>false</ConcurrentGarbageCollection>` + `Fixtures/AllocationProbe` (повтор окна, если за замер сработал GC)
  Для новых проектов с `GetAllocatedBytesForCurrentThread` - то же.
  Диагностика: временно разнести тик на фазы и мерить аллокации по каждой, гонять набор в 3 параллельных циклах.
- **Тесты 0 B с воркерами падали на 168 Б под нагрузкой (`RenderViewTests.View_...(threads: 2)`: 9 из 20 прогонов при 6 busy-loop + load 20-30), проходили при повторе.**
  Корень не в ядре: `GC.GetTotalAllocatedBytes` считает все потоки процесса, а фоновый поток рантайма (tiered-JIT/таймер) аллоцирует
  ~170 Б раз в ~100 мс; при медленной машине окно `Step(100)` длиннее, и это попадает в каждое из 50 окон «минимума» (поток теста и воркеры - по 0 Б,
  проверено счётчиками по фазам). → `AllocationProbe.MeasureSimThreads(sim, window)`: счётчик `GetAllocatedBytesForCurrentThread` потока теста + каждого
  воркера `WorkerPool` (читается заданием пула в `RunRange`, до и после окна), с тем же повтором при GC. Не возвращайся к `GetTotalAllocatedBytes`.
  `Step3GateRun` замерял 1000 тиков без прогрева и без повтора при GC - переведён на `AllocationProbe.Measure`.

## Валидатор и превью (T7)
- **Границы по умолчанию (`OutOfBounds`, bbox сети + 2 км) ломают тесты «вдали от города»:** дороги на (5000..9000) отклоняются. Такие тесты ставят `sim.SetToolsConfig(ToolsFixture.Unbounded)`; конфигурация инструментов - хост-параметр, вне сейва (после `Load` задавать заново).
- **Явные зоны `Demand.Zones` не получают полос появления (`SpawnLaneCount = 0`, TODO генератора):** связность по зонам в таких мирах пуста; тест `Connectivity_Preview` назначает `ZoneLanes` вручную. Для реальных проверок брать город с генератором.
- **Превью против применения расходятся в одном тике:** фаза 1а (финалы дренажа) идёт до команд того же `Step`, поэтому сегмент/рукав, исчезнувший в 1а, даёт другой отказ - сравнивать вердикты только при `Ops.Count == 0`. Врезка в построенный узел (`BuildRoad`, Mechanism 1) валидатором не планируется (нужен сегмент в сети): `Busy/CreatesTrap` узнаются только при применении.
- **`SetTurnBan` в валидаторе временно правит `nd.TurnBan` на время `PlanRebuild`** (читает запреты из узла) и возвращает значение до выхода - хэш и сейв не меняются; не вызывать из параллельных фаз.
