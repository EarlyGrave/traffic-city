Файлы-нарушители не создавались (блок до записи); дерево чистое.

### Находки
- У субагента post-build молчал: worktree агентов создаются от `main` (там ещё нет csproj).
  Исправлено процессом — каждый бриф начинается с fast-forward worktree на рабочую ветку.
  Ручной вызов хука в worktree с проектами даёт exit 2 с ошибкой компилятора.
- guard-bash эвристический: срабатывает и на текст команды внутри heredoc/кавычек
  (например, если в Bash-команде записывается markdown с примером force push). Это ложный блок,
  а не пропуск — безопасная сторона. Обход: такие тексты писать инструментом Write.

## Шаг 4. Автобусы (ADR-0008)
Выпуск по интервалу с первой остановки, рейс «остановка → остановка» через маршрутизацию, стоянка =
база + время на пассажира (вышли + сели, ≤ 45 с), пассажиры — детерминированный счётчик, конечная — деспаун.
Карман пока = обочина (блокирует правую полосу, объезд MOBIL). s1k 30 мин с 10 маршрутами: автобусов выпущено 61,
прибытий на остановки 466, посажено 4887, **bus_headway_deviation_s = 35.6 с** при интервале 300 с; stuck 0,
gridlock 0, tick p95 711 мкс.

### Топ-3 узких места (профиль выше)
1. **Маршрутизация на больших картах**: A* — 57% CPU на s100k (поиск магистралей, куча). Плоский A* не масштабируется.
2. **Интеграция + поведение (фазы 5–6)**: 22% + 19% на s1k — основной «честный» расход на машину.
3. **Снапшот**: 16% на s1k, из них 10% — копирование полного буфера `VehicleRenderData` каждый тик.

### Что проверить руками (Godot 4.7.2 .NET, Windows)
1. Открыть `game/project.godot`: импорт и сборка C# без ошибок, `Main.tscn` открывается.
2. F5: сеть s1k видна, машины едут, в консоли нет `ERROR`; камера показывает всю сеть.
3. Машины: коробки ориентированы по движению, стоят на дороге; автобусы длиннее и оранжевые.
4. Плавность: нет рывков 20 Гц, FPS ≥ 60 (F3); проверить ×2/×4 (`+`) и паузу (Space).
5. Камера: WASD, края экрана, ПКМ-drag, колесо, Q/E и СКМ.
6. F1 — тепловая карта загрузки (зелёный → красный, ~2 раза/с), повторное F1 — выкл.
7. F2 — маркеры фаз светофоров на стоп-линиях, цвета меняются по циклу 24/3/1.
8. ЛКМ по машине — белая подсветка и жёлтая лента маршрута; Esc/клик мимо — снять выбор.
9. F3 — FPS, frame, tick p50/p95, агенты ~1000, alloc/tick ≈ 0, GC не растёт.
10. Запуск `-- --scenario s10k`: FPS и tick ms на десктопе.
11. Если машины перекошены/невидимы — смотреть `game/Scripts/BoxBatch.cs` (раскладка буфера MultiMesh).
Плюс: поставить `.NET SDK 10` и `.NET 8 Runtime` (STACK.md); облачный setup script:
`apt update && apt install -y dotnet-sdk-10.0 dotnet-sdk-8.0`.

### Предложения на этап 2 (по приоритету)
1. **Иерархическая маршрутизация** (матрица хабов / contraction hierarchies, routing.md §9) — снимает 57% CPU на s100k
   и арену маршрутов на s1m.
2. **s10k до бюджета ≤ 4 мс**: сейчас 4.5 мс p95 при половине машин — профиль после (1).
3. **Удержание автобусов на остановке** против «пачек» (отклонение интервала 35.6 с) и настоящие карманы `BusBay`.
4. **Снапшот без полного копирования** (компактный список живых, двойной буфер по указателю) — −10% тика на s1k.
5. **Стабильность perf-измерений**: изолированный CPU/повторы для compare (±13% шума) и `perf/baseline-ci.json` из лога CI.
6. **Гибрид micro/meso для s1m** — ADR после (1): мезоскопика вдали от камеры.
7. Порядок владельца: s10k → пешеходы и пассажиры как агенты → зонирование и спрос → low-poly арт.
