# Отчёт этапа 2

> Все цифры — из реальных прогонов (облачный контейнер, 4 vCPU Xeon 2.1 ГГц, .NET 10, Release), источники — отчёты
> агентов и верификаторов в `docs/plan/agents.md`, подробности — в спеках. Одиночный p95 в контейнере шумит на ±25–40%.

## Цель и итог
Цель этапа: s10k ≤ 4 мс tick p95 при полной загрузке, 0 B/тик, бюджеты s1k не хуже; задел на масштаб, сейвы,
качество трафика. Решения владельца по ходу: карт-бланш на редизайны; целевое железо — ноутбук среднего класса+
(6–8 ядер), бюджеты с воркерами до 4 потоков; критерий stuck раздельный (deadlock/gridlock = 0, длинные ожидания —
метрика качества); принцип Парето, оптимизации масштаба — на паузе.

## Что сделано (по шагам roadmap)
- **2.1 Честные замеры.** `--warmup-until-full`, ramp-поля, единый `scripts/bench-gate.sh` с 3 попытками
  (ложный FAIL 12% → 0.2%). Шум контейнера не победить настройками рантайма — источник в VM.
- **2.2 Иерархическая маршрутизация (ADR-0009).** Оверлей ячеек (CRP), компактный план + окно, перемаршрутизация
  по дрейфу; кэш магистралей и хабы удалены. Маршрутизация на s100k: 57% → 4.7% тика.
- **2.3 Дешёвый снапшот (ADR-0010).** Копирования не было (двойной буфер) — удешевлена фаза 10; на s1k 15.9% → ~8%.
- **2.4 Горячий путь (ADR-0016, ADR-0017).** P1 замер фаз и счётчики работы; P2–P5 побитово эквивалентные правки
  (s10k p95 7.96 → 4.33–4.74 мс); детерминированные воркеры фаз 5/6/10 (хэш не зависит от числа потоков).
  Попутно: 2 бага порядка билетов (MOBIL, ghost), бюджет плановых запросов, правило голодания левых «4b-bis».
- **2.5 Качество трафика (ADR-0018, поправка ADR-0008).** Адаптивные светофоры со стрелкой по спросу (дефолт);
  координация «зелёная волна» — опция (`alternate`), не дефолт: остановки на артериях −2…3 п.п., но больше stuck;
  бронь выезда — отклонена по диагностике (места на выезде нет); удержание автобусов на остановке
  (отклонение интервала 36.5 → 21.5 с); метрики длинных ожиданий и распределения по полосам в bench.
- **2.6 Уровни детализации (ADR-0013, ADR-0019).** Каркас LOD, кинематический meso, активные множества A1–A4
  (снапшот по виду: s100k фаза 10 4.8 → 0.46 мс), отзыв допуска на красном R1 (stuck: micro 18 → 6, meso 255 → 59),
  прототип Q-meso под флагом — ворота решения не пройдены (0.150 мкс/машину при цели 0.03).
- **2.6b Сейвы (ADR-0012).** Бинарный SoA-контейнер (XXH64, fuzz), полное состояние мира (продолжение после load
  побитово равно непрерывному, переносимо между числом потоков), канонический порядок сети, миграции (каркас),
  манифест ассетов, конверт `.tcsave`, корпус golden-сейвов в CI.
- **Документы:** реестр рисков по урокам CS2 (`docs/design/cs2-lessons.md`), ADR-0009, 0010, 0012, 0013, 0016–0019.

## Что не сделано / бэклог
1. **Масштаб s100k/s1m ≤ 15 мс** (с воркерами): Q0b (инкрементальные OutReserved/NodeBusy, connector'ы событиями,
   кэш TryGrant), параллельная фаза 4 по цветам ячеек, L3–L5 (контроллер LOD, клиент, сценарии s1m/stress-1m).
2. **Промахи полосы:** `lane_miss_share` s10k ≈ 0.45 — почти половина поездок перемаршрутизируется из-за полосы.
3. Координация `alternate` как дефолт — после работы с промахами полосы/спилловером.
4. «Новые параметры ассета только для новых спавнов» — нужны версии параметров типов в мире.
5. Карманы `BusBay`, «точки» вдали в снапшоте (ADR-0014 бюджет рендера), ручная проверка Godot-клиента владельцем.

## Что проверить руками (Godot)
Чек-лист этапа 1 (`docs/REPORT-stage1.md`) + новое: F2 — стрелки левого поворота на адаптивных светофорах;
автобусы стоят на остановке дольше при догоне; клиент работает с видом «всё» (снапшот по виду — ядро готово).
