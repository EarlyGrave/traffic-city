# Парковка как ресурс (спецификация, этап 4.4, ADR-0026)

Статус: предложено (2026-10-26, агент #128). Источник истины для `src/Sim.Core/Parking/` и правок ног жителей, спавна, прибытия,
выбора и сейва в части парковки. Связано: `zoning-demand.md` §2–4, §6.5, §7, §12, §15, §20.1–20.3; `pedestrians.md` §4, §8;
`routing.md` §3, §9.6–9.7; `intersections.md` (`LaneNo 0` — правая); `player-tools.md` §1–2, §6–8, §11; `save-format.md` §3, §4, §12;
`scenario-format.md` §2.6; `cs2-lessons.md` T5. ADR-0006, 0009, 0011, 0012, 0017, 0019, 0020, 0021, 0022, 0023.

## 0. Идея в трёх абзацах

1. **Место — счётчик у объекта, машина — поле жителя.** Объект стоянки (обочина участка, стоянка здания, гараж игрока) хранит
   ёмкость и три счётчика: закреплённые домашние места, гости, резервы в пути. Где стоит машина жителя, записано у жителя (`CarFac`).
   Стоящих машин нет ни в `VehicleStore`, ни в горячем цикле.
2. **Резерв до выезда.** Заявка машинной ноги (фаза 2r) сначала резервирует место у цели. Маршрут строится к точке въезда этого места.
   Мест нет — машина не выезжает, житель ждёт дома по автомату `WaitDepart` и в конце концов меняет способ. На дорогу не попадает
   машина, которой некуда встать, поэтому кружения нет по построению (T5).
3. **От места до двери — пешком.** После постановки житель идёт к двери (таймер или пешеход-агент), обратная нога начинается с пути
   к машине. Время ожидания мест, поиска и ходьбы входит в наблюдение ноги, поэтому скимы и выбор способа (ADR-0021) видят дефицит.

## 1. Границы и инварианты

Режим: `parking.model = "resource"` (только при `demand.model = "residents"`, иначе `InvalidScenario`). Без режима `World.Parking == null`,
и ни одна новая ветка не исполняется.

| # | Инвариант | Проверка (§17) |
|---|---|---|
| PK1 | Без режима: состояние, хэш, сейв (кроме столбцов-дефолтов новой `world_version`) и поведение побитово прежние | golden s1k/s10k/s1k-peds/s1k-res, `HotPathGoldenHashTests`, корпус |
| PK2 | Сохранение мест: для каждого живого объекта `Assigned`, `Occupied`, `Reserved` равны пересчёту по жителям, машинам и поездкам | `ValidateParking` (debug раз в 100 тиков, тест, после `Load`) |
| PK3 | Ёмкость: `Assigned + Occupied + Reserved ≤ Capacity`, пока объект не `Closing` и ёмкость не уменьшали; новый резерв или закрепление только при `Free > 0` | тест-фаззер |
| PK4 | Сохранение машин: у жителя с `HasCar` машина ровно в одном месте — на объекте (`CarFac ≥ 0`), в пути (`Agent` = машина) или в заявке (`PendingTrips`) | `ValidateParking` |
| PK5 | Нет кружения: у машины жителя на дороге есть живой резерв (`ParkFac`) либо она в поиске не дольше `search_max_s`; машина не исчезает иначе как стоянкой | тест-зонд по тикам |
| PK6 | Дом всегда достижим: у жителя с `HasCar` есть домашнее место (`HomeFac`) либо машина стоит на `Overflow` у дома и ждёт переназначения | `ValidateParking` |
| PK7 | Хэш не зависит от числа потоков (1/2/3) и от `RenderView` | тест |
| PK8 | 0 B/тик в стационаре (micro и aggregate) | `Step_Allocates_ZeroBytes` с `s1k-res-park` |
| PK9 | Решения целые: стоимость выбора места, плата, ходьба — `int`/`long` (мм, тики, деньги); `float` только в `AccessS` (как `S` машин) | ревью |

Вне объёма: поиск вслепую у обочины (доля трафика от ищущих), время стоянки и штрафы, грузовики и доставка, такси, park & ride
(пересадка машина → автобус), электрозарядки, общие обочины для жителей без разрешения (вопрос владельцу №3).

`Free = Capacity − Assigned − Occupied − Reserved` (может быть < 0 после уменьшения ёмкости — тогда 0 для решений).
`Overflow` — слот 0, создаётся в `Create`, `Capacity = int.MaxValue`, не входит в окрестности; машина на нём привязана к участку
жителя (`CarLot`, §2.2). Размер ≈ 60 Б на объект.

### 2.3 Машина и поездка
- `VehicleStore.ParkFac`, `ParkFacGen` (int, −1 у OD, автобусов и машин без режима) — резерв машины в пути; `ParkSearchTick` (long, −1 —
  не ищет) — начало поиска после потери резерва (§7).
- `PendingTrip.ParkRef` — индекс объекта + 1 (0 — нет; нулевая структура безопасна, как `ResidentRef`) и `ParkGen`.

### 2.4 Окрестности (`Parking/Catchment.cs`, производное)
Для каждого участка — до `max_candidates` (16) объектов, отсортированных по `(WalkMm, индекс)`: обочины и гаражи (`Public`) и стоянка
здания этого участка, у которых `WalkMm ≤ walk_max_m` и общая дорожная компонента с участком (`RoadComp`), при сети пешеходов — и общая
пешеходная. `WalkMm` — манхэттен между точкой пешехода объекта и центром участка, целые мм. Плоские массивы `CatchFirst[lot]`,
`CatchCount[lot]`, `CatchFac[]`, `CatchWalkMm[]`. Поиск соседей — корзинная сетка 100 м (scratch в `Create`). Пересборка — в `Create`
и `Load` целиком, при правке объекта — для участков в радиусе `walk_max_m` от него. Тест: локальная пересборка = полной.

## 3. Объекты: виды, создание, ёмкость

- **Обочина (`Curb`)** — одна на участок, если у стороны сегмента есть полосы (`CarLane ≥ 0`) и режим обочины стороны не `Off`.
  `Capacity = floor(фасад / curb_slot_m)` минус въезд (1 слот, если у здания участка есть своя стоянка) минус запретные зоны (остановка
  `±curb_stop_clear_m`, переход на перегоне). Режим стороны сегмента (`CurbMode`: `Off`, `Free`, `Paid`) по умолчанию задаётся типом
  дороги (`curb.street`, `curb.arterial`). Флаги: `Public`, `Permit` (если `curb.permits`). Создаётся вместе с участком: в `Create`, на
  `BuildRoad` (участки Z6), в загрузчике. Участок `Lost` → объект снесён (§7).
- **Стоянка здания (`Building`)** — ёмкость из типа здания (`BuildingTypeDesc.ParkingCapacity`, `buildings.json` поле `parking`), доступ
  `ParkingAccess`: `Private` (жильцы R; работники и посетители C/I этого здания), `Public` (любые гости). Точка въезда — `CarLane/CarS`
  участка, `WalkMm = 0`. Создаётся при переходе здания в `Active`; `Abandoned` → `Closing`; снос здания → объект снесён (§7).
  Жилой дом с `Private` — только закрепления (`Permit`), гостей нет.
- **Гараж (`Garage`)** — здание типа вида `Parking` (новое `LotZone.Parking = 4`, рост его не трогает) на участке, ставится командой
  `BuildParking` (§9). `Public`, плата `Fee` (по умолчанию `garage_fee`), `Permit` по `garage.permits`.
- Уменьшение ёмкости (смена режима обочины, въезд нового здания) резервы и стоящих не трогает: `Free` уходит в 0, лишние уйдут сами.

## 4. Домашнее место (`Parking/HomeAssign.cs`)

- **Когда.** Начальное население (`CityInit`, после выпадения `HasCar`), въезд и переезд (Z4 `Market`), потеря домашнего места (§7),
  ежедневный проход по жителям `Overflow`-дома (курсор, ≤ `home_retry_per_day`).
- **Правило.** Кандидаты по порядку: стоянка своего здания (`Private` или `Public` с `Permit`), затем объекты окрестности дома с `Permit`
  и `WalkMm ≤ home_walk_max_m`, по `(WalkMm, индекс)`. Первый с `Free > 0` → `HomeFac`, `Assigned++`, машина ставится туда (`CarFac = HomeFac`).
- **Нет места.** При въезде и в начальном населении: `HasCar` снимается, `parking_car_shed++` (вместимость стоянок ограничивает
  автопарк). При потере места у жителя с машиной: машина на `Overflow` у дома (`CarFac = 0`, `CarLot = участок дома`), `HomeFac = −1`,
  повтор в ежедневном проходе.
- **Отъезд из города / переезд:** `Assigned--` у старого места, машина уезжает вместе с жителем (она всегда дома, так как отъезд только
  из `AtHome`, а у жителя в `Overflow` — снимается `CarLot`).

## 5. Резерв и выбор места (`Parking/ParkingOps.cs`)

`TryReserve(w, r, destBuilding, out fac)` — вызывается в `TripLegs.Submit` для машинной ноги до `TryEnqueue` (после проверки `Trips.IsFull`):
1. Обратная нога домой: `fac = HomeFac` (закреплено, `Reserved` не меняется). Если `HomeFac < 0` — `Overflow` у дома (`fac = 0`).
2. Иначе обход окрестности участка цели: допустим объект, если жив, не `Closing`, `Free > 0` и он `Public` либо это стоянка здания цели.
   Стоимость `C = CatchWalkMm · 20 / walk_speed_mm_s · w_walk + Fee · fee_ds_per_money` (децисекунды, целые; `w_walk` — Q8 из `choice`).
   Минимум `C`, ничьи — по индексу. PRNG нет.
3. Успех: `Reserved++`, `PendingTrip.ParkRef/ParkGen`, `DestLane/DestS = AccessLane/AccessS` объекта, `CarWalkMm` = ходьба кандидата, `LegStage = Drive`.
   Отказ: заявка не подаётся, событие повтора через `retry_s` (как `Begin.Backlog`, но с паузой), счётчик
   `parking_no_spot_waits++` (раз на ногу); при успехе `LegParkWait = Tick − LegWaitFrom`. Дедлайн `WaitDepart` (`LegWaitFrom + wait_max_s`) переключает способ (`Alternative`), иначе
   отменяет тур — автомат `zoning-demand.md` §3.3 без изменений; переключение по причине мест — `parking_mode_switch++`.
- Освобождение резерва (`Reserved--`): поездка удалена (`OnTripDropped`: `RouteFailed`, полоса исчезла), отмена заявки (`CancelRequest`),
  прибытие (§6). Все пути проходят через `ParkingOps.Release` — одно место для PK2.
- Резерв делается **при заявке**, а не в фазе 3: поездка без места в голове FIFO `PendingTrips` заблокировала бы весь спавн (ADR-0026).
  Маршрут фаза 3 строит прежним `Query` к `DestLane/DestS` резерва — «при построении маршрута» место уже закреплено.

## 6. Нога с парковкой (`City/TripLegs.cs`, `Parking/AccessWalk.cs`)

| Стадия | Вход | Что происходит | Выход |
|---|---|---|---|
| `WalkToCar` | заявка машинной ноги при `CarWalkMm > 0` | житель `InLeg`, пешком от двери к точке пешехода объекта | конец ходьбы → `WaitDepart`, `LegWaitFrom = Tick`, `Submit` |
| (`WaitDepart`) | заявка | резерв цели (§5), заявка в `PendingTrips` | машина поставлена |
| `Drive` | `Spawner.TryPlace` | `CarFac = −1`; у гостевого объекта `Occupied--` (место освобождается в момент выезда) | прибытие в `AccessLane/AccessS` |
| `WalkFromCar` | фаза 8 / `QueueMeso`: `ParkingOps.Park` | `Reserved--`, `Occupied++` (дом: ничего), `CarFac = ParkFac`, плата (§8); пешком к двери | конец ходьбы → `ArrivalRing` |

- **Ходьба.** Без пешеходов-агентов (дефолт и всегда без `peds.source = city`): таймер колеса жителей, событие `ResidentEvent.AccessWalkDone`,
  длительность `ceil(CarWalkMm · 20 / walk_speed_mm_s)` тиков, накопитель ноги `walk`. С `peds.source = city` и `parking.access_walk = "agents"`:
  `PedWorld.RequestLeg(r, …, mode = Walk)` от точки пешехода объекта к тротуару участка (и обратно), прибытие пешехода → выход стадии
  (задача K4). `CarWalkMm = 0` — стадии нет.
- **Выезд из середины полосы.** Машина ставится в `AccessS` с проверкой зазоров (`TryPlace` уже вставляет между соседями). Правило горизонта
  ворот (урок Z2, `lessons/sim-city.md`): если `Length − s < far` (та же оценка `farDistance`, что в `GatePhase.ScanActive`), позиция сдвигается к
  `Length − far` (не меньше 0). Нет зазора — попытки `s − 8 м`, `s − 16 м`, иначе заявка ждёт следующего тика. Debug-сверка `GatePhase`
  обязана проходить на `s1k-res-park`. Без режима спавн жителей прежний (`FromS = 0`).
- **Прибытие.** Условие фазы 8 прежнее (`Lane == DestLane && S ≥ DestS`). Прибытие машины жителя в режиме — только через `ParkingOps.Park`
  (до `TripLegs.OnVehicleArrived`); кольцо прибытий получает жителя в конце `WalkFromCar`. Наблюдение ноги — от `LegReq` до двери.
- **Валидатор.** `InLeg` со стадией ходьбы и таймером имеет `Agent = −1` (исключение в `ValidateCity`), со стадией `Drive` — живую машину
  с обратной ссылкой и `ParkFac`.

## 7. Потеря резерва, поиск, `Overflow` (`Parking/ParkingSearch.cs`)

- **Снос объекта** (`Lost` участка, снос здания или гаража, `RemoveParking`) → `ParkingOps.Remove(f)` в той фазе, где снос (1 или 9r):
  1. машины в пути с `ParkFac = f` (обход `VehicleStore` до `HighWater`, редкое событие) → `ParkFac = −1`, `ParkSearchTick = Tick`,
     в кольцо `ParkSearchQueue` (`[MaxVehicles]`, флаг `VehicleFlags.ParkSearch` против дублей);
  2. заявки `PendingTrips` с `ParkRef = f` → повторный `TryReserve` на месте; отказ — поездка снимается, житель в `WaitDepart` (§5);
  3. стоящие гости (`CarFac = f`) → «эвакуация» на домашнее место (`CarFac = HomeFac`; `Overflow` у дома, если места нет), `CarWalkMm = −1` («машина не рядом»): обратная нога тура идёт другим способом
     (`Alternative`; без вариантов — агрегатная ходьба, `zoning-demand.md` §4.1), `parking_towed++`;
  4. закрепившие (`HomeFac = f`) → переназначение по §4, машина — туда же;
  5. слот объекта освобождается (канонические нули), окрестности пересобираются локально.
- **Поиск** (фаза 3, до `RerouteQueue`, по порядку кольца): машина повторяет `TryReserve` к цели ноги не чаще раза в `search_retry_s`.
  Успех → `ParkFac`, новые `DestLane/DestS`, машина в `RerouteQueue` (kind = Miss, `routing.md` §9.7). Пока поиска нет, машина едет к прежней
  точке (`DestLane/DestS` не меняются, полоса жива или машина в дренаже ADR-0023).
- **Лимит.** Машина без резерва достигла `DestLane/DestS` или `Tick − ParkSearchTick ≥ search_max_s` → постановка на `Overflow` у участка
  цели при ближайшем прибытии: при истечении лимита `DestLane/DestS` = `CarLane/CarS` участка цели (перемаршрутизация), прибытие
  без резерва → `CarFac = 0`, `CarLot = участок цели`, `parking_overflow++`. Повторного круга нет: из поиска есть только прибытие.
- Выезд с `Overflow` — из `CarLane/CarS` участка `CarLot` (по §6), `CarLot = −1`.
- Время от `ParkSearchTick` до резерва или `Overflow` идёт в `parking_search_time` той ноги.

## 8. Плата, экономика, выбор способа

- **Плата** — при постановке гостя (`Park`), если `Fee > 0`: проводка `Ledger` «житель → владелец» (стоянка здания → счёт здания, обочина и
  гараж → `City`). CZ2 сохраняется. Нет денег у жителя — ставится в долг, как прочие траты 3.2 (правило `Ledger`), без отказа.
  Плата за домашнее место (разрешение) — вне 4.4 (вопрос владельцу №4).
- **Выбор способа** (`Demand/Choice.cs`, только в режиме): стоимость машины на тур получает `ParkCost(dest) + HomeWalk(r)` в децисекундах:
  `ParkCost` — §5 п. 2 для лучшего допустимого объекта окрестности цели **без учёта занятости** (массив по зданиям, пересчёт в дневном проходе),
  `HomeWalk` — ходьба к домашнему месту (туда и обратно). Ожидание мест видят скимы (наблюдение от заявки). Без режима выбор побитово прежний.
- **Агрегат** (`Demand/AggregateExec.cs`, `trip_execution = aggregate`): тот же `TryReserve` при заявке, `Park` в момент прибытия агрегата,
  ходьба добавляется к времени ноги. Решения не зависят от исполнителя (как `zoning-demand.md` §18).

| `SetCurbParking` | сегмент (handle), сторона (0/1/2 = обе), `CurbMode`, `Fee` | сегмент жив; `Paid` требует `Fee > 0` | `SetCurbParking(прежнее)` по сторонам |
| `BuildParking` | участок, строка типа гаража | участок без здания или с заброшенным, не `Lost`; тип вида `Parking`; деньги (если экономика 4.2) | `RemoveParking` |
| `RemoveParking` | здание-гараж (handle) | вид `Parking` | `BuildParking(RestoreOf)` (ёмкость и плата) |
| `SetParkingFee` | объект (handle), `Fee` | объект жив, не `Overflow`; `Fee ≥ 0` | `SetParkingFee(прежнее)` |

- Применение в фазе 1. Смена режима обочины пересчитывает ёмкость объектов стороны (§3) и окрестности. Превью (`player-tools.md` §7):
  `IssueCode.ParkingDisplaced` с числом закреплённых жителей и гостей, которых затронет снос/закрытие.
- `RemoveRoad` (T4): финал `RemoveSegment` → участки `Lost` (Z6) → `ParkingOps.Remove` для их обочин и стоянок.
- Типы гаражей — в `buildings.json` (`kind: "parking"`, `capacity` = мест, `parking_fee`); `base` получает один тип (§14).

## 11. Метрики (`SimCounters`, блок `parking` JSON бенча и `run`)
- `parking_search_time` — по закрытым машинным ногам: `LegParkWait` + время поиска §7, в тиках; сумма, число и гистограмма с фиксированными
  корзинами (0, ≤ 20 с, ≤ 60 с, ≤ 300 с, ≤ 600 с, > 600 с) — без float; в JSON — среднее и p95 по корзинам.
- `parking_no_spot_waits`, `parking_mode_switch`, `parking_tours_dropped`, `parking_overflow`, `parking_towed`, `parking_car_shed`,
  `parking_searching` (машин в поиске сейчас), `parking_walk_ticks` (сумма ходьбы от мест), заполненность `Σ(Assigned+Occupied)/Σ Capacity`
  по видам (‰, целые).
- Норма: `parking_overflow = 0` и `parking_searching = 0` без сноса; ненулевое значение без сноса — баг.

## 12. API и клиент (правка `core-api.md` §3, §5)
- `int GetParking(Span<ParkingRenderData>)` + `ParkingVersion` (меняется при создании, сносе, смене ёмкости). `ParkingRenderData` 24 Б:
  `X, Z, Heading` (float), `Kind` (byte), `Flags` (byte), `Capacity` (ushort), `Fee` (int), `Gen` (int), выравнивание.
- `ReadOnlySpan<ushort> ParkingFill` — `Assigned − HomeAway + Occupied` по индексу объекта (сколько машин стоит сейчас), публикуется
  копией в `Publish`, только если менялась (флаг грязи). Клиент ставит машины в слоты обочины по порядку `0..Fill−1` вдоль фасада
  (детерминированно, без данных о машинах).
- `ParkingStats GetParkingStats()` — POD счётчиков §11. В `ResidentInfo`: `HomeFac`, `CarFac`, `LegStage`; в `VehicleInfo`: `ParkFac`, поиск.
- Клиент (Godot): инстансы стоящих машин у обочин (по LOD рендера ADR-0014: только в фокусе), гаражи коробками, оверлей заполненности
  (зелёный → красный), инструменты §9 и подсказка «мест нет» у здания.

## 13. Сейв и хэш
- Блок `PARK` (только в режиме): все поля §2.1 кроме производных, свободные слоты — канонические нули; `ParkSearchQueue` (порядок кольца).
  Столбцы: `RESD` — §2.2; `VEHC` — `ParkFac`, `ParkFacGen`, `ParkSearchTick`; `TRIP` — `ParkRef`, `ParkGen`; `PARM` — параметры §14;
  `CNTR` — §11; `BLDG`/`BTYP` — `ParkingCapacity`, `ParkingAccess`, `ParkingFee`; сегменты — `CurbMode`, `CurbFee` по сторонам.
- `world_version` — **следующая свободная при мерже K1** (сейчас 3; T2 и M4 планируют 4 и 5), запись в `save-format.md` §12, приложение A,
  миграция `MigrationVn` только добавляет столбцы-дефолты (−1 / 0), блоков не создаёт. Корпус: `w{n}-*` прежних сценариев с тем же хэшем, плюс
  `w{n}-s1k-res-park`.
- Хэш: секция `ParkingHash` только в режиме (`hash_version` не меняется: режима раньше не было). Окрестности, `X/Z`, `WalkMm`, `ParkCost`,
  `ParkingFill` — производные, не хэшируются и не сохраняются; `Load` строит их заново.
- `SaveValidator.ValidateParking`: PK2, PK4, PK6; ссылки (`HomeFac`, `CarFac`, `ParkFac`, `ParkRef`) живы с верным поколением; `CarLot`
  только при `CarFac = 0`.

## 14. Сценарий (`scenario-format.md` §2.6, необязательная секция)
```json
"parking": { "model": "resource", "access_walk": "timer", "walk_max_m": 400, "home_walk_max_m": 300, "max_candidates": 16,
             "walk_speed_mps": 1.3, "fee_ds_per_money": 60, "retry_s": 30, "search_retry_s": 10, "search_max_s": 300,
             "home_retry_per_day": 0.02,
             "curb": { "slot_m": 6, "stop_clear_m": 15, "street": "free", "arterial": "off", "fee": 0, "permits": true },
             "garage": { "fee": 0, "permits": false } },
"capacities": { "max_parking": 0 }
```
- `max_parking = 0` → `max_lots + max_buildings + 64`. Дробные значения — в целые единицы в одном месте (`ScenarioLoader.Parking.cs`, правило
  ADR-0022). Неизвестные ключи отклоняются; `parking` без `residents` → `InvalidScenario`.
- `buildings.json`: поля `parking` (мест, дефолт 0), `parking_access` (`private|public`), `parking_fee`. Дефолты `base` (вопрос владельцу №1):
  R низкая 8 (`private`, 1 на квартиру), R высокая 20 (`private`, 0.5 на квартиру), C низкая 10 (`public`), C высокая 30 (`public`),
  I низкая 12 (`private`), I высокая 40 (`private`); гараж `base:building/parking_garage` — 200 мест.
- Сценарии: `s1k-res-park.json`, `s10k-res-park.json` = `*-res` + секция `parking`; прежние `*-res` не меняются (PK1).

## 15. Детерминизм, потоки, Rust
- PRNG не используется; порядок — по индексам и порядку колец; ничьи — по индексу объекта.
- Все массивы — в `Create`/`Load` по ёмкостям; `Step`, команды и локальная пересборка окрестностей не аллоцируют (scratch).
- Решения целые; `AccessS` — float только как позиция машины (как `CarS`). Модуль — без ссылок между объектами, переносим как есть.

## 19. Открытые вопросы

### Геймдизайн (владелец; дефолты уже в §14)
| № | Вопрос | Дефолт | Трейдофф |
|---|---|---|---|
| 1 | Вместимость стоянок по типам зданий | R 1 / 0.5 на квартиру, C = рабочих мест (низк.) и 30 (выс.), I 12 / 40, гараж 200 | Меньше мест — меньше машин в городе (`parking_car_shed`) и больше автобуса |
| 2 | Где разрешена стоянка на улице | улицы — да, артерии — нет; слот 6 м, 15 м у остановок | Стоянка на артериях — больше мест, но в реальности снижает пропускную (не моделируется) |
| 3 | Обочина у дома — закреплённое разрешение или общая | закреплённое (`permits: true`) | Общая честнее, но обратная нога может не найти место и потребует запасной цепочки |
| 4 | Плата: обочина, гаражи, разрешения жителей | всё 0; игрок ставит плату командой | Плата — рычаг игрока против машин в центре; связь с бюджетом города — 4.2 |
| 5 | Что делать при нехватке мест у цели | ждать дома ≤ `wait_max_s`, затем другой способ или отмена тура | Альтернатива «ехать и искать» реалистична, но это и есть T5 |
| 6 | Поиск у обочины вслепую как эффект (доля трафика от ищущих) | не моделируется | Можно добавить позже как задержку у цели без кружения |
| 7 | Гаражи — только игрок или растут сами в C высокой плотности | только игрок | Автогаражи упрощают игру, но снимают рычаг |

### Технические (оркестратор)
| № | Вопрос | Рекомендация | Трейдофф |
|---|---|---|---|
| 1 | Номер `world_version` и `CommandKind` | Следующие свободные при мерже K1 / K6, запись в журналы | Порядок мержа с T-волной и 4.2 сдвигает номера |
| 2 | Резерв в 2r вместо фазы 3 | Да (§5): нет блокировки головы `PendingTrips` | Формулировка плана «при построении маршрута» выполняется по смыслу: маршрут строится уже к месту |
| 3 | Ходьба таймером или агентами по умолчанию | Таймер; агенты — `access_walk = agents` (K4) | Агенты дороже на s10k-res (+≈ 2 пешехода на машинную ногу) |
| 4 | Расстояние ходьбы — манхэттен вместо пути по сети пешеходов | Да в 4.4 | Через реку/артерию без перехода оценка занижена; компоненты связности всё же проверяются |

| 6 | Объект обочины на участок, а не на сторону сегмента | На участок | Нет мест вдоль фасадов без участков (у узлов) — честно мало |

### K1 (2026-10-28, агент L27): поверхность и данные
- **Сейв.** `world_version` 10 (`MigrationV10`, `save-format.md` §12, приложение A): блок `PARK` (пул объектов + поля §2.1 без производных), `PARM` 220-239, `BTYP` 10-12, `RESD` 41-49, `VEHC` 42-44, `TRIP` 12-13, `CNTR` 157-172. Окно v10 открыто до K8: K2-K7 вправе дописывать столбцы с дефолтом в `MigrationV10` и перегенерировать корпус `w10-*`. `ParkSearchQueue` (§13) в `PARK` не включена — её добавит K3 вместе с кольцом.
- **`AccessLane/AccessS/PedEdge/PedSMm` — производные, не состояние.** Они считаются из участка (`Lots.CarLane/CarS/PedEdge/PedSMm`, `AccessS` ограничен `[0, Length − MinPhysicalGap]`) в `ParkingBuild.RefreshAll`, которую зовёт `LotBuilder.RestoreDerived`/`OnRoadBuilt`. Так индексы полос и рёбер тротуара не нужны в `RefKind` и их не надо переносить при правках сети (T3). `AccessS` — без правила горизонта ворот (это §6, K2).
- **Положение объекта без тригонометрии.** `X/Z` = ось сегмента в середине отрезка участка + нормаль × `FrontOffsetM` (`LotBuilder.FrontPoint`); `WalkMm` обочины до центра своего участка и пары (объект, участок) в окрестностях — манхэттен в целых мм усечением (`Catchment.Manhattan`).
- **Окрестности.** Плоские массивы со стоянкой `max_candidates`; в список входят объекты с флагом `Public` и стоянка здания самого участка (любой вид доступа, `WalkMm = 0`), поэтому `Public`-стоянка здания C доступна гостям соседних участков; `Private` C/I — только своему зданию. Условие пешеходной компоненты — `PedComp` равны, когда есть сеть пешеходов. Корзинная сетка 100 м пересобирается целиком при любой правке (O(объекты)), окрестности — для участков в манхэттен-радиусе `walk_max_m` от точки правки (`RebuildNear`); тест: локальная = полной.
- **Обочина.** Один объект на участок, если у стороны есть полосы и режим не `Off` (`curb.street`/`curb.arterial` по `RoadKind`; режима стороны сегмента в сейве K1 нет — его принесёт K6 вместе с `SetCurbParking`). Ёмкость = `floor(фасад/slot)` − 1 слот въезда, если у здания участка своя стоянка, − `ceil(пересечение/slot)` на каждую остановку той же полосы в зоне `±stop_clear_m`. Переходы на перегоне пока не вычитаются. Пересчёт ёмкости — в `CreateAll`, при `Active`/снос здания (`RecomputeCurb`); уменьшение резервы и стоящих не трогает.
- **Жизненный цикл зданий.** Хуки `Growth.Complete` (создать), `Growth.Abandon` (`Closing`), `Growth.RemoveAbandoned` (снести), `LotBuilder.OnSegmentRemoved` (снести обочину потерянного участка), `LotBuilder.OnRoadBuilt` (обочины новых участков). Гараж (`LotZone.Parking = 4`, тип `kind: "parking"`) создаётся тем же путём, но типа в `base` и команды пока нет (K6).
- **Дом.** `HomeAssign.TryAssign/AssignInitial/OnMoveIn/Release`; `Market.MoveOut` освобождает место, `TryRelocate` и `Immigrate` закрепляют новое (нет места — `HasCar` снимается, `parking_car_shed++`). Это шире строки K1 («начальное население»), но без этого PK6 ломался бы при первом въезде; ежедневный проход `Overflow`-дома остаётся за K3.
- **`ParkingOps`.** `TryReserve/Release/Park` — заглушки (K2, сигнатуры заморожены); `Remove(w, f)` рабочий уровня K1: закрепившие переназначаются (иначе `Overflow` у дома), стоящие гости эвакуируются, слот освобождается, окрестности пересобираются локально. Машины в пути и заявки с резервом на объекте (K3) в K1 невозможны.
- **Хэш.** `ParkingHash` (объекты, поля жителей/машин, счётчики §11) и поля заявок `ParkRef/ParkGen` — только в режиме; без секции `parking` хэш, сейв (кроме столбцов-дефолтов) и поведение прежние (корпус `w1-w9` и golden). Тест `ParkingDataTests` (создание детерминировано = Load, формула ёмкости, окрестности, `HasCar` снят ровно у не получивших место, снос, рост на коротких сутках, 1/2/3 потока, 0 Б/тик, землепользование).
- **Валидатор.** `ParkingCheck.Validate` (PK2 пересчётом, PK6, ссылки с поколением; PK4 — в части K1: ссылки живы, `CarFac = −1` допустим, строгое «ровно в одном месте» после K2) вызывается `SaveValidator.ValidateParking` и тестами.
- **Землепользование в сейве (долг VS8).** Блок `LUSE` (полигоны 36 Б по столбцам, есть ⇔ `PARM.LandUseCount > 0`): `Load` кладёт их в `World.LandUse`, нарезка новых участков после `Load` обходит парки и воду как в `Create`. Сейвы до v10 полигонов не несут (параметров `city.landuse` в файле нет).
- **Сценарий.** `scenarios/s1k-res-park.json` = `s1k-res` + `parking.model = "resource"` (нужен корпусу `w10-s1k-res-park`; K2 вправе его расширить). Корпус: все прежние сценарии w10 с теми же хэшами, что в w9.

### K2 (2026-10-28, агент L36): резерв и ноги micro
- **Вход прибытия — один, для micro и meso.** `TripLegs.OnVehicleArrived` уже зовут и `ArrivalPhase`, и `QueueMeso.Arrive`, поэтому постановка (`ParkingOps.OnArrival` → `Park` / дом) происходит в нём, и **`Lod/QueueMeso.cs` не правился** (N3 держит `Lod/**`). Отдельный вызов из `QueueMeso` не нужен; `ParkingOps.OnMesoArrival` оставлен как документированный синоним на случай, если после слияния N3 прибытие meso станет отдельным путём. Тест `Meso_ArrivalGoesThroughParking_Pk2To5Hold` (режим `all_meso` на `s1k-res-park`).
- **`TryReserve` не пишет в жителя.** Ходьба `CarWalkMm` меняется только при постановке (`Park`: `WalkTo` по окрестности участка цели ноги), иначе снятая заявка оставила бы жителю чужую ходьбу. Обратная нога домой: `ParkRef = 0`, у машины `ParkFac = -1`, на прибытии `HomeFac` либо `Overflow` у дома (`parking_overflow++`); гостевое место, совпавшее с `HomeFac` самого жителя, ставится как домашнее (только `Reserved--`, `HomeAway--`).
- **Заявка и деньги резерва.** Резерв — в `SubmitParked` после проверки `Trips.IsFull`; нет места → заявка не подаётся, событие `Depart`/`EndActivity` через `retry_s` (не позже дедлайна), `parking_no_spot_waits` раз на ногу (отметка `LegParkWait = -1`, при успехе заменяется ожиданием `Tick - LegWaitFrom`). Дедлайн `WaitDepart` считается от `LegWaitFrom` (`LegReq`, если пешего участка к машине не было). Снятие резерва — везде через `ParkingOps.Release/ReleaseRef`: `CancelRequest`, `OnTripDropped(w, r, in trip)` (сигнатура получила заявку: вызывающий уже убрал её из очереди), машина без жителя.
- **Смена способа по причине мест** (`parking_mode_switch`, `parking_tours_dropped`): дедлайн сработал, а заявка в `PendingTrips` так и не попала (нет места или очередь полна). Сбой маршрута (`OnTripDropped`) в эти счётчики не входит. **Обратная машинная нога способ не меняет** (иначе машина осталась бы стоять у цели и дом стал бы недостижим, PK6): при дедлайне — `res_stuck++` и повтор, как раньше.
- **Стадии ноги.** `WalkToCar`/`WalkFromCar`: житель `InLeg` без агента, событие `ResidentEvent.AccessWalkDone` (6, `SaveValidator.City` пропускает его вместе со стадией ходьбы), накопитель `LegWalk` и `parking_walk_ticks`. `Drive` ставит `OnDeparture` (место освобождается в момент выезда: гость `Occupied--`, `Overflow` `Occupied[0]--`, своё место `HomeAway++`). Эвакуация (K1) не лишает пути машину в пути: `Remove` оставляет ей `CarFac = -1`. После эвакуации (`CarWalkMm = -1`) нога идёт без машины, а по возвращении домой другим способом ходьба восстанавливается (`OnReturnedHome`).
- **Правило горизонта ворот — в `AccessS`.** `ParkingBuild.GateSafeS`: не ближе `max(30 м, MinGap + 1.5 м)` к концу полосы (та же оценка, что `farDistance` в `GatePhase.ScanActive`), короткая полоса — 0; одна позиция и для прибытия (`DestS`), и для выезда. Вторая причина падения Debug-сверки `GatePhase` (`OutReserved[..] 0 против 12`), которую правило горизонта не снимает: машина, вставленная **перед допущенной** (автобус с допуском в 60 м от конца), ломает префикс допущенных головы полосы. `Spawner.TryPlace` для машин жителей в режиме отказывает, если ведомая (`behind`) допущена; выезд без зазора пробует `s - 8 м`, `s - 16 м`, иначе заявка в хвост очереди (тест `Day_*`/`T5_*` в Debug).
- **PK4 строго**: `ParkingCheck` код 9 — у жителя с машиной `CarFac >= 0` ⇔ машин жителя на дороге нет, `CarFac = -1` ⇔ ровно одна; PK6 ослаблен до «гость без дома не бывает» (`CarFac > 0` без `HomeFac`), потому что машина в пути имеет `CarFac = -1`. `HomeAway` ведётся инкрементально (выезд/прибытие/`HomeAssign.Release`), `Remove` пересчитывает его целиком.
- **Метрики.** `parking_search_time` закрытой машинной ноги (micro) = `LegParkWait` (+ поиск K3 из `ParkSearchTick` машины); сумма, число и шесть корзин (§11) пишет `RecordSearchTime` в `OnLegArrived`. Плата (§8) в `Park` — K5; сейчас `Fee` учтён только в стоимости выбора.
- **Сейв.** Новых столбцов не понадобилось (все поля ноги K1 уже в `RESD`); корпус `w10-s1k-res-park-t24000` перегенерирован отдельным коммитом (поведение сценария изменилось).
- **Цель позади на том же направленном сегменте** (`DirSeg` равны, `FromS > DestS`): `Router` возвращает `NoPath` (назад ехать нельзя), заявка падала бы по кругу каждый тик (`res_stuck` 39 тыс. за 3 суток до правки). Машина переставляется без выезда на дорогу (`ParkingOps.Hop` = `OnDeparture` + постановка), нога идёт в `WalkFromCar` либо сразу в кольцо прибытий (`Begin.Instant`).
- **Цифры `s1k-res-park`, 3 игровых суток (216 000 тиков, Debug-прогон, 1 поток).** По умолчанию: машинных ног 12 288, закрыто 12 272, `parking_search_time` = 0 тиков (все в корзине 0), `no_spot` 0, смен способа 0 (доля 0 %), `res_stuck` 0, `parking_overflow` 0, ходьбы от мест 0 (у каждого здания своя стоянка). Ёмкость всех объектов ×0.5: ходьба 76 658 тиков, ожиданий нет. Ёмкость ×0.05 (гостевых мест почти нет): `no_spot` 2 725 ног, смен способа 2 128 (55 % начатых машинных ног 3 897), туров снято 165, закрытых машинных ног 1 446 со средним `parking_search_time` 1 011 тиков (≈ 51 с; корзины 0/≤20 с/≤60 с/≤300 с/≤600 с = 1 142/0/63/139/102), `res_stuck` 0. Ожидание ног, сменивших способ, в `parking_search_time` не входит (нога закрыта другим способом).
