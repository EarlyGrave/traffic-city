# Новая игра с нуля: Юрьев-Польский, въезд с края карты (спецификация, задача Y2, ADR-0037)

Статус: черновик на подтверждение владельцу (агент L82, 2026-10-29). Цифры с пометкой [Старт] — стартовые значения для калибровки,
[Оценка] — расчёт без прогона, [Факт] — прочитано в коде. Замеров в этой спеке нет: их даёт задача Y7.

## 0. Идея в трёх абзацах

1. **Сейчас «новая игра» = готовый город** (`progression.md` §7.3, `scenarios/game-city.json`, `ReadyCity.Prepare`): 11 тыс. жителей,
   сеть уже построена. Нужен второй режим, как в Cities: Skylines — пустая карта рельефа Юрьева-Польского, одна готовая артерия с юго-запада
   (направление на Москву), а город игрок строит сам. Жители въезжают по этой дороге: у края карты появляется машина переселенца и едет к новому дому.
2. **Минимум новой механики — «внешний мир у края карты»** (`outside`). Это узел сети на краю карты, через который (а) въезжают новые жители,
   (б) работают «внешние рабочие места» (Москва и область): пока своих фирм нет, жители ездят на работу за край карты. Без (б) город не
   стартует: спрос на жильё `R = вакансии − ищущие + r_bias` [Факт, `Growth.UpdateDemand`], а вакансий в пустом городе ноль.
   Внешние места дают и первый трафик по артерии — то, ради чего игра.
3. **Всё остальное — уже есть**: участки нарезаются вдоль новых дорог (`LotBuilder.OnRoadBuilt`), рост зданий по спросу (`Growth.Build`),
   вехи и замки инструментов (`progression`), рельеф (`terrain`). Нужно поправить три «нуля», которые ломают старт с пустого города
   (§2.2), и добавить пункт меню (§4).

## 2. Ядро

### 2.1 Внешнее подключение (`outside`) — данные сценария

Новая необязательная секция, `format_version` не растёт (как `progression`, `terrain`). Нет секции — поведение, хэш и сейв побитово прежние.
Разрешена только при `demand.model = "residents"`.

```jsonc
"outside": {
  "connections": [
    { "id": "moscow",            // строка для UI (имя на карте берёт клиент из ресурсов по id)
      "node": 0,                 // индекс узла явной сети (network.nodes); узел обязан лежать в пределах 50 м от края world_bounds
      "jobs": 3000,              // [Старт] внешних рабочих мест (вакансий) за этим краем; 0 — только въезд
      "job_cost_s": 2400,        // [Старт] доп. «время за краем» в обобщённой стоимости поездки на внешнюю работу, с (40 мин до Москвы условно)
      "immigrant_share": 1.0 }   // доля въезжающих через этот въезд (сумма по всем = 1.0); пока один въезд
  ],
  "min_immigrants_per_day": 120, // [Старт] пол въезда: cap = max(min, max_immigrants_per_day · N) — иначе при N = 0 въезда нет (§2.2)
  "outside_jobs_decay": 0.5,     // [Старт] доля внешних мест, которая «закрывается» за сутки сверх своих вакансий города (§2.4), 0 — никогда
  "arrival_by_car": true         // переселенец едет машиной от края к дому (§2.3); false — появляется дома сразу (как сейчас)
}
```

- Загрузчик (`Sim.Scenarios`, одно место): узел существует и у края; ≤ 4 подключений; `id` уникальны; сумма `immigrant_share` = 1 (±0.001);
  неизвестные ключи — ошибка с JSON-путём. Доли → Q16, секунды → тики.
- POD ядра: `OutsideDesc { int MinImmigrantsPerDay; int JobsDecayQ16; bool ArrivalByCar; int Count; OutsideConnDesc C0..C3 }`,
  `OutsideConnDesc { int Node; int Jobs; int JobCostTicks; int ShareQ16; }` — фиксированный размер, без массивов в `ScenarioDesc` (FFI).
- Узел подключения помечается флагом `NodeFlags.Outside` (новый бит): инструменты не дают его снести/сдвинуть (`RejectReason.Protected`,
  есть ли такой — проверить в Y3; иначе новый номер в конец), сегмент от него можно апгрейдить, но не удалить.

### 2.2 Три «нуля», ломающие пустой старт (правки без новой механики)

| Где [Факт] | Что ломается при 0 жителей | Правка |
|---|---|---|
| `CityGrid.TryCreate(w.Net, cellM)` — сетка ячеек по bbox **начальной** сети | Сеть = одна артерия → сетка ячеек узкая полоса; участки за её пределами прижимаются к краевой ячейке (`Clamp`), скимы бессмысленны | При наличии `tools.world_bounds` (или `terrain.extent`) сетка строится по ним. Только для новых сценариев с `outside` — у старых сетка прежняя (хэш). Проверка `Skims.MaxSkimEntries` на 6 км и `lod.cell_m` = 250 м: 24×24 = 576 ячеек — в пределе [Оценка] |
| `Growth.Daily`: `cap = max_immigrants_per_day · pop` | `pop = 0` → въезд 0 навсегда | `cap = max(outside.min_immigrants_per_day, rate · pop)` |
| Казна: `Endowment = initial_city_balance_per_resident · Alive` (`city-economy.md`) | 0 жителей → казна 0, стройка заблокирована | Новый ключ `economy.initial_city_balance` (абсолютный, [Старт] 150 000), прибавляется к прежнему |

Плюс **частота роста**: въезд и рост зданий сейчас раз в игровые сутки (дневной проход). На пустой карте игрок разметил зону и ждёт до
полуночи — до 60 мин на ×1. Правка (рекомендация, вопрос В1): ключ `zoning.growth_step = "hour"` — `Growth` (спрос, въезд, рост) идёт на
сдвиге часа KPI с лимитами /24; остальной дневной проход (фирмы, налоги, рынок работы) — как был. Дефолт `"day"` — старые сценарии побитово прежние.

### 2.3 Въезд машиной (`arrival_by_car`)

- `Market.Immigrate` как сейчас выбирает дом (логит по доступности) и создаёт жителя, но житель получает состояние `Arriving`
  (новое значение `ResidentState`, в конец перечня) и одну ногу `Outside → дом` способом «машина» вне зависимости от `car_ownership`.
- Нога исполняется существующим `TripLegs` (micro — агент, aggregate — как обычная нога без агента), начало — узел подключения:
  машина спаунится на полосе выезда из узла `Outside` тем же кодом, что вставка на участке (ожидание свободного места, `WaitMaxTicks`).
  Подключение выбирается по `immigrant_share` из потока PRNG `Demand` (один вызов на жителя, в порядке создания).
- Пока житель `Arriving`: не ищет работу, не планирует день. Прибыл → `AtHome`, дальше обычный автомат. Дом занят с момента выбора
  (иначе двое въедут в одно место). Не доехал за `wait_max_s` + 2 ч [Старт] → телепорт домой и счётчик `ArrivalTimeouts` (не застревание).
- Детерминизм: порядок создания = порядок индекса жителя, спаун — в фазе вставки по возрастанию индекса ноги. Многопоточность не меняется
  (нога — обычная). 0 Б/тик: состояние в существующих массивах жителя, новых коллекций нет.

### 2.4 Внешняя работа

- Каждое подключение = **виртуальная фирма**: элемент массива `OutsideJobs[k]` (вакансии, занято) в `CityWorld`, не здание. Рынок работы
  (`Market` §8.1) видит её как кандидата с местом «узел подключения» и стоимостью `C_commute(дом → узел) + job_cost`. Ячейка места —
  ячейка узла (скимы считают её как любую).
- Работник внешней фирмы едет на работу ногой `дом → Outside`, машина исчезает в узле (как прибытие на участок), вечером — обратно.
  Смена — 08:00–17:00 [Старт] (как у I-зданий по умолчанию).
- Зарплата: поток `External → житель` (налог города берётся как с обычной зарплаты; казна видит налоги жителей). Фирма в `Ledger` не заводится.
- Затухание: каждые сутки `OutsideJobs.Jobs = max(занято, Jobs − decay · (свои вакансии города))` — когда в городе появляются свои места,
  внешние перестают звать новых. Уволить никого не увольняем — работники уходят сами по обычному `switch_ratio`.
- Спрос: вакансии внешних фирм входят в `вакансии` формулы R (и только R; в I не входят — иначе I отрицательный навсегда).

### 2.5 Сейв, хэш, API

- `world_version` 13 (после TR1 = 12), `MigrationV13`: «подключений нет». Блок `OUTS` только при секции: на подключение — `Jobs`, `Taken`,
  счётчики въезда/выезда за сутки. Состояние `Arriving` и нога жителя уже лежат в блоках жителей (новое значение байта). Раздел хэша — новый номер,
  только при секции. Корпус сейвов: `w13-outside-*` (пустой город, середина въезда с машиной в пути).
- API клиенту (`Api/Simulation.Outside.cs`): `int OutsideCount`, `OutsideInfo GetOutside(int k)` — `{ Node, X, Z, JobsTotal, JobsTaken,
  ArrivalsToday, ArrivalsInTransit }` для значка на краю и подсказки. События: `ImmigrantsArrived` (A = число за час, B = подключение) — для тоста
  «Въехало 12 семей». Снапшот машин не меняется (машина переселенца — обычная машина; бит «переселенец» в `VehicleRenderData` — вопрос В4).

## 3. Прогрессия старта с нуля

### 3.1 Стартовые условия [Старт]
- Население 0, `residents.initial_fill = 0`, `zoning.auto` нет (участков нет, пока нет улиц), `zoning.growth = true`.
- Казна `initial_city_balance` 150 000 (≈ 60–80 сегментов улицы с участками [Оценка] по `tools.costs`), кредит — по `city-economy.md` как есть.
- Время старта — 06:00 суток 0 (`calendar.start_hour`, если ключа нет — добавить в Y4; без него 6 игровых часов пустой ночи).
- `r_bias` 0: спрос R даёт внешняя работа (§2.4).

### 3.2 Открыто на M0
Улица `street_2`, `oneway_2`, снос, **зонирование кистью R/C/I** (`PaintZone`; в готовом городе оно на M4, здесь без него игра невозможна),
разрез/слияние, знаки, запреты поворотов, налоги. Закрыто: `arterial_4/6`, `asym_1_2`, светофоры (фикс. и адаптивный), автобусы, полосы, кривые.

### 3.3 Вехи (новый набор в сценарии; механика `progression` не меняется)

## 4. Клиент: «Новая игра»

- Главное меню → «Новая игра» → экран выбора из двух карточек: **«Готовый город»** (как сейчас, `ReadyCity.Prepare`, полоса подготовки ~45 с) и
  **«Юрьев-Польский с нуля»** (подпись: «Пустая карта, одна дорога из Москвы. Стройте город сами»). Под карточками — поле seed (свёрнуто, «Дополнительно»).
- «С нуля»: `ScenarioLoader.LoadInfo("scenarios/yuryev-scratch.json")` → `Simulation.Create` → `SimThreadHost`, без `ReadyCity` (пустой мир готовится за
  доли секунды [Оценка]; дальше — только загрузка рельефа). Сейв первой минуты не нужен.
- В игре: значок «Москва» на узле подключения (из `GetOutside`), подсказка первого шага (одна строка, закрывается), тост `ImmigrantsArrived` (слияние 10 с).
- Камера стартует над узлом подключения, а не над центром карты.

## 6. Открытые вопросы владельцу

**В1. Как часто растёт город с нуля.** Сейчас новые дома и жители появляются раз в игровые сутки — в полночь. В готовом городе это незаметно,
а на пустой карте игрок разметил зону и смотрит на пустоту до 60 минут реального времени.

| Вариант | Что видит игрок | Плюсы | Минусы и риски | Цена |
|---|---|---|---|---|
| **А. Рост каждый игровой час (реком.)** | Стройки через 1–2 мин после разметки (×2) | Отклик как в CS; логика та же, только чаще | Дневной проход дробится; нужен тест, что сутки = 24 часа по сумме | Y4 +0.5 дня |
| Б. Раз в сутки, но старт в 20:00 | Первая стройка через ~10 мин, дальше раз в 30 мин | Ноль кода в росте | Ощущение «игра зависла» после каждой разметки | 0 |
| В. Ускорять время ×8, пока город < 100 жителей | Время летит, пока пусто | Просто | Неуправляемо для игрока, сбивает KPI | мало |

Рекомендация А: без быстрого отклика на разметку режим «с нуля» не играется.

**В2. Как появляются переселенцы.**
