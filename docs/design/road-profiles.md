# Профили дорог, мировая сетка 8 м и участки на сетке (`road_profiles`)

Статус: спека, 2026-10-27 (агент L10), ответы владельца — §9. Решение — ADR-0030 (принят). Реализация — после мержа
`local/corner-radius` (ADR-0028, `world_version` 6), карманов BB1–BB3 (ADR-0029, `world_version` 7) и VS8. Задачи — §8.

## 0. Как сейчас и что меняем
- Ширина дороги нигде не хранится. Она выводится из `NetworkOptions.LaneWidth = 3.5` (одна на сеть), умноженной на число полос.
  Тротуар — глобальный `peds.sidewalk_width_m` (3 м). Без пешеходов участки берут `SidewalkDefaultM = 3`. Разделителя нет.
- Полуширина проезжей части считается заново в четырёх местах: смещение полос (`NetworkBuilder.AddSegment`), `h(a)` отступа рукава
  (ADR-0028), углы и переходы пешеходов (`PedNetwork.HalfRoad`), фасад участков (`LotBuilder.FrontOffsetM`).
- Участки сейчас выровнены по дороге: фасад идёт по `S` оси, прямоугольник повёрнут по касательной, а сетка занятости 8 м служит
  только для отбраковки пересечений. `RejectReason.Overlap` объявлен, но не выдаётся.
- **Владелец (2026-10-27):** модуль 8 м на весь город. Ширина профиля кратна 8 м, полоса 3–4 м, остальное — тротуары и газоны.
  **Дороги строятся свободно** (под любым углом, по кривой), привязка к мировой сетке опциональна. **Участки всегда лежат на мировой сетке 8 × 8.**

## 1. Профиль дороги
**Сечение** — упорядоченный список элементов слева направо, если смотреть по оси A→B (движение правостороннее, полосы `forward`
идут справа). Ось сегмента сети — середина профиля (`W/2`). Смещение элемента считается от неё, `+` — вправо.

| Тип | Допуск ширины | В симуляции |
|---|---|---|
| `sidewalk` | ≥ 1.5 м | ребро тротуара пешеходной сети этой стороны |
| `verge` (газон) | ≥ 0 | ширина и рендер |
| `curb` | 0–0.5 м | кромка проезжей части: от неё считаются `h` (ADR-0028) и длина перехода |
| `lane` (`dir`: `forward`/`backward`) | 3.0–4.0 м | полоса движения: своё смещение и своя ширина |
| `median` | ≥ 0 | ширина (островка безопасности нет) |
| `bike`, `parking`, `tram`, `bus_bay` | 1–4 м | **резерв**: занимают ширину, полос в сети нет |

**Каталог** — `scenarios/road-profiles.json`, язык-независимый, ширины в м (ядро хранит целые мм). Стартовый набор
(Σ проверена; все конкретные метры живут только здесь, см. §2):

| id | kind | W, м | Сечение слева направо (м) |
|---|---|---|---|
| `street_2` | street | 16 | sidewalk 3, verge 1.25, curb 0.25, lane← 3.5, lane→ 3.5, curb 0.25, verge 1.25, sidewalk 3 |
| `oneway_2` | street | 16 | sidewalk 3, verge 1.25, curb 0.25, lane→ 3.5, lane→ 3.5, curb 0.25, verge 1.25, sidewalk 3 |
| `arterial_4` | arterial | 24 | sidewalk 3, verge 0.75, curb 0.25, 2 × lane← 3.5, median 2, 2 × lane→ 3.5, curb 0.25, verge 0.75, sidewalk 3 |
| `arterial_6` | arterial | 32 | sidewalk 3, verge 1.25, curb 0.25, 3 × lane← 3.5, median 2, 3 × lane→ 3.5, curb 0.25, verge 1.25, sidewalk 3 |
| `asym_1_2` (задел) | arterial | 24 | sidewalk 3, verge 2.5, curb 0.25, lane← 3.5, median 2, 2 × lane→ 3.5, curb 0.25, verge 2.5, sidewalk 3 |

```json
{ "format_version": 1, "module_m": 8,
  "profiles": [ { "id": "street_2", "kind": "street", "width_m": 16, "elements": [
      {"type": "sidewalk", "w": 3}, {"type": "verge", "w": 1.25}, {"type": "curb", "w": 0.25},
      {"type": "lane", "w": 3.5, "dir": "backward"}, {"type": "lane", "w": 3.5, "dir": "forward"},
      {"type": "curb", "w": 0.25}, {"type": "verge", "w": 1.25}, {"type": "sidewalk", "w": 3} ] } ] }
```

**Асимметрия и направление.** `LanesAB` = число `forward`, `LanesBA` = число `backward`. Нынешние поля `SegmentData` не меняются,
`lanesAB ≠ lanesBA` они уже допускают. Профиль задаётся в направлении рисования. Сегмент, построенный B→A относительно профиля,
получает бит `SegmentFlags.Mirrored` (бит 2, свободен): элементы читаются в обратном порядке, `forward` ↔ `backward`.
Одностороннюю дорогу задаёт профиль без `backward`, отдельного типа не нужно.

**Привязка.** В сценарии — `"road_profiles_file"`. В генераторе — `city.profiles: {"street": "street_2", "arterial": "arterial_4"}`:
число полос берётся из профиля, а не из жёстких «1+1 / 2+2». В явной сети у сегмента — `"profile": "id"`: `lanes_ab/lanes_ba/kind`
тогда выводятся, а если заданы, обязаны совпасть. Индекс профиля — порядок в файле. **Если `road_profiles_file` нет, включается режим `legacy`**:
прежняя геометрия, хэши и сейвы побитово прежние. Константы 3.5/3 остаются только в `LegacyGeometry` (одно место, только для старых сетей).

**Валидация** (загрузчик, `InvalidNetwork`, одинаково в C# и Rust):
- ширины — целые мм; Σ = `width_m` = `k · module_m`, `k ∈ 1..8`;
- ≥ 1 полосы; полосы одного направления идут подряд, `forward` правее `backward`;
- между полосой и тротуаром/газоном — ровно один `curb`;
- ширина каждого элемента — в допуске таблицы; полос на направление ≤ 8;
- `id` уникальны; ≤ 64 профилей, ≤ 16 элементов в профиле.

## 2. Изменяемость (сквозное требование владельца)
Ширины должны меняться быстро и ничего не ломать.
1. **Все метры — только в JSON** (каталог, `module_m`). В коде ядра, клиента и Rust нет ни одной ширины, кроме `LegacyGeometry`.
   Ревью: grep литералов `3.5f|4.25|16f|24f` в `Network/`, `Peds/`, `City/`, `game/` = 0.
2. **Тесты проверяют инварианты, а не метры.** Игровой каталог загружается и валидируется. Для каждого профиля: Σ = k × module,
   порядок, непрерывность групп полос, смещение полосы = вычисленное из элементов. Ожидаемые значения тесты берут из самого
   каталога, литералов в них нет.
3. **Golden — от каталога-фикстуры** `tests/fixtures/road-profiles.fixture.json`: копия стартового набора, заморожена. Golden-тесты
   (`HotPathGoldenHashTests`, `AdaptiveGoldenHashTests`, `BasePackageGoldenTests`, сеть s1k, golden Rust-пилота) подменяют
   `road_profiles_file` фикстурой через хелпер загрузки (`ScenarioOverrides.Profiles`). Правка игрового каталога golden не трогает.
4. **Смена ширины = пересборка сети в `Create`.** Миграций и кода не нужно. Сейв хранит свой каталог (`RPRF`, §3.4), поэтому
   загруженный город и дороги, построенные в нём, остаются в прежних ширинах. Команда «применить новый каталог» — вне объёма (вопрос 3).
5. **Что всё-таки придётся сделать после правки игровых ширин:** перемерить качество (доля ожиданий, участки) и облачный baseline
   (`update-baseline`), потому что геометрия меняет поведение. Тесты и golden при этом зелёные.

## 3. Ядро
### 3.1 Данные (SoA, без ссылок)
- `RoadProfileStore` создаётся в `Create`, в тике только читается.
  - По профилю: `FirstElem, ElemCount, WidthMm, Kind, LanesFwd, LanesBwd`.
  - Производные: `CurbLMm/CurbRMm` (ось → кромка), `WalkLMm/WalkRMm` (0 — тротуара нет), `EdgeMm = WidthMm/2`, `LaneOffsetMm[k]`, `LaneWidthMm[k]` в нумерации `LaneNo`.
  - По элементу: `Kind, Dir, OffsetMm, WidthMm`.
  - В режиме `legacy` профилей нет, `SegmentData.Profile = -1`.
- `SegmentData.Profile` (`int`, в конце структуры), бит `Mirrored`, `LaneData.Width` (`float`, м; пишется при эмиссии).
  Клиенту — `NetworkView.RoadProfiles` и `ProfileElems` (blittable, для FFI так же).

### 3.2 Кто берёт ширину из профиля
| Где | Было | Станет |
|---|---|---|
| `NetworkBuilder.AddSegment` | `halfWidth − (k + 0.5)·LaneWidth` | `LaneOffsetMm[k]` (с учётом `Mirrored`), `Lanes[].Width` |
| `PlanSetbacks`/`IncrementalSetback` (ADR-0028) | `h = (AB+BA)·W/2` | `h = max(CurbLMm, CurbRMm)` поперечного рукава. У асимметричного профиля оценка консервативная; точная (кромка ближней стороны) — по запросу |
| `TransitionPhase.LateralOffset` | `p.LaneWidth` | `(Width[from] + Width[to]) / 2` |
| `Connectors` (разворот, радиус) | `_o.LaneWidth` | `Width` входной полосы |
| `PedNetwork` | `HalfRoad + sw/2` | по сторонам `Curb{L,R} + Walk{L,R}/2`; переход `CurbL + CurbR + (WalkL + WalkR)/2`; стороны без тротуара нет |
| `LotBuilder` | `max(lanes)·W + 3` | полоса дороги `±EdgeMm` для растеризации (§4) |
| Снапшот кармана BB2 | `LaneWidth` | `Width` крайней полосы (позже — элемент `bus_bay`) |

Следствия для стартовых профилей:
- **Артерия 24 м:** кромка 8 м вместо 7. Отступ рукава у артерии становится `8 + corner_radius` (+1 м), полосы BA сдвинуты разделителем.
- **Улица 16 м:** проезжая часть та же, тротуар 3 м, как сейчас, газон 1.25 м добавляет ширины.

### 3.3 Хэш, детерминизм, 0 B/тик
- Профили считаются в `Create`. В тике — одна загрузка `Lanes[].Width` в `LateralOffset`, аллокаций нет.
- Смещения считаются из целых мм одной формулой, `(OffsetMm + WidthMm/2) · 0.001f` — побитово одинаково в C# и Rust.
- Раздел профилей, `Segment.Profile` и `Lane.Width` попадают в `NetworkStore.Hash()` и `desc_hash` **только в режиме профилей**.
  В `legacy` хэш прежний (`Legacy_ReproducesNetworkHash`). От числа потоков хэш не зависит.

### 3.4 Сейв — `world_version` 8 (после 7 у BB1)
- Новые данные:
  - блок `RPRF` — каталог целиком;
  - столбцы `NSEG.Profile` (бит `Mirrored` — в уже сохраняемом `Flags`), `NLAN.Width`, `PARM.RoadProfileMode`;
  - `PARM.WorldGridOriginX/Z`;
  - столбцы `LOTS` из §4.4.
- RP2 объявляет все столбцы v8 сразу, как Z1 у города, чтобы RP5 не поднимал версию второй раз.
- `MigrationV8`: режим `legacy`, `Profile = -1`, `Width = NetLaneWidth`, у участков `Orient = 255` (прежняя геометрия вдоль дороги).
  Корпус `w1`–`w7` — прежние хэши, новый — `w8-*`.

### 3.5 Rust-пилот
- `tc-scenarios` читает каталог с той же валидацией. `tc-core` повторяет эмиссию по профилю, `Mirrored` и `h`.
- Golden `net-profiles.json` строится от фикстуры: улица, односторонняя, артерия 3+3, `asym_1_2` в обе стороны рисования.
- Golden `err-profile-*`: сумма не кратна модулю, полоса 4.5 м, нет `curb`.
- Прежние golden (явные сети без профилей) не меняются. Растеризация участков (§4) — целочисленная, порт тривиален, но в пилот не входит.

## 4. Мировая сетка 8 м и участки
### 4.1 Сетка
- Начало — `(0, 0)` мира, клетка `module_m` (8 м), индекс `(ix, iz)` — целые.
- Генератор ставит узлы на сетку (§5), инструменты — по желанию игрока (§6). Сама дорога о сетке не знает: ось и профиль — как построены.

### 4.2 Нарезка (`LotBuilder`, режим профилей). Всё в целых мм, ось сегмента округляется до мм
1. **Маска дороги.** Клетка — дорога, если в ней меньше `zoning.cell_min_share_pct` (дефолт 75) свободной площади. Площадь считается
   по 16 точкам 4 × 4 (целый счёт). Точка занята, если `dist²` до оси сегмента ≤ `EdgeMm²` или она внутри диска узла радиуса
   `max(NodeData.Radius, EdgeMm рукавов)`. Расчёт — `int64`, без `sqrt`: одинаково на любой платформе и в Rust.
2. **Цепочка фасада** стороны сегмента. Шаг 4 м по `S` от `node_clear_m` до `L − node_clear_m`; точка `ось(s) + n·(EdgeMm + 4 м)`.
   Клетка точки (повторы подряд схлопываются) — кандидат фасада. Если она «дорога», берётся следующая наружу, один раз.
   На прямой осевой дороге цепочка — ровный ряд, на косой — ступенчатый край, на кривой идёт за дугой.
3. **Ось глубины** — та из `±x/±z`, что ближе к наружной нормали в начале участка; ось фасада — перпендикулярная ей.
4. **Участок — прямоугольник клеток** `F × D`. Фасад — подряд идущие клетки цепочки в одном ряду, `F ≤ zoning.lot_frontage_cells`
   (дефолт 5); ряд сменился — участок закрывается. Фасад из одной клетки (дорога круче ~27° к сетке) склеивается со следующей,
   передний ряд — дальний, а клетка-уступ остаётся газоном. `F < 2` — участка нет.
5. **Глубина** `D ≤ zoning.lot_depth_cells` (дефолт 5, максимум 6). Все клетки должны быть не дорогой и свободны в сетке занятости.
   Если глубина не влезла, участок укорачивается до `D ≥ 2`, иначе отбрасывается.
6. **Порядок** прежний: сегменты по индексу, стороны 0, 1, первый занявший клетку побеждает. Угол достаётся сегменту с меньшим
   индексом, перекрытия блоков двух дорог невозможны по построению.

### 4.3 Что из этого следует
- **Ортогональная решётка генератора.** Узлы на сетке, профиль кратен 16 м (улица, `arterial_6`): кромка дороги совпадает с линией
  сетки, участки вплотную к ней. У профиля, кратного 8, но не 16 (`arterial_4` 24 м), край на `±12` м — полклетки. Эта клетка
  получается «дорогой», вдоль артерии остаётся газон 4 м (вопрос 2).
- **Косые и кривые дороги.** Ступенчатый фасад. Участки и здания стоят по сетке, а не параллельно дороге (как в SimCity 4, не как
  в CS2). Треугольники между кромкой и уступами остаются газоном. Чем ближе дорога к 45°, тем короче участки (F → 2) и больше
  потерь фасада.
- **Спрос и экономика** формул не меняют, меняются число и положение участков. Точка доступа (`CarLane/CarS`, `PedEdge/PedSMm`) —
  проекция центра переднего ряда на ось своего сегмента. `*-res` сценарии получают `road_profiles_file`, `city.profiles`,
  `zoning.lot_*_cells`. Число участков, домохозяйств и мест — в отчёте RP8.
- **Правки дорог проще, чем при участках вдоль дороги.** Участок не следует за дорогой. Расширение профиля или новая дорога
  переводят задетые клетки в «дорогу», и участки с ними получают `Lost`. Сдвигать участки не нужно.

### 4.4 Данные участка и сейв
- `LotStore` + `CellX, CellZ` (передний левый угол), `CellsF, CellsD` (byte), `Orient` (byte: ось глубины `+x, −x, +z, −z`,
  255 — legacy). Это теперь **состояние** (столбцы `LOTS` v8), а не производное: участок не должен сдвинуться, если дорогу расширили.
- `S0Mm/S1Mm` остаются (проекция фасада, нужна парковке у обочины, `parking.md` §4). Центр, курс, LOD-ячейка и точки доступа —
  производные.
- Сетка занятости — производная, при `Load` строится из участков. Её размер тот же, что у нынешней scratch-сетки (8 м по городу
  с полями). Для s1m предлагается упаковать её в биты.

### 4.5 Цена и риски против участков вдоль дороги
| | Вдоль дороги (прежнее предложение) | Мировая сетка (решение) |
|---|---|---|
| Работа | квантование в `LotBuilder`, ~0.5 дня | растеризация, цепочка, прямоугольники, столбцы `LOTS`, поворот зданий в клиенте — ~2 дня (RP5 + RP10) |
| Косые и кривые | участки по дороге, без потерь | уступы, газонные треугольники, короче участки |
| Правка дорог | участки сдвигаются вместе с дорогой | клетки «дорога» → `Lost`, участки стоят |
| Риски | — | (1) потери фасада и мест на диагоналях — мерить; (2) граница «доли клетки» чувствительна к мм, отсюда только целые; (3) полоса 4 м у профилей 24 м; (4) вид: здания не параллельны косой дороге |

## 5. Генератор на сетке 8 м
- **Шаг решётки `block_m` = 152** (19 клеток), сценарии — `size_m: [3040, 3040]`. Сейчас `nx = round(w/block)`, и при 3000/150 это
  `20·scale`. При 3040/152 — те же `20·scale` на всех ступенях лестницы (s1k … s1m): число узлов и сегментов, порядок PRNG, удаления
  улиц и выбор нерегулярных узлов совпадают с нынешними, меняется только геометрия. Площадь города +2.7 %.
  Шаг 144 (18 клеток) дал бы ровный ряд между улицами 16 м, но `nx` у s10k/s100k изменится (42, 104 …), и топология станет другой.
  Чтобы её сохранить, пришлось бы сжать карту до 2880 м (−8 % площади).
- Генератор берёт `bx = block_m` точно (а не `w/nx`). Валидатор: `block_m` кратен `module_m`. `halfW = 1520·scale` кратно 8 при
  целом `scale` (у всех сценариев так).
- **Джиттер — снап после розыгрыша**: координата округляется до ближайшего кратного `module_m`. Число и порядок PRNG-draw прежние,
  контракт «draw делается всегда» сохраняется. Нерегулярный узел (сдвиг до 40 м под случайным углом) после снапа даёт косые дороги
  с узлами на сетке. Узел слияния — тоже снап. `MinArmAngle` проверяется после снапа.
- Секция `city` в JSON: `snap_nodes: true` (дефолт в режиме профилей; `false` — прежнее поведение).

## 6. Инструменты игрока
- **`BuildRoadCmd`** получает `ushort Profile` (+1; 0 — legacy) и бит `Mirrored`. Полосы и тип берутся из профиля, рассогласование
  даёт `InvalidArgument`. Асимметричный профиль клиент разворачивает битом, если игрок рисует «против» профиля. Стоимость —
  прежняя `RoadCost` по полосам.
- **`UpgradeRoadCmd`** получает `ushort Profile`.
  - Смещения полос те же — правка на месте.
  - Смещения сдвинулись — перенос (`Relocate`, машины сохраняют `S`).
  - Изменилось число полос — существующий механизм ±полос.
  - Отступы соседних рукавов не перестраиваются (ADR-0028). Если новая `h + corner_radius` больше отступа — превью `Warning SetbackShort`.
- **`Overlap`**: полосы `±EdgeMm` пересекаются вне дисков общих узлов, или параллельные оси ближе `(W1 + W2)/2`.
  Участки с клетками, которые стали «дорогой», получают `Lost` (превью `ZoneLotsLost`).
- **Снап к мировой сетке** — только клиент (UI): концы, узлы и шаг кратны `module_m`, переключатель. Ядру он не нужен, команды
  несут уже округлённые координаты, реплей детерминирован. Клиент берёт `module_m` и начало сетки из `NetworkView`/`CityView`, а не из констант.

## 7. Клиент и порядок работ
- **Лента сегмента LOD0** строится по `ProfileElems`: асфальт — от кромки до кромки; бордюр, газон, разделитель и резерв — цвета

## 10. Решения при реализации RP1 (агент L13)
- `CurbL/CurbR` - расстояние от оси до внешнего края крайней полосы (внутренний край бордюра), а не до внешнего края элемента `curb`; отсюда `h` артерии 24 м = 8 м (как в §3.2).
  `h = max(CurbL, CurbR)`, от `Mirrored` не зависит.
- Режим профилей строг: у каждого сегмента явной сети и у обоих классов дорог генератора профиль обязателен (`InvalidNetwork` иначе); ссылка на профиль без каталога - тоже ошибка.
  Инструменты игрока (`BuildRoad`) до RP7 строят сегменты без профиля (`Profile = -1`, геометрия legacy).
- `Lane.Width` пишется у Normal-полос (из профиля или `NetworkOptions.LaneWidth`), у connector'ов 0; u-turn connector'а берёт ширину входной полосы. Сейв v7 (RP2 перейдёт на v8) при загрузке заполняет `Profile = -1`, `Width = NetLaneWidth`.
- Сохранение мира в режиме профилей поддержано с RP2 (`world_version` 8, см. §11); до RP2 каталог и `Profile` в сейв не писались.
- `NetworkStore.Hash()` хэширует полосы полями в прежней раскладке (60 байт); профильный раздел (каталог, `Segment.Profile`, `Lane.Width`) добавляется только при каталоге. То же для `NetworkHash.Network` и `desc_hash` (метка раздела `FORP`).
- **RP3 (агент L18, Rust-пилот).** `tc-core::api::profiles` (валидатор с теми же видами ошибок), `network::profiles::RoadProfileStore`, эмиссия по профилю

  golden `net-profiles`, `err-profile-*` (rust-pilot.md §5.1). Старые golden не менялись. C ABI профили не передаёт.

## 11. Решения при реализации RP2 (агент L17)
- `world_version` 8. `PARM` 188 `RoadProfileMode` (0 legacy, 1 профили), 189-190 `WorldGridOriginX/Z` (`ScenarioDesc.WorldGridOriginX/Z`, `World.WorldGridOriginX/Z`; в хэш не входят, поведение задаст RP5/RP9).

Столбцы: `ModuleMm`; по профилю `Kind`, `WidthMm`, `ElemCount`, `IdLength`; по элементу `ElemKind`, `ElemDir`, `ElemWidthMm`; `IdBlob` (UTF-8). При загрузке каталог проходит тот же `RoadProfileValidator`, что при `Create`.

У connector'а `Width = 0`, у обычной полосы `> 0`. RP7 (`UpgradeRoad` с другой шириной/числом полос) обязан сохранять эти инварианты или ослабить проверку осознанно.

Валидатор: `Orient = 255` ⇒ клеток нет (все 0); иначе `Orient <= 3`, `CellsF >= 1`, `CellsD >= 1`.

Асфальт — подряд идущие полосы одной ширины одной лентой с разметкой шейдера (`UV.y` = номер полосы слева направо, осевая — граница `backward|forward`). Высоты слоёв (м): резерв 0.01, газон/разделитель 0.03, бордюр 0.04, тротуар 0.045 (ниже тротуара пешеходной сети 0.06, чтобы её heatmap оставался сверху).
- **Уровни:** LOD0 — все элементы + разметка + стоп-линии; LOD1 — асфальт одной лентой от кромки до кромки и тротуар; дальняя лента — только асфальт (цвета «карты» вдали отвергнуты владельцем). Draw calls не меняются (меши чанков общие), растут только треугольники профильных сегментов.
- **Разметка:** разделители полос одного направления — пунктир (шейдер, `CUSTOM0.z = 1`, штрих 3 м / период 9 м), осевая — сплошная, оба — слабые линии VS3a (alpha 0.30/0.45). Стоп-линия — отдельный квад (`CUSTOM0.y = -2`, `Palette.StopLineAlpha`) в 1 м от торца ленты поперёк полос приходящего направления.
- **Площадка перекрёстка:** торцы лент — кромки проезжей части (`±CurbL/R`), угловая кривая — внешняя кромка правого поворота (ширина полосы из `Lane.Width`). Дальше наружу в каждом углу кольца бордюра, газона и тротуара (`AddCornerStrips`): ширины слоёв линейно меняются от сечения входного рукава к сечению выходного (улица 16 м ↔ артерия 24/32 м); к краю профиля `EdgeMm` слои доходят на торце рукава. Тупик и угол без профильных рукавов колец не получают. Направляющие внутри площадки считают границу полосы от внешней кромки своего направления (между направлениями может быть разделитель).

## 13. Решения при реализации RP5 (агент L32)
- **Код.** `City/LotBuilder.Grid.cs` (режим профилей, `GridMode`), `LotBuilder.cs` выбирает нарезку по `Net.Profiles != null`. Legacy-путь не тронут: хэши, голдены и корпус `w1`–`w10` прежние.
- **Начало сетки.** `World.WorldGridOriginX/Z` (м) округляется до мм и применяется в `LotBuilder`: клетка `(ix, iz)` покрывает `[Ox + ix·M, Ox + (ix+1)·M)`; `M = RoadProfileStore.ModuleMm`. Массив занятости выровнен по этим клеткам (бит 1 — участок, бит 2 — дорога по маске); клетка вне массива считается дорогой.
- **Маска (§4.2 п. 1).** 16 точек клетки `(2i+1)·M/8`, расстояние до оси сегмента и диск узла — `int64`; перпендикуляр сравнивается в `Int128` (`cross² ≤ Edge²·len²`), без `sqrt`. Диск узла: `max(NodeData.Radius, EdgeMm рукавов)`. «Дорога» ⇔ свободных точек `< ceil(75·16/100) = 12`. Порог 75 % — константа ядра `LotBuilder.CellMinSharePct`: ключа в сценарии нет (параметр в сейве потребует world_version).
- **Размеры участка** берутся из прежних `zoning.lot_frontage_m` / `lot_depth_m` (дефолт 40 м) делением на `module_m`: `F ≤ clamp(…, 2, 8)`, `D ≤ clamp(…, 2, 6)`; отдельных ключей `lot_*_cells` нет (новые столбцы PARM потребовали бы world_version 11).
- **Цепочка.** Шаг 4 м от `node_clear_m` до `L − node_clear_m`; точка `ось(s) + n·(EdgeMm + 4 м)`, всё в мм. Клетка-«дорога» → одна клетка наружу по оси участка, снова дорога — точка пропущена, участок закрывается. Ось глубины выбирается по нормали в первой точке участка (`|nx| > |nz|` → x, ничья → z). Клетка входит в участок, если её фасадный индекс равен последнему или соседний в том же направлении, `F` не превышена и разброс рядов (дальний ряд по каждому индексу) `≤ 1`. Передний ряд — самый дальний; ближние клетки (уступ) остаются газоном. На прямой сетке — `F = 5`, на 45° — `F = 2–3`.
- **Глубина** — подряд свободные ряды до `D_max`; `D < 2` → срез фасада с хвоста, затем с начала (минимально необходимый), иначе участок не создаётся. Центр в `city.landuse` (парк, вода) — участок не создаётся, как в legacy.
- **Состояние.** `Orient` — направление оси глубины от дороги наружу: 0 `+x`, 1 `−x`, 2 `+z`, 3 `−z`. `CellX/CellZ` — клетка переднего ряда с левого края, если смотреть вдоль оси глубины (левая рука `(dz, −dx)`); остальные клетки: `−i·left` по фасаду, `+k·dir` вглубь (`LotBuilder.CellBounds`). Столбцы `LOTS` 11–15 не менялись, схема сейва и `world_version` тоже. Валидатор: клеточный участок допустим только в мире с каталогом профилей, `CellsF/CellsD ≤ 16`, `|Cell| ≤ 10⁶`.
- **Хэш.** `CityHash.AddLots` пишет `CellX, CellZ, CellsF, CellsD, Orient` только при `Orient ≠ 255`.
- **Точка доступа и парковка.** `S0Mm/S1Mm` симметричны относительно проекции центра переднего ряда на ось сегмента (`ProjectMm`), поэтому `FrontPoint` парковки (середина `S0..S1` + нормаль на `FrontOffsetM`) и `CarLane/CarS/PedEdge` участка считаются прежним кодом и совпадают с точкой доступа §4.3. Полуширина — длина цепочки участка, ограниченная расстоянием до концов сегмента; участок с полушириной < 0,5 м не создаётся. Ёмкость обочины (`S1 − S0`) на диагонали честно меньше. `X, Z, Heading, Cell` — по прямоугольнику клеток (курс — против оси глубины).
- **`Lost` по клеткам.** `LotBuilder.OnRoadsChanged(w, c)`: пересчёт маски и занятости из живой сети, участки на сетке с хотя бы одной клеткой-дорогой → `Lost` (здание `Abandoned`, обочина снесена); возвращает число потерянных. `OnRoadBuilt` вызывает его сам; RP7 вызывает после `UpgradeRoad`/`BuildRoad` с профилем. Снос сегмента (`OnSegmentRemoved`) работает как раньше.
- **Дороги без профиля** (`Profile = -1`, построены инструментом до RP7) в режиме профилей режутся по тому же алгоритму, ширина края — прежняя формула `lanes·LaneWidth + тротуар`.
- **Масштаб.** `s1k-res` по профилям фикстуры: 4 555 участков против 1 781 в legacy; из них `D = 2` — около трети (внутренность квартала достаётся по правилу «укоротить до `D ≥ 2`»). Это следствие §4.2 п. 5, а не ошибка; число домохозяйств и мест — в отчёте RP8. Для таких сценариев `max_lots` приходится поднимать (тест берёт 12 000).
- **Сценарии `*-res`** файлами не переключены на профили (это пересоздаст голдены, корпус `w10-s1k-res*` и облачный baseline): тесты собирают профильный вариант подменой JSON (`ProfileSaveFixtures.Res`). Корпус: добавлен `w10-s1k-res-prof`.

## 14. Решения при реализации RP7 (агент L35)
- **`UpgradeRoad` в ядре не существовал** (T5 в бэклоге: диспетчер отвечал `NotSupported`), поэтому RP7 реализовал его в объёме, нужном профилям: `Api/CommandDispatcher.Tools.cs`, `Tools/ToolValidator.Profiles.cs`, `Network/NetworkBuilder.Reshape.cs` (три режима `ReshapeMode`, см. `player-tools.md` §4.5). Дренажа и `ShrinkLanes` нет: правка числа полос или типа требует пустого сегмента и его connector'ов (`Busy` иначе). Профиль при тех же полосах (ширины, смещения, `Mirrored`) правится на месте и занятости не требует.
- **Команды.** `BuildRoadCmd.Profile` (индекс + 1; 0 — как раньше) лежит на байтах `Cz` (payload полон, 56 Б): раскладка структуры явная, смещение 28. Когда T5 вернёт кривые, поле придётся переложить. `BuildRoadFlags.Mirrored` = 8. `UpgradeRoadCmd` 16 → 20 Б: `Profile` (0 — не менять), `Flags` бит1 `Mirrored`. Сборка по профилю: `AddProfileSegment` (отступы рукавов — `IncrementalSetback`). Полосы и тип в команде обязаны совпасть с профилем (`InvalidArgument`); `Mirrored` без профиля — `InvalidArgument`.
- **Инвариант RP2 сохранён.** Сегмент с профилем меняет полосы/тип только профилем (`UpgradeRoad` с `LanesAB/BA/Kind` без профиля на таком сегменте — `InvalidArgument`); сегмент без профиля (дорога игрока до RP7) можно как править полосами (legacy-ширина `NetworkOptions.LaneWidth`), так и перевести на профиль. Обратно «в без профиля» команды нет (у такой правки нет обратной, превью даёт `UndoUnavailable`).
- **Ось не меняется.** `SegmentPoints`, `Length` и отступы концов остаются: меняются смещения и ширины полос (`Lane.Width`), `Kind`, `Profile`, бит `Mirrored`, число полос. Отступы соседних рукавов не перестраиваются (ADR-0028), поэтому превью даёт `SetbackShort` (Warning, `Value` — нехватка в мм, объект — рукав), если рукав пересекается с новой дорогой, а его отступ меньше `h + corner_radius`.
- **`Overlap`** (только для дорог с профилем: `BuildRoad` и расширяющий `UpgradeRoad`). Ось с краем `EdgeMm` против оси каждого живого сегмента с его краем (`LotBuilder.FrontOffsetM`: профиль — `EdgeMm`, иначе прежняя формула): расстояние между ломаными меньше суммы краёв (с допуском 1 см) — `Overlap`. У общих узлов обе оси обрезаются на радиус диска `(En + Ee) / (2 sin(θ/2))` (θ — угол между рукавами), но не больше `2 (En + Ee)`: под прямым углом и при продолжении «прямо» стык допустим, острее ~29 градусов — отказ. Вплотную лежащие параллельные дороги (зазор 0) допустимы. Оценка геометрическая (float, без `sin`), не проверяет сами полосы по клеткам.
- **`Lost`.** `BuildRoad` с профилем: `OnRoadBuilt` уже зовёт `LotBuilder.OnRoadsChanged` (RP5). `UpgradeRoad` (кроме смены одной скорости): `OnRoadsChanged`, событие `ZoneLotsLost(seg, число)`, затем `RestoreDerived` (полосы и рёбра тротуара оставшихся участков). Превью: `ZoneLotsLost` Warning, `Value` — число участков; `LotBuilder.PreviewLost` считает по копии маски дороги (без дисков узлов), на тестовом сценарии равно факту.
- **Перенос полос (`Swap`).** Новый блок полос и точек; уцелевшие полосы переезжают по `Relocate.Apply` (номер в направлении сохраняется), исчезающие остаются до перестройки узлов, затем старый блок освобождается. До переноса: зоны теряют исчезающие полосы (`PruneZoneLanes`), машины и поездки с назначением на них получают новое (`RetargetVanishing`, детерминированно, без PRNG), маршруты через сегмент освобождаются (`SegmentClosure.AfterClosing`), `OutReserved` и список затронутых ворот сбрасываются (индексы полос меняются, а фаза 4 пересоберёт значения с нуля). Пробное планирование перестройки концов (`CheckRebuildEnds`, `SegmentData` правится на время пробы) даёт `NodeLimit`/`Capacity` до мутации; арены на реальный пик перестройки проверяются приближённо — отказ `CommitRebuild` после переноса оставил бы структуру согласованной, но команда отклонилась бы уже после мутации (на практике не воспроизводится).
- **Undo/redo и журнал.** Обратная `UpgradeRoad` — прежние полосы/профиль/зеркальность/скорость/тип (флаги `BusOnly`/`NoLaneChangeOut` убранных полос не восстанавливаются); обратная `RemoveRoad` (`BuildRoad(RestoreOf)`) несёт `Profile` и `Mirrored` сегмента. Журнал (`ReplayLog`) хранит `Command` 64 Б как есть — формат не менялся, `world_version` тоже.
- **Для клиента (RP10).** Команды строить только с `Profile`+`Mirrored` из каталога дескриптора; полосы и тип брать из профиля. Превью: `Overlap` как ошибка, `SetbackShort`/`ZoneLotsLost` как предупреждения; `Busy` на `UpgradeRoad` — повторять позже (дренажа нет), в UI показывать как «сегмент занят». `Mechanism` превью: 1 — замена блока полос, 0 — на месте. Снап к сетке остаётся клиентским.
