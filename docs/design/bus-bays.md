# Карманы автобусных остановок (`BusStopKind.Bay`)

Статус: спека, 2026-10-27 (агент L9); **BB1 и BB2 реализованы** (агент L12, ветки `local/bb1-bays`, `local/bb2-bays`, ADR-0029): въезд/выезд/fallback/горизонт, снапшот, JSON, хэш, сейв `world_version` 7,
валидатор; BB2: уступка (§2 п. 5, `LaneYieldS`), правки сети с автобусом в кармане, кузов в кармане параллелен полосе (снапшот). Отличия реализации от текста ниже (подробно — ADR-0029): маршрут к следующей остановке строится в тик выезда,
а не в конце стоянки (`BusNextStop` остаётся остановкой кармана, пока автобус не выехал); `Masks.Remove` на въезде не нужен (автобус остаётся живым и учтённым фазой 6);
производное `World.BayBus` (остановка → автобус) для вида снапшота. Дополняет ADR-0008
(«карман как обочина» — этап 1) и `city-generator.md` §6 (G6: геометрия кармана — спека транспорта). Нужен ADR-0029 (решение ниже).

## 1. Как сейчас
- **Данные есть, поведения нет.** `BusStopKind { Curb, Bay }` (`Api/Command.cs:54`), `BusStopData.Kind` (`Api/NetworkData.cs:141`), сейв
  `NET`-столбец 3 `StopKind`. Генератор при `stop_kind: mixed` даёт `Bay` артериям (`Gen/TransitGenerator.cs:306-310`, s1k/s10k — `mixed`).
  `LaneKind.BusBay` (`NetworkData.cs:29`) объявлен, но ни одной такой полосы сеть не строит (валидатор только допускает значение).
- **Где Bay игнорируется.** `Transit/BusStopRules.cs:7-9` прямо: Curb и Bay «моделируются одинаково». Прибытие
  (`Transit/BusStopPhase.cs:98-165`): на полосе остановки, ≤ 3 м, ≤ 0.5 м/с → `AtStop`, автобус остаётся в списке полосы. Фаза 5
  (`Rules/BehaviourPhase.cs:226-262`): у `AtStop` `Accel = 0`, а ведомые находят его лидером через `Ahead[i]` (`Rules/LeaderSearch.cs`
  `Find`/`FindFor`) и стоят, пока MOBIL не выпустит их в соседнюю полосу. Meso объезжает его тем же способом (`Rules/MesoBehaviour.cs:221`).
- **Следствие** (замер L8, ADR-0028): на s10k эпизоды ожидания ≥ 60 с за автобусом на крайней полосе артерии 25 → ~65 из 129, медиана
  доли 0.427 % при бюджете 0.15 %. Вторая причина (коробки 26 м на светофорах) — вне этой спеки.

## 2. Модель: два варианта
| | **A. Виртуальный карман** (рекомендую) | B. Полоса `BusBay` в сети |
|---|---|---|
| Суть | На прибытии автобус снимается со списка полосы (`Occupancy.Unlink`) и стоит «вне сети» у точки остановки; выезд — вставка в полосу по gap acceptance | Генератор строит короткую полосу-карман со съездом/въездом посреди сегмента; автобус едет по ней как по обычной полосе |
| Новое | 1 бит флага, 3 поля остановки, правило вставки, массив уступки | новый тип связи «полоса→полоса посреди сегмента», маршрутизация через карман, ворота на въезде (мини-перекрёсток), `Relocate`/инструменты/undo для `BusBay`, точки полос, сетевой хэш |
| Геометрия | Только читает её: длина полосы, горизонт ворот, ширина полосы для отрисовки | Сама геометрия: отступы, отгоны ≥ 25 м, зависит от отступов ADR-0028 |
| Стоимость | ~1.5 дня sonnet | ~5–8 дней, 4–5 подсистем |
| Риски | автобус вне списка полосы — правки сети и снапшот обязаны о нём знать (§3, §5) | меняет топологию: golden сети, Rust-пилот, сейвы сети, `NetworkHash` |
| Rust | только плоские поля и правило в фазе 8b | новый тип ребра в графе ядра |

Решение — **A**. Б даёт визуальный съезд и физическое вливание, но тот же эффект на очереди (ведомые не стоят за автобусом) A получает
за малую долю цены. Карман-полосу вернуть в roadmap, если клиенту понадобится видимый манёвр съезда.

Правила варианта A (только при `transit.bay_model = "virtual"`, только `Kind == Bay`, только `Lod.Mode == Off`; иначе — как Curb):
1. **Въезд.** Условие прибытия прежнее. Плюс: карман свободен (`BayUsed == 0`) и точка вне горизонта ворот — `Lane.Length − stop.S ≥ far`
   (та же `farDistance`, что в `GatePhase` и правиле выезда парковки, `parking.md` §6). Тогда: `Occupancy.Unlink(i)` (`Lane = −1`,
   `GhostLane` уже −1 по условию прибытия), `Flags |= AtStop | InBay`, `BayUsed = 1`, активные множества — как при деспауне (`Masks.Remove`).
   Посадка, стоянка и удержание — без изменений. Иначе (карман занят, горизонт, LOD) — обслуживание у обочины, как сейчас, `BayFallbacks++`.
2. **Ёмкость — 1 автобус.** Остановка принадлежит одному маршруту (`BusStopData.Route`), два автобуса сразу бывают только при пачке, а тогда
   второму хватает старого поведения. Слотов и порядка в кармане нет.
3. **Конец стоянки.** Маршрут к следующей остановке строится от `(stop.Lane, stop.S)` (сейчас `Advance` берёт `v.Lane[i]` — для `InBay`
   подставлять точку остановки). `Deferred` — повтор, как сейчас. Затем `BayExitFrom = Tick`, каждый тик — попытка выезда.
4. **Выезд (gap acceptance).** Вставка в `stop.Lane` на `s = stop.S` через `FindNeighbours` (ghost-члены учитываются), если:
   впереди `gap ≥ s0` автобуса; сзади (`b`) `gap_b ≥ s0_b + v_b·T_b` и `v_b² / (2·(gap_b − s0_b)) ≤ b_comf,b` (параметры IDM типа `b`, без новых
   констант); `b` не допущен воротами (`GateRules.IsGranted`, intersections.md §5.1); полоса не `Closed`/`Draining`. Вставка — как в
   `Spawner.TryPlace` (`InsertBetween`, `ChooseConnector`, `Masks`), скорость 0, флаги `AtStop | InBay` снимаются, `BayUsed = 0`.
5. **Уступка** (ПДД 18.3: в населённом пункте водители уступают автобусу, начинающему движение от обозначенной остановки).
   Если `Tick − BayExitFrom ≥ bay_yield_ticks`, у остановки поднимается `BayFlags.Yield`, и ведомые полосы видят виртуальную стену в
   `stop.S − L_bus` — только те, кто может остановиться перед ней с `b_comf` (кто не может — проезжает). Стена — ещё один кандидат в
   минимум ускорения фазы 5, рядом с `BusStopRules.ObstacleGap`; в клэмп I6 не входит (не безопасность, а вежливость). Выезд снимает `Yield`.

## 3. Данные
- `VehicleFlags.InBay = 64` (бит свободен). Инвариант: `InBay ⇒ IsBus ∧ AtStop ∧ Lane == −1 ∧ Ahead/Behind/GhostLane == −1`, целевая остановка
  (`BusNextStop`) — `Bay` с `BayUsed == 1`. Позиция стоянки — `S[i] = stop.S`. Без ссылок между объектами: связь автобус → остановка
  уже есть (`BusRoute`, `BusNextStop`), обратной ссылки нет — только счётчик.
- `BusStopData`: `ushort Reserved` → `byte BayUsed, byte BayFlags` (раскладка прежняя), новое поле `long BayExitFrom` (−1 — нет).
  Размер структуры растёт: хэш сети пишется полями (урок `lessons/sim-traffic.md` про `NodeData/SegmentData`), сдвига golden сети нет.
- Производное, не состояние: `float[] LaneYieldS` (по полосам, −1 — нет), пишет фаза 8b, читает фаза 5; после загрузки пересобирается
  из `BayFlags`. `SimCounters`: `BayEntries`, `BayFallbacks`, `BayYields`, `BayExitWaitTicksTotal`.
- **JSON** (`scenario-format.md`, `transit`): `bay_model: "virtual" | "lane"` (дефолт загрузчика — `virtual`, вопрос 1), `bay_yield_s`
  (дефолт 3, 0..60). `RoutesExplicit` — без изменений (`kind` уже есть).
- **Хэш.** Поля `BayUsed/BayFlags/BayExitFrom` и новые счётчики — только при `bay_model = virtual` и `BayStopCount > 0`; иначе хэш побитово
  прежний. `Flags` машин и `Lane = −1` уже в хэше.
- **Сейв.** `world_version` 7 (после 6 из ADR-0028): `PARM` `TransitBayModel`, `TransitBayYieldTicks`; столбцы `BDYN` `BayUsed`, `BayFlags`,
  `BayExitFrom`. `MigrationV7`: `bay_model = lane` — старые сейвы ведут себя как раньше, корпус `w1`–`w6` продолжается прежними хэшами.
  Валидатор: инвариант `InBay` выше, `BayUsed ∈ {0,1}` и равен числу автобусов `InBay` этой остановки, `BayExitFrom ≤ Tick`.

## 4. Горячий путь
- Въезд, выезд, уступка — в фазе 8b (`BusStopPhase`, последовательная, главный поток): меняют списки полос, `BusStops`, `LaneYieldS`.
  Параллельных записей в общие данные нет.
- Фаза 5 (воркеры, ADR-0017): одно чтение `LaneYieldS[lane]` на машину, стена — в собственный `Accel[i]`; автобус `InBay` (`Lane < 0`) —
  ранний выход, как сейчас (`BehaviourPhase.cs:212`). Фаза 6 пропускает его (`IntegratePhase.cs:232`), `StillTicks` не растёт.
- 0 B/тик: массивы — при создании мира (размер = ёмкость полос), без коллекций и замыканий. Детерминизм: обход 8b по индексу машины,
  как сейчас; решения выезда читают позиции конца фазы 7 текущего тика — одинаково при 1/2/3 потоках.
- Снапшот: у `InBay` `Lane = −1`, сейчас слот обнуляется (`SnapshotPhase.cs:227`) — автобус пропал бы. Позиция берётся из
  `(stop.Lane, stop.S)`, `LateralOffset = −ширина полосы сети` (из опций построителя, не константа в `game/`), флаг `AtStop`; вид ADR-0019 —
  по `stop.Lane`.
- Правки сети: снос остановки/сегмента, дренаж, `Relocate` при автобусе `InBay` — вставить обратно, если полоса жива и есть зазор, иначе
  `BusStopPhase.Remove` (пассажиры выходят, `DropAll`). Дренаж полосы не считает её пустой, пока на её остановке есть `InBay`.

## 5. Тесты и приёмка
Модульные (`tests/Sim.Core.Tests/Transit/BusTests.cs`, прямой сегмент 1 и 2 полосы):
1. Bay, 1 полоса: машина за автобусом проезжает `stop.S` во время стоянки, её `StillTicks` < 20 с; та же сцена с Curb — ждёт до отправления (как сейчас).
2. Выезд: поток с интервалом < `T_b` — автобус ждёт; после `bay_yield_s` ведомый тормозит у стены ≤ `b_comf`, автобус вставлен, перекрытий нет (`VerifyDerived`).
3. Занятый карман → второй автобус обслуживается в полосе (`BayFallbacks == 1`); точка в горизонте ворот → поведение Curb.
4. `bay_model = lane` и сценарии без Bay — хэш равен прежнему golden; миграция `w1`–`w6` — прежние хэши.
5. Детерминизм: s10k, хэш при 1/2/3 потоках; сейв на каждом тике вокруг въезда/выезда + 20 тиков (шаблон `WorldSaveMomentsTests`).
6. 0 B/тик с автобусами в кармане (`AllocationProbe`); фазз валидатора (`InBay` с `Lane ≥ 0`, `BayUsed` не сходится); снос остановки/сегмента с автобусом в кармане.

Golden: меняются эталоны хэша состояния s1k/s10k (`HotPathGoldenHashTests`, `AdaptiveGoldenHashTests`, `BasePackageGoldenTests`, корпус `w7-*`) —
отдельным коммитом. `NetworkStore.Hash()` и golden Rust-пилота не меняются (сеть та же; транзит в пилоте не портирован).

Приёмка (после мержа `local/corner-radius`, `bench --ticks 12000 --warmup-until-full`, сиды дефолт / 11 / 12, медиана `still_episodes_60s`):
s1k ≤ 0.25 %, s10k ≤ 0.15 %; в отчёте — до/после по эпизодам, `BayEntries/BayFallbacks/BayYields`, средний выезд из кармана,
`bus_headway_deviation_s`, поездки. tick p95 s1k ≤ 1 мс и 0 B — `bench-gate` в облаке. Если s10k всё ещё выше бюджета — остаток
относится к коробкам светофоров (задача интергрина), не к этой.

## 7. Вопросы владельцу
1. `bay_model = virtual` по умолчанию для новых сценариев? Это меняет golden s1k/s10k и облачный baseline. Рекомендую да.
2. Ёмкость кармана — 1 автобус, второй обслуживается в полосе. Достаточно?
3. Уступка через 3 с ожидания (по ПДД — сразу). Оставить 3 с или уступать сразу?
4. Видимый съезд в карман (вариант B) — нужен клиенту позже или снимаем с roadmap?

**Ответы владельца (2026-10-27):** 1 — да, `virtual` по умолчанию; 2 — ёмкость 1 автобус; 3 — уступка через 3 с (`bay_yield_s`);
4 — **реальный карман (вариант B) остаётся на будущее.** Поэтому в BB1 закладываем стык под него, не реализуя: значение `bay_model = "lane"`
в JSON и `LaneKind.BusBay` зарезервированы под настоящую полосу-карман (а не под «как Curb»; прежнее поведение — отдельное значение
`"curb"`, его же ставит `MigrationV7` старым сейвам); поля `BusStopData` (`BayUsed`, `BayFlags`, `BayExitFrom`) и правила въезда/выезда/уступки
не зависят от того, виртуальный карман или полоса, — вариант B потом меняет только «куда уходит автобус» (`Lane = −1` → полоса `BusBay`).
