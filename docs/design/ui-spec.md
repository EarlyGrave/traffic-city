## 1. Принципы (6)

1. **Мир — главный экран.** HUD занимает края, центр всегда свободен. На 1366×768 при масштабе 100% миру остаётся ≥ 80% высоты.
   Данные — в инфо-режиме F1, а не постоянными панелями поверх мира [Факт: `visual-style.md` §7].
2. **Сначала превью, потом клик.** Любая команда-инструмент показывает до применения:
   - призрак по `axis`;
   - цену;
   - вердикт;
   - предупреждения в точке проблемы.

   Ошибка не «случается» после клика. Её видно заранее, и у неё есть текст «почему» и «что сделать» (U1).
3. **Одно действие — один жест.** Протянуть дорогу, закрасить зону, провести линию — это drag, а не окна. Свойства инструмента лежат
   в строке опций над тулбаром, глубже двух уровней меню нет.
4. **Каждое сообщение привязано к месту.** Уведомление строится из события ядра и несёт координату и кнопку «Показать». Нет событий
   «настроения» без данных (U2).
5. **UI — тонкий слой над ядром.** Клиент читает только снапшоты и `Get*`, а пишет только `Enqueue(Command)` и `Preview`. Числа на экране —
   те же, что в ядре, без собственной логики подсчёта (U3) [Факт: `CLAUDE.md` правило 5].
6. **Дёшево и читаемо на ноутбуке.**
   - 0 аллокаций в кадре;
   - тексты обновляются с частотой 4 Гц, графики — 1 Гц;
   - один шрифт, иконки атласом, без размытия фона;
   - масштаб UI и палитра для дальтоников — в MVP (U4).

## 2. Информационная архитектура: режимы

Режимы взаимоисключающие, кроме камеры и времени: они работают всегда. `Esc` всегда возвращает на уровень вверх.

```
                 ┌──────────── Обзор (по умолчанию) ─────────────┐
                 │ камера, время, клик = Инспектор                │
                 └──┬───────────┬───────────┬───────────┬────────┘
            B/R/Z…  │      F1   │   клик    │    F5/F10 │
          ┌─────────▼──┐ ┌──────▼─────┐ ┌───▼──────┐ ┌──▼──────────────┐
          │ Стройка    │ │ Инфо       │ │ Инспектор│ │ Экраны (модально)│
          │ (инструмент│ │ (слой 1..4,│ │ (выбран  │ │ Бюджет F5,       │
          │  активен)  │ │  легенда)  │ │  объект) │ │ Настройки F10/Esc│
          └────────────┘ └────────────┘ └──────────┘ └──────────────────┘
```

| Режим | Вход | Выход | Что видно | Совместимость |
|---|---|---|---|---|
| Обзор | старт, `Esc` | — | верхняя полоса, тулбар (свёрнутые категории), время | — |
| Стройка | клавиша категории или клик по тулбару | `Esc` (сначала отменяет протяжку, затем выходит из инструмента) | строка опций инструмента, призрак, курсор-метка цены | **с инфо-режимом можно** [Рек.]: стройка поверх слоя «Трафик» — частый сценарий |
| Инфо | `F1` | `F1`/`Esc` | беж + слой, легенда слоя, переключатель 1–4 | со стройкой и инспектором |
| Инспектор | ЛКМ по объекту в Обзоре или Инфо | `Esc`, клик в пустоту, × | правая панель объекта | инфо-режим не сбрасывается |
| Бюджет | `F5` или кнопка в верхней полосе | `F5`/`Esc` | модальное полноэкранное окно, пауза **не** включается [Рек.] | — |
| Настройки | `F10` или `Esc` из Обзора | `Esc` | модальное окно, **пауза включается** [Рек.] | — |

**Почему `Esc` в Обзоре открывает меню** — конвенция жанра. Сейчас `Esc` снимает выделение [Факт: `SimHost.cs`]. Порядок
сохраняется: сначала `Esc` отменяет протяжку, потом выходит из инструмента, потом закрывает инспектор, и только последним открывает меню.

## 5. Потоки инструментов

Общая схема для всех инструментов:

```
выбор инструмента → наведение (Preview каждый кадр движения, ≤ 1 вызов на кадр) → нажатие/протяжка → отпускание
  → Verdict == None? ─да→ (Warning с потерей доступа? → P13 подтверждение) → Enqueue → ждать CommandApplied/Rejected по Tag
                     └нет→ метка красная, клик игнорируется, звук «нельзя» (Позже)
```

**Правила:**
- `Preview` вызывается **между `Step`** в том же потоке [Факт: `player-tools.md` §7.1]. Не чаще одного раза на кадр и только при смене
  входа: курсор сдвинулся > 0.5 м или сменилась опция.
- Действие игрока — **группа** для `UndoStack`: протяжка цепочки = одна группа [Факт: §8.3].
- Отказ при применении (`CommandRejected` после зелёного превью, например из-за гонки с дренажом) показывается тостом в точке.

### 5.1 Дороги: строительство, апгрейд, снос

**Строительство (`BuildRoad`, профиль RP7)**
1. `R` или клик «Дороги». Строка опций показывает:
   - профиль — последний использованный, `street_2` по умолчанию;
   - режим — Прямая;
   - снап — вкл.;
   - сетку — выкл.
2. Профиль выбирается:
   - выпадающим списком с миниатюрой сечения: полосы, тротуары, ширина в м;
   - или клавишами `[` и `]` (листают по кругу).

   Каталог берётся из ядра (`RoadProfileStore` через `NetworkView`), а не из констант.
3. **Наведение.** Курсор «прилипает» в порядке приоритета:
   1. существующий узел (радиус 6 м);
   2. ось существующего сегмента (разрез, `SnapKind = 2`);
   3. мировая сетка 8 м, если снап включён;
   4. свободная точка.

   Тип привязки показан иконкой у курсора (● узел, ✚ разрез, # сетка). Всё это **клиент** [Факт: `road-profiles.md` §6].
4. **ЛКМ** фиксирует точку A. Дальше курсор тянет призрак:
   - `Preview` возвращает `axis`, `LengthM`, `Cost`, `Verdict` и issues;
   - призрак — лента ширины профиля: белая при OK, жёлтая с предупреждением, красная с ошибкой;
   - проблемное место (`PreviewIssue.X/Z`) отмечено маркером.
5. **Режим «Кривая»** (`Tab` переключает): A → контрольная точка → B. **Зависимость: T5** (Безье в ядре). До T5 опция серая с тултипом
   «кривые — скоро».
6. **ЛКМ** в точке B ставит `BuildRoad`. Протяжка продолжается от B (цепочка) до `ПКМ`-клика без движения или до `Esc` [Владелец].
   Сейчас **ПКМ-drag = панорама** [Факт: `RtsCamera.cs`], поэтому «ПКМ отменяет» допустимо только как клик без сдвига (порог 4 px).
7. **Модификаторы:**
   - `Shift` удерживать — снап выключен временно (как C/Shift в TF2 [S28]);
   - `Ctrl` — фиксация угла с шагом 15°;
   - `M` — Mirror для асимметричного профиля.
8. **Цепочка = одна группа undo.** Превью цепочки — сумма одиночных [Факт: `player-tools.md` §16 в. 6].

**Апгрейд (`UpgradeRoad`, Replace-паттерн CS2, U7)**
1. В режиме «Дороги» выберите профиль и наведите на **существующий** сегмент с зажатым `Alt` или включите режим «Заменить» (`U`).
2. Сегмент подсветится, `Preview(UpgradeRoad)` покажет:
   - разницу цены;
   - механизм (на месте, перенос или дренаж — иконкой);
   - `SetbackShort` или `ZoneLotsLost`, если они есть.
3. ЛКМ применяет к одному сегменту. Drag по нескольким сегментам ставит пачку с одной группой undo.
4. Дренаж при уменьшении полос показывается индикатором P5.

**Снос (`RemoveRoad`)**
1. `X`, или «Снос», или `Ctrl+ЛКМ` внутри «Дорог» [Рек.].
2. Наведение на сегмент показывает:
   - красную ленту;
   - возврат денег (`Cost < 0`);
   - `DrainVehicles` («уедут 23 машины»);
   - `ZonesLosingAccess` и `BusStopsLost`.
3. Drag выделяет несколько сегментов, применение — одной группой.
4. `ZoneAccessLost`/`StopAccessLost` → подтверждение P13. Ловушка `CreatesTrap` → запрет [Факт: в. 3 `player-tools.md`].
5. После применения сегмент в `Closing`:
   - вдали — штриховка;
   - вблизи — тон (долг VS3a);
   - над ним P5. `ToolOpFinished` убирает индикатор.

**Переключатели снапа и сетки** [Факт: `road-profiles.md` §9]:
- снап — `G`;
- показ сетки — `Shift+G`.

Оба переключателя продублированы кнопками в P3 и сохраняются в настройках клиента.

### 5.2 Зонирование кистью (`PaintZone`)
1. `Z` → строка опций:
   - вид зоны — по каталогу, цвет как в слое «Зоны»;
   - плотность;
   - режим — Прямоугольник (MVP) или Кисть вдоль дороги (Позже);
   - «Стереть» (`ZoneKind 0`).
2. При входе в инструмент **автоматически** включается слой «Зоны» инфо-режима [Рек.]. При выходе он возвращается в прежнее состояние.
3. Drag рисует прямоугольник. Клетки 8 × 8 подсвечиваются по сетке участков:
   - зелёные — будут зонированы;
   - серые — недоступны (дорога, вода, нет доступа);
   - оранжевые — здание другого вида уйдёт в `Abandoned`.

   **Превью для `PaintZone` в ядре не описано** (`player-tools.md` §7 — только дорожные команды). Нужна задача ядра (см. §13, UI-C1)
   или клиентская оценка по `GetLots` [Владелец].
4. Отпускание → `PaintZone` → событие и перерисовка `LotChunks` по `LotsVersion`.
5. Ограничение `zoning.max_paint_m2`: при превышении прямоугольник становится красным с подписью «не больше N м²».

### 5.3 Редактор автобусной линии (после T9)
1. `T` → «Новая линия». Курсор ставит остановки кликами по сегментам.
   - Остановка привязывается к полосе и стороне (`InsertBusStop`: сегмент + направление + `LaneNo` + `S`).
   - Сторона выбирается по положению курсора относительно оси.
2. После каждой остановки рисуется путь от предыдущей по текущему графу — данные из `RouteView` или превью ядра.
   Если пути нет — `Unreachable`, нога красная.
3. ЛКМ по первой остановке замыкает петлю. Двойной клик или `Enter` завершает открытую линию, тогда ставятся `CreateBusRoute` + `AppendBusStop`×k
   одной группой.
4. Правка существующей линии из инспектора линии (§7.6):
   - перетащить остановку — это `RemoveBusStop` + `InsertBusStop`;
   - вставить остановку кликом по ноге;
   - удалить — ПКМ-клик по остановке.
5. Параметры (`SetBusRouteParams`): интервал, тип ТС — ползунок в инспекторе линии.
6. Цвет линии — автоматический из палитры, различимой для дальтоников (§11). Ручной выбор — Позже.

### 5.4 Редактор светофора и узла
1. `J` («Узлы») → клик по узлу, или клик по узлу в Обзоре → инспектор узла (§7.4) с кнопкой «Править».
2. Режим управления узлом (`SetNodeControl`): без светофора, главная/второстепенная, светофор фиксированный, светофор адаптивный.
3. План светофора (`SetSignalPlan`):
   - **MVP** — 3 пресета, как в текущем `NodePanel`, и длительность цикла ползунком;
   - **Позже** — редактор фаз в виде таблицы «фаза × рукав → стрелки» с длительностями.
4. Рукава (`SetArmControl`): клик по иконке рукава в мире циклически меняет приоритет, «уступи» и «стоп».
5. Запрет манёвра (`SetTurnBan`): стрелки над рукавами в стиле TM:PE [S35], клик по стрелке выключает манёвр. Иконки видны
   только в инструменте, а постоянный оверлей — опция (Позже).
6. Полосы (`SetLaneFlags`: `BusOnly`, `NoLaneChangeOut`) — из инспектора сегмента, переключателем на полосе.
7. Превью перестройки узла: `SignalPlanReset`, `NodeRebuildDelayed` → предупреждение в метке.

### 5.5 Undo / redo
- **Клавиши:**
  - `Ctrl+Z` — undo;
  - `Ctrl+Y` или `Ctrl+Shift+Z` — redo;
  - кнопки ↶ ↷ в тулбаре с тултипом «Отменить: снос улицы (3 сегмента)».
- Глубина 100 групп [Факт: §8.3]. Кнопка серая, если стек пуст.
- Undo **логическое** — уехавшие машины не вернутся [Факт]. Первый undo сноса показывает тост «Дорога восстановлена; машины,
  которые уехали, не вернутся» (один раз за сессию) [Рек.].
- Отказ обратной команды (`CommandRejected`: `Busy`, `Capacity`, `InsufficientFunds`) → тост с причиной; запись снимается [Факт].
- Возврат денег за undo — по `city-economy.md` §8.3 (`UndoCredits`). В тултипе ↶ стоит сумма возврата.

## 6. Обратная связь

### 6.1 Превью
- Призрак — лента профиля той же геометрии, что `axis`. Цвета:
  - OK — белый с контуром;
  - Warning — жёлтый;
  - Error — красный.
- Цвет всегда дублируется иконкой и текстом (доступность).
- Мир под инструментом **не** заливается сплошным цветом (U5). Подсвечиваются только затронутые объекты:
  - зоны без доступа — штриховкой;
  - остановки — значком;
  - сегменты, которые придётся дренировать, — пунктиром.
- Холодное превью (первое после смены сети, строится кэш Tarjan) может занять > 1 кадра. Тогда метка показывает «…», а клик
  разрешён: валидатор применения тот же [Факт: §7.1].

### 6.2 Цена
- Метка у курсора: «₽ 9 200» — трата; «+₽ 3 100» — возврат, зелёным.
- Без экономики (`city_budget` выкл.) цена **не показывается** [Рек.].
- `InsufficientFunds` → метка красная: «не хватает ₽ 2 400».

### 6.3 Ошибки — таблица текстов (заглушки, локализация — в ресурсе)

| Код | Текст в метке | Подсказка «что сделать» |
|---|---|---|
| `TooShort` | Слишком короткий участок | Тяните дальше: от 20 м |
| `TooSharp` | Слишком острый угол | Разведите рукава или увеличьте радиус |
| `Overlap` | Пересекает другую дорогу | Ведите до узла или через перекрёсток |
| `NodeLimit` | Слишком много рукавов у узла | Не больше 6 |
| `Busy` | Дорога ещё перестраивается | Дождитесь окончания (полоса над дорогой) |
| `CreatesTrap` | Тупик для одностороннего движения | Добавьте выезд или сделайте двустороннюю |
| `InsufficientFunds` | Не хватает денег | Нужно ещё ₽ N |
| `Unreachable` | Автобус не доедет до остановки | Проверьте связь дорог |
| `OutOfBounds` | За границей карты | — |
| `ZoneRule` | Здесь нельзя эту зону | — |
| `Capacity` | Достигнут предел объектов | — |
| `InvalidHandle` | Объект уже удалён | — (молча обновить выделение) |
| `NotSupported` | Пока недоступно | — |

Предупреждения (`IssueCode` ≥ 100): `DeadEnd`, `ZoneAccessLost`, `StopAccessLost`, `PedAccessLost`, `DrainNeeded` («уедут N машин»),
`RoutesAffected`, `BusRouteShortened`, `SignalPlanReset`, `NodeRebuildDelayed`, `NearCapacity`, `UndoUnavailable`, `ZoneLotsLost`,
`SetbackShort`. Метка показывает не больше 2 по тяжести, остальное — «ещё N» с раскрытием по `Alt`.

### 6.4 Уведомления

**Правила:**
- Источник — **только** `SimEvent` или пороговые метрики ядра.
- Каждое уведомление несёт: тип, координату или объект, время, кнопку «Показать», которая подлетает камерой и открывает инспектор.
- **Агрегация:** одинаковые события за 10 с игрового времени сливаются в одно с «×N».
- **Порог:** не больше 1 тоста в 3 с; остальное попадает в список 🔔.

| Событие | Важность | Текст (заглушка) | MVP |
|---|---|---|---|
| `DrainStalled` | ⚠ | Дорога не пустеет: машины не могут уехать | да |
| `GridlockOn`/`Off` | ⚠ / ✓ | Пробка-клин на перекрёстке / рассосалась | да |
| `VehicleStuck` (агрегат > N) | ⚠ | Застряли N машин | да |
| `ZoneAccessLost`, `ZoneLotsLost` | ⚠ | Район потерял доступ к дорогам / N участков потеряно | да |
| `CommandRejected` (после зелёного превью) | ✗ | Не удалось: <причина> | да |
| `CapacityExhausted`, `EventsOverflow` | ✗ | Достигнут предел симуляции | да (это и отладка) |
| Бюджет: `Insolvent`, лимит долга (события E1) | ⚠ | Казна пуста / долг у лимита | после E2 |
| Парковка: переполнение (K-волна) | ⚠ | Не хватает парковки у … | после K7 |

Звук и «настроение жителей» (Chirper) — **нет** (U2).

## 11. Доступность и масштаб
- **Масштаб UI** (MVP): `content_scale_mode = canvas_items`.
  - Базовый множитель — `высота окна / 768`, ограничен диапазоном 1.0–1.5.
  - Поверх — пользовательский множитель 75–150% с шагом 5%.
  - Предпросмотр в настройках, применение сразу [Рек.].
  - Вариант «одинаковый размер в физических пикселях» — [Владелец].
- **Кегль:** основной 15 px, вторичный 13 px, заголовки 18 px (логические). Минимальный итоговый на экране — 11 физических px при 75%.
- **Контраст:** текст ≥ 4.5:1 к фону панели в обоих режимах (обычный вид и беж инфо-режима). Проверка — скриншоты `godot-shot.sh` + ручной расчёт.
- **Палитра для дальтоников** (MVP): переключатель «Обычная / Дейтеранопия-Протанопия / Тританопия» меняет `HeatPalette`, цвета
  зон, цвета линий и семантику ошибки и предупреждения. Семантика **никогда** не передаётся только цветом: всегда есть иконка или текст.
- **Непрозрачность панелей:** 70–100% (по умолчанию 95%), без размытия фона.
- **Ремап клавиш** — Позже (Godot `InputMap` + сохранение в `user://`). Для MVP клавиши задаются через `InputMap` действиями, а не через
  `Key.*` в коде, чтобы ремап потом был дешёвым [Рек.].
- **Тачпад** [Владелец]: опция «Режим тачпада» — двухпальцевый скролл = панорама, `Alt+скролл` = зум, ПКМ-клик-отмена без drag.
- **Геймпад** — не цель [Рек.]; для Steam Deck — Позже.

## 12. Заметки реализации (Godot 4.7, C#)
- **Дерево:** `CanvasLayer` «UI» (layer 10) → `Control` root, full rect, `mouse_filter = Pass`. Дети:
  - `TopBar` (`HBoxContainer`);
  - `ToolOptions`;
  - `Toolbar`;
  - `Inspector` (`PanelContainer`, справа);
  - `Toasts` (`VBoxContainer`);
  - `Legend`;
  - `Modal` (бюджет, настройки).

  Метка у курсора и маркеры проблем — отдельный `Control`, который позиционируется через `Camera3D.UnprojectPosition`.
- **Тема:** один `Theme` ресурс (`game/ui/theme.tres`). Все цвета UI лежат в `Palette.cs` (как мир) или в `UiPalette.cs` рядом, хексы вне
  них запрещены (тот же grep-критерий, что в VS1). `StyleBoxFlat` с контуром 1 px, скругление 4 px, без теней. Один шрифт (variable
  или 2 начертания), иконки — один атлас (`AtlasTexture`).
- **Ввод:**
  - UI обрабатывает `_GuiInput`, мир — `_UnhandledInput` [Факт: `SimHost`];
  - клики по панелям не проходят в мир;
  - инструменты — отдельные классы `ITool` (`OnHover/OnPress/OnRelease/OnCancel`) в `game/Scripts/Tools/` (каталог задачи T13),
    активный инструмент один.
- **Данные:**
  - UI читает `Simulation` только между `Step`, через `TryGet*Info`, `NetworkView`, `RenderView`, `ToolOps`, `GetCityBudget`;
  - пишет только `Enqueue`;
  - `Preview` — с переиспользуемыми `Span`-буферами (`PreviewIssue[16]`, `Vec2[256]`), выделенными один раз;
  - события — из буфера событий кадра; роутер раздаёт их уведомлениям, `UndoStack`, индикаторам.
- **Цена (цели, подтвердить замером `RenderStats`/`Performance`):**
  - 0 управляемых аллокаций в кадре в стационаре;
  - CPU UI ≤ 0.5 мс;
  - ≤ 80 draw call с открытым инспектором и легендой.

  Тексты обновляются 4 Гц, через `StringBuilder` → `Label.Text` только при изменении. Без `RichTextLabel` с BBCode в часто
  обновляемых местах. Узлы строк списков — пул, без `QueueFree` и создания на лету. Скрытое — `Visible = false`.
- **Compatibility** (облако, llvmpipe) — UI должен работать и там. Скриншоты UI для ревью — `scripts/godot-shot.sh` с новым аргументом
  `--ui-state build|info|inspect` (задача UI1). **Godot не запускается агентами-документалистами.** Запуск только в задачах реализации.
- **Моды:** UI не экспортирует узлы модам, моды работают с данными (`modding.md`). Иконки и подписи новых профилей и зданий — из
  каталогов JSON (поле `ui_name`/`icon`, Позже).

### Ядро: UI-C1 — превью `PaintZone` (агент 178, ночь N1) [Факт: слит в ветке `claude/cool-newton-91p1tr-n1`]
- `Simulation.Preview(Command.MakePaintZone(..), out PreviewResult r, issues)`: `r.Verdict` — тот же `Zoning.Check`, что в применении (`InvalidArgument`, `ZoneRule` для площади больше `max_paint_m2`, `NotSupported` без режима жителей); `r.AX/AZ/BX/BZ` — упорядоченный прямоугольник; `r.Cost = 0`.
- Счётчики: `ZoneLots` (участки под прямоугольником, не `Lost`), `ZoneLotsChanged` (из них реально меняются), `ZoneCells` (клетки 8 м этих участков), `ZoneAbandon` (здания другого вида → `Abandoned`), `ZoneUnavailableCells` (клетки прямоугольника без участка: дорога, вода, парк, нет доступа к дороге — отдельных причин ядро не различает, клиент при необходимости красит серым всё, где нет участка). Считаются тем же обходом (`Zoning.Scan`), что и применение.
- Предупреждения: `IssueCode.ZoneBuildingsAbandoned` (114, `Value` = число зданий; оранжевая подсветка), `ZoneNothingToPaint` (115, Info), `UndoUnavailable` (111).
- Подсветка по участкам: `Simulation.PreviewPaintMarks(in PaintZoneCmd, Span<PaintLotMark>)` → число участков; `PaintLotMark { Lot, State (PaintLotMarkState: Unchanged/Zoned/ZonedAbandon), X, Z }`, индекс `Lot` — в `GetLots`.
- Отступление от формулировки «клетки»: ядро зонирует по участкам, а не по клеткам сетки; клетки — оценка по `CellsF × CellsD` участков (legacy-участок = 1).
