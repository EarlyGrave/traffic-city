## 2. Модель
### 2.1 Режим `city.zones`
Секция сценария `city.zones` (требует `demand.model = residents`; `city_budget`, `lifecycle`, `services` — не требует). Без секции —
прежние R/C/I × 2, прежние типы, прежние деньги товаров (`PayGoods`): `s1k-res`, `s10k-res`, `*-res-bl`, `*-res-sr`, s1k/s10k, Rust
побитово прежние. С секцией — виды 1–3, 6–8, варианты §2.3, заказы §2.6, `PayGoods`/`PickSupplier` и `export_per_shift` у I выключены.
Включается в игровых сценариях (`game-city`, `yuryev-*`, `ys0-*`, новая игра) и в новых `s1k-res-fr`, `s10k-res-fr`.

### 2.2 Вид × плотность — сетка кода, параметры — данные
- **`LotZone`** (номера закреплены): `Residential 1` жильё · `Commercial 2` торговля · `Industrial 3` промышленность · `Office 6` офисы ·
  `Warehouse 7` склады · `Mixed 8` смешанная (`Parking 4`, `Service 5` — не зоны). Плотность: жильё 0–2, остальные 0–1. Итого 13 ячеек;
  ячейка сетки = **вариант**. Новый вариант — код (новое поведение), параметры варианта — данные (правило `modding.md` §3).
- **Запись варианта** — новый контент пакета `zones.json` (`content.zones`, `format_version` 1, `ModLimits.MaxZoneVariants` 16): `id`
  (`<пакет>:zone/<имя>`), `rev`, `kind`, `density`, `milestone`, `cut_class`, `shifts` (≤ 3 × `{start_slot, slots}`), `spread_slots`,
  `car_own_pct` (жильё), `road_min` (`street|arterial`), `job_weight`, `noise`, `dirt` (0–10), `freight` (§2.6.1). Пакет с той же
  `(kind, density)` заменяет запись (по `rev`, как типы). Ядро — POD `ZoneVariantDesc` (без массивов: `Shift0..2`, как `CityOutsideDesc`),
  таблица `ZoneVariants[13]` по индексу `VariantOf(kind, density)`; строк в ядре нет.
- **Тип здания** (`buildings.json`) получает необязательные поля: `zone` (id варианта; без него — строка прежнего набора R/C/I),
  `role` (`main|podium`, только у `mixed`), `floors`, `unit_m2` (LP §2.7 — FR вводит, LP начинает читать), BL-поля `decay_bp_day`,
  `ceil_drop_bp_day`. Новые виды: `kind` `office|warehouse|mixed` у записи варианта; у типа здания `kind` — поведение записи:
  `residential|commercial|industrial|office|warehouse`. `Types.Find(зона, плотность, вариант)` в режиме берёт только строки с `zone`,
  вне режима — только без `zone`: базовый пакет может нести оба набора, эталоны старых сценариев не сдвигаются.
- **`PaintZone`** — payload прежний: `ZoneKind` 0–3, 6–8, `Density` ≤ максимума вида; вне режима — прежняя проверка. Замок: `Feature.Zoning`
  (как сейчас) **и** `milestone` варианта (`Locked`, как `milestone` уровней SR — новых `Feature` под варианты нет). Здание другого вида
  уходит в `Abandoned` (как сейчас); для `Mixed` «свой вид» — пара `main`(R) + `podium`(C) этого варианта.
- **Палитра** (данные клиента по `id` записи): 6 групп × варианты, замок до вехи; названия и иконки — ресурсы клиента.

### 2.4 Смешанная зона — два здания на одном участке (вопрос §9.4, рекомендация А)
- `Growth.Place` на участке `Mixed` создаёт **пару**: `main` — тип `role: main` (поведение R) и `podium` — тип `role: podium` (поведение C).
  Новое поле здания `Twin` (int, индекс напарника или −1) у обоих; `Lot.Building` = `main`. Участок `LotOf` у обоих один.
- Всё прочее — прежним кодом: рынок жилья видит `main` как R, выбор цели и покупки видят `podium` как C, фирма — счёт `podium`, BL износ —
  у каждого свой (высотка над магазином ветшает своим темпом), заброшка фирмы снизу не выселяет жильцов.
- Пара разделяется только сносом: `Abandon`/`DemolishBuilding`/перекраска/`Lost` участка — оба (`main` первым). `RemoveAbandoned` удаляет
  пару, когда оба удаляемы. Повторное заселение BL §2.3 — каждый отдельно.
- **Пешие покупки:** в `Choice.ChooseDestination` у жителя `main` с активным `podium` кандидат 0 — свой `podium` (остальные K−1 — выборкой
  как сейчас). Способ — logit §6.5 `zoning-demand.md`: расстояние 0 → `walk`. Так «часть поездок становится пешей» без новых правил.
- Клиент рисует одну модель на участок: `podium` несёт бит `Podium` в `BuildingRenderData.R1` (§6).

### 2.5 Рисунок поездок по видам
- **Смены.** У варианта до 3 смен `{start_slot, slots}`; работник получает смену `seq % число_смен` (без нового состояния). Желаемое
  прибытие `start + (seq % (2·spread + 1)) − spread`; при `spread_slots` 3 — ровно прежняя формула. Третья (ночная) смена не v1: тур не
  переходит через полночь (`DayPlan.cs:100`), смены выбраны так, чтобы кончаться ≤ 22:00.
- **Открытие торговли** = смена: дневной лимит визитов `ShopCapacity · slots/12` (как сейчас).
- **Машина у семьи** — порог `car_own_pct` варианта дома (тот же бросок PRNG в `CityInit.cs:181` и при въезде); вне режима — `car_ownership`.
- **Офисы** — фирма без товаров: доход `office_income_per_shift` (70) от `External` за отработанную смену (поток `Export`, как I сейчас).
- **Деловой центр и башня:** транспортного требования при постройке нет — пробка без автобуса и есть их задача (правило владельца).
  **Логистика** строится только на участке, чей сегмент `RoadKind.Arterial` (`road_min`), и, если есть `outside`, в одной `RoadComp` с подключением.

### 2.6 Грузы: один товар, склад — счётчик, заказы целыми единицами
#### 2.6.1 Роли
Одна единица товара (**ед.**) = товар на `visits_per_unit` (5) покупок. Состояние здания: `Stock` (ед.), `InTransit` (ед. в пути к нему),
`Carry` (остаток продаж меньше единицы).

| Роль варианта | Кто | Потребление/выпуск | Откуда берёт (по порядку цены, §2.6.3) | Машина приёма | Окно приёма |
|---|---|---|---|---|---|
| `shop` | торговля, низ смешанной | `−⌊(визиты вчера + Carry) / 5⌋` | простой склад, лёгкая, логистика, тяжёлая (только ТЦ), внешний мир | `inbound` варианта | §2.3 |
| `store` | склады | транзит | лёгкая и тяжёлая промышленность, логистика (для простого), внешний мир | `inbound` | §2.3 |

Машина поездки — `inbound` получателя; вывоз на экспорт — `outbound` производителя (лёгкая — фургон, тяжёлая — фура). Классы — VC
(`van`, `truck`); тип — запись `freight.vehicle_van/truck` секции (дефолт `base:vehicle/van`, `base:vehicle/truck`), валидатор: класс совпадает.

#### 2.6.2 Суточный расчёт (стадия «здания» дневного прохода, по возрастанию индекса, в `Economy.BuildingDay`)
1. **Выпуск и расход** по вчерашним `VisitsDay` (визиты C, смены I — уже считаются). Нехватка — `supply_pct` §2.6.6.
2. **Заказ получателя** (`shop`, `store`, сырьё `make_raw`): `use = max(вчерашний расход, cap_use / 4)`, `cap_use` — по ёмкости; если
   `Stock + InTransit < reorder_days · use` (1), заказ `need = target_days · use − Stock − InTransit` (2 дня), округлённый **вверх до
   целых загрузок** (фургон 10 ед., фура 40 ед.); склад: порог 50 % `stock_cap`, заказ до `stock_cap`.
3. **Выбор поставщика** (§2.6.3) резервирует товар сразу: `Stock_src −= units`, `InTransit_dst += units`. Не хватает у ближайшего — следующий
   по цене; частичной отгрузки нет (заказ — целые загрузки, поставщик отдаёт загрузки, сколько есть, остаток — следующему).
4. **Вывоз** (`make`, `make_raw`): `Stock` сверх `stock_cap` производителя (лёгкая 120, тяжёлая 400 ед.) уходит на экспорт целыми
   загрузками `outbound` к ближайшему подключению.
5. **Заказы → поездки:** заказ = `Order {Src, Dst, Gen×2, Units, VehType, Kind (Supply|Export|Raw), DepartTick, Vehicle+Gen, State}` (40 Б),
   одна загрузка — один заказ. `DepartTick` = слот окна `win0 + H(dst, day, k) % (win1 − win0)` (хэш без состояния, как броски SR); если
   слот уже прошёл — следующий слот. Заказ кладётся в корзину своего слота (288 голов списков + `Next`).

#### 2.6.3 Выбор поставщика — ближайший по времени с поправкой цены
- Индекс по ячейкам `CityGrid` (≈ 1 км): `CellStock[роль-источник][cell]` — сумма `Stock` поставщиков, правится на каждом изменении `Stock`
  (целые сложения); список зданий-поставщиков ячейки — по образцу `RebuildCellIndex` (`Skims.cs:298`), пересборка при `Complete`/`Abandon`.
- Цена кандидата `C = Skims.Get(cellSrc, cellDst, Car, period окна) + penalty_роли`; внешний мир: `ским до подключения k + import_penalty_s`
  (1 800 с) — местный поставщик всегда предпочтительнее при прочих равных. Перебор ячеек — в радиусе `supplier_radius_cells` (16) от
  получателя; ским пуст — манхэттен ×1.3 / 8 м/с (формула `TravelSlots`). В ячейке — здание с наибольшим `Stock` (равенство — меньший индекс).
- Грузовые ноги **не пишут** наблюдения в скимы (скимы — легковые, VC §2.3); отдельных грузовых скимов в v1 нет.

#### 2.6.4 Диспетчер и машина (переиспользует BL/SR)
- **Выпуск** (фаза 9r, после диспетчера SR): на смене слота корзина слота переносится в кольцо `Ready`; из него до `max_freight_dispatch_per_tick`
  (8) заказов в тик → `PendingTrip` от участка источника (`Lots.Capacity + k` для подключения) к участку получателя, тип `VehType`,
  `ResidentRef = −(FreightBase + order + 1)`. Связь машины: `VehicleStore.Resident = −2 − (CrewCap + order)` — диапазон ниже бригад BL/SR
  (`CrewCap = max_service_vehicles`); одно сравнение в местах разбора `Resident ≤ −2`.
- **Прибытие** — кольцо `CrewArrivals` BL, разбор по диапазону: `Stock_dst += Units`, `InTransit_dst −= Units`, деньги §2.7, заказ свободен.
  Затем **порожний обратный рейс**: `PendingTrip` к источнику с `ResidentRef = 0` — обычная машина без связи, исчезает на месте, как поездки
  OD (`freight.return_empty`, дефолт `true`). Экспорт: прибытие в подключение = продажа.
- **Срок** `3 · ским + 1 ч` (BL): не доехала — заказ считается доставленным (`FreightLate++`), машина едет дальше без связи. Так машина,
  снятая клапаном или застрявшая, не теряет товар — сохранение единиц держится без отслеживания удаления машины.
- **Агрегат** (`exec = aggregate`): `DueTick` по скиму, та же машина состояний (как бригады BL). **Без `outside`:** импорт и экспорт — без
  машины, мгновенно (`FreightVirtual++`).

#### 2.6.5 Запреты фур и «нет пути»
Запрет улицы (VC `SetStreetAccess`) действует на маршрут сам: фура едет в объезд — дольше в пути, дороже доставка (§2.7) и больше машин в
окне. Пути нет вовсе — заявка сброшена при спавне (`OnTripDropped` с отрицательной ссылкой): товар возвращается источнику
(`Stock_src += Units`, `InTransit_dst −= Units`), `FreightNoRoute++`, получатель закажет снова завтра; три дня подряд без поставки —
жалоба `NoDeliveries` у участка (следующий свободный `ComplaintKind`) — игрок видит, что запретом отрезал магазин.

#### 2.6.6 Нехватка товара (вопрос §9.2, рекомендация Б)
`cover = min(100, Stock · 5 · 100 / dayCap)`; `supply_pct = max(cover, shortage_floor_pct)` (дефолт **50**). Дневной лимит визитов C —
`dayCap · out_pct(BL) · supply_pct / 10 000`; визит сверх лимита из-за товара — `VisitsNoGoods` (не в спрос C, а в спрос складов §2.8).
Тяжёлая без сырья — выпуск `× supply_pct` по сырью. `Stock` не уходит ниже 0. Эффект на фирму — через прибыль: меньше продаж → `ProfitEwma`
падает → правила §7.4 `zoning-demand.md` (сокращение через 3 дня, закрытие через 14 и счёт < 0). Бит `Shortage` у здания — клиенту.

#### 2.6.7 Внешний мир (вопрос §9.3, рекомендация А)
Подключения ADR-0037 — неограниченный источник (импорт, сырьё) и сток (экспорт) с самого начала: ранняя игра не блокируется цепочками.
Цена делает своё: импорт дороже местного (§2.7), поэтому склады и промышленность выгодны, а их рост тянет спрос §2.8.

### 2.7 Деньги (ledger CZ2, потоки при прибытии)
| Поток | Кто → кому | Сумма (стартовое) |
|---|---|---|
| `Goods` | получатель → поставщик-здание | `Units · price`: промышленность 60, склад 66 |
| `Import` | получатель → `External` | `Units · 72`; сырьё тяжёлой — `Units · 30` |
| `Export` | `External` → производитель | `Units · 54` |
| `Freight` (новый, следующий свободный, ожидается 23) | платит **отправитель** (импорт — получатель) → `External` | `trip_base` (фургон 10, фура 25) + `per_min` (1 / 2) × минут симуляции в пути |

- Проверка стационара: покупка 30 × 5 визитов = 150 выручки на единицу против 60–72 закупки — 40–48 % (как `goods_pct` 40 сейчас); лёгкая:
  12 ед. × 60 = 720 на 10 смен против 600 зарплаты (+20 %); тяжёлая: 20 × 60 − 10 × 30 = 900 (+50 % минус фуры) — богаче, но шумит и ветшает
  быстрее всех. Числа — вход калибровки FR5 по принципу «ровной кривой денег», не баланс.
- Налог на прибыль, земля, квартплата BL (`UtilityFee` за `Capacity`), расходы служб SR — без изменений: новые виды платят по тем же правилам.
  Деньги цен и доставки уходят во внешний мир — «волна»: город с длинными объездами фур богатеет медленнее.

## 7. Тесты и приёмка
Модульные (`tests/Sim.Core.Tests/City/Freight*`, `Zones*`, малый город фикстуры с 1 подключением):
1. **Сохранение единиц:** за N суток `выпуск + импорт + сырьё = продано + экспорт + Σ Stock + Σ InTransit + списано`; `Σ InTransit` = единицы
   заказов в пути; в micro и агрегате.
2. **Голод:** магазин без поставщиков и без `outside` → `supply_pct` = пол, визиты `VisitsNoGoods`, прибыль ниже, сокращение по §7.4;
   при полу 0 — продаж нет.
3. **Запрет фур:** ТЦ за улицей «без фур» с объездом — поставка доходит, время и `Freight` больше; без объезда — `NoPath`, товар вернулся,
   `FreightNoRoute`, через 3 дня `NoDeliveries`; подъезд к цели на запретной улице разрешён (VC §2.2).
4. **Внешний мир:** импорт выбирается, только если местного нет в радиусе или он дороже на `import_penalty_s`; экспорт тяжёлой — фуры к
   подключению; без `outside` — виртуально.
5. **Смешанная:** пара `main`/`podium`, общий участок, заброшка низа не выселяет жильцов, снос — оба; доля пеших покупок жильцов башни
   > доли жильцов `housing_high` того же района.
6. **Смены и пики:** гистограмма прибытий `office_cbd` — ≥ 80 % в ±1 слот от 9:00; `office_small` — шире; тяжёлая — два пика 6:00 и 14:00.
7. **Окна:** выезды фургонов `retail_local` в 06–11, фур ТЦ в 02–07, логистика — во все часы.
8. **Сейв:** `Save → Load → Save` побайтно; сейв на каждом тике вокруг заказа, выпуска корзины, прибытия, сброса «нет пути», порожнего рейса
   (шаблон `WorldSaveMomentsTests`).
9. **Детерминизм:** `s10k-res-fr` хэш при 1/2/3 потоках; 0 Б/тик (`AllocationProbe`) с фурами в пути и полной корзиной.
10. **Инварианты спроса:** `OneMoreLane` и `Braess` (`zoning-demand.md` §10.2–10.3) зелёные в режиме; DM1–DM4 — прежние.
11. **Без режима:** хэши `*-res`, `*-res-bl`, `*-res-sr`, s1k/s10k, Rust — прежние; `PaintZone` с видом 6 → `InvalidArgument`.

Приёмка (FR5, облако): `bench-gate` s1k без регрессии; справочно `s10k-res-fr` (3 сида, окно 12 000 тиков): tick p95, доля грузовых и фур,
нехватка (доля магазинов с `supply_pct < 100`), импорт/местное, средняя доставка, доля ожиданий ≥ 60 с (бюджет ≤ 0.15 %).

## 9. Вопросы владельцу
### 9.1 Насколько подробно моделировать грузы
**Что это.** Фургоны и фуры должны ездить «по делу»: отвозить товар от склада в магазин. Можно хранить у здания запас товара и делать
отдельный заказ на каждый рейс, а можно просто пускать грузовые машины между районами по средним потокам, без запаса.

| Вариант | Что увидит игрок | Плюсы | Минусы и риски | Цена |
|---|---|---|---|---|
| **А. Заказы целыми загрузками, запас — счётчик у здания** (рекомендую) | каждый фургон везёт конкретный товар конкретному магазину; пробка или запрет фур — у магазина кончается товар | причина и следствие видны; запреты и объезды имеют цену; точный учёт (тест «сколько уехало — столько приехало») | больше кода: заказы, сейв, проверки | ≈ FR3 целиком (opus) |
| Б. Потоки без запаса: фуры между ячейками по средней матрице | грузовики ездят, но магазину всё равно, доехали ли | дёшево, как OD-генератор | грузы — декорация: пробка ничего не ломает, крупная торговля и склады «держатся» ни на чём | −40 % FR3 |
| В. Только деньги, как сейчас | грузовиков нет | 0 | противоречит решению «грузовые обязательны» | 0 |

Рекомендация — А: решение владельца «на грузах держатся ТЦ, тяжёлая промышленность и склады» требует, чтобы недоставка что-то значила.

**Вопрос:** модель грузов — явные заказы (А) или средние потоки (Б)?

### 9.2 Насколько больно без товара
**Что это.** Если фургон не доехал (пробка, запрет, нет склада), у магазина пустеют полки; у тяжёлой промышленности — нет сырья.

| Вариант | Что увидит игрок | Плюсы | Минусы и риски | Цена |
|---|---|---|---|---|
| А. Жёстко: нет товара — нет продаж | магазин стоит пустой в тот же день | сильный сигнал | одна пробка утром — день без выручки, фирмы закрываются лавиной | 0 |
| **Б. Мягко: продажи падают до 50 %** (рекомендую) | выручка падает, значок «нет товара», через 3 дня сокращения, через 2 недели — закрытие | время на реакцию («удивить, но не убить молча»); вред накапливается через прибыль | без значка игрок не поймёт причину | 0 |
| В. Только жалобы | ничего не ломается | просто | грузы теряют вес | 0 |

Рекомендация — Б: проблема видна и растёт, как в BL; пол — одна ручка `shortage_floor_pct`, перейти на А = поставить 0.

**Вопрос:** без товара продажи — ноль (А), половина (Б) или без потерь (В)?

### 9.3 Может ли внешний мир снабжать всё с начала
**Что это.** В начале игры нет складов и заводов. Если товар можно привезти «из-за края карты», магазины работают сразу, но импорт дороже.

| Вариант | Что увидит игрок | Плюсы | Минусы и риски | Цена |
|---|---|---|---|---|
| **А. Да, всё и сразу, импорт дороже на 20 %** (рекомендую) | фургоны едут от въезда в город; свои склады выгоднее — их строят | ранняя игра не блокирована; фуры на въездах — первая транспортная задача | без складов город долго живёт на импорте | 0 |
| Б. Импорт только сырья; магазинам — только местное | без склада и завода магазины пустые | сильная цепочка | старт блокирован, первые минуты — сплошная нехватка | 0, но калибровка тяжелее |
| В. Импорт с дневной квотой, квота растёт с вехами | часть магазинов на импорте, часть ждёт | средний путь | ещё одна ручка и счётчик | +0.5 дня |

**Вопрос:** импорт открыт для всех с начала (А), только сырьё (Б) или квотой (В)?

### 9.4 Смешанная зона: одно здание или два
**Что это.** «Магазин внизу, квартиры сверху». Технически это либо одна запись с двумя счётчиками (жильцы и работники), либо два здания
на одном участке (жилое сверху и торговое снизу), которые строятся и сносятся вместе.

| Вариант | Что увидит игрок | Плюсы | Минусы и риски | Цена |
|---|---|---|---|---|
| **А. Два здания на участке, связаны** (рекомендую) | один дом; закрылся магазин — жильцы живут | весь существующий код рынка, покупок, износа работает без правок; сейв и хэш — обычные здания | связь пары нужно держать при сносе и заброшке | ≈ 1 день в FR2 |
| Б. Одна запись с двумя пулами | то же | одна строка на дом | правки во всех местах, где читается вместимость и жильцы (рынок, экономика, план дня, износ BL) — риск ошибок | ≈ 3 дня, opus |

**Вопрос:** смешанная — два связанных здания (А) или одно с двумя счётчиками (Б)?

### 9.5 Лестница открытий
**Что это.** С какой вехи доступен каждый из 13 вариантов и когда появляются фуры (а с ними запрет улиц для фур).

| Вариант | Что увидит игрок | Плюсы | Минусы и риски | Цена |
|---|---|---|---|---|
| **А. Лестница §2.9: фуры и запрет улиц с M1, башня с M5** (рекомендую) | город растёт волнами: высотки и ТЦ приходят с первой магистралью, деловой центр — с выделенками | каждая веха приносит новую транспортную задачу вместе с инструментом для неё | 13 вариантов надо объяснить в палитре (замки) | 0 |

### 9.6 Приняты по умолчанию (поменять — словом владельца)
- Один товар (ед.), фиксированные цены; рынка цен и многих товаров нет. Жильё и офисы грузов не получают (доставка на дом — позже).
- Режим `city.zones` — опция сценария; без неё прежние R/C/I и эталоны прежние. Сетка 13 вариантов — код, параметры — данные модов.
- Ночной смены нет (тур не переходит через полночь): у тяжёлой и логистики две смены 6–14 и 14–22; фуры логистики — круглосуточно.
- Покупатели логистики в выходные — нет: в календаре нет недели; розничный зал логистики — после календаря недели.
- Порожний обратный рейс есть (вдвое больше грузовых машин на улицах), машина без связи.
- Поставщик — ближайший по скиму легковых с надбавкой импорту; грузовые ноги скимы не пишут; своих грузовых скимов нет.
- Не доехавшая в срок поставка засчитывается (товар не теряется); «нет пути» — товар возвращается, повтор завтра, жалоба через 3 дня.
- Деловой центр и башня строятся без требований к транспорту — пробка и есть их задача; логистика — только у магистрали.
- Шум и грязь — поля варианта без действия до блока экологии; клиент может показывать.
- Работа делится между офисами и промышленностью поровну (`job_weight`); третья ночная смена, вывоз мусора, почта — не v1.
