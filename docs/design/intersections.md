# Перекрёстки: connector'ы, конфликты, приоритет, светофоры (спецификация, шаг 3)

Статус: принято (ADR-0004). Реализуется задачей J (`core-api.md` §14) поверх структур
`core-api.md` §6.1 (`LaneKind.Connector`, `ConflictGroup`, `NodeControl`), §6.7 (`SignalStore`) и фаз 4/5/7
(§7). Поля, добавленные этой спекой в `core-api.md`, перечислены в §12. Всё, что здесь не оговорено
(IDM, MOBIL, списки на полосе, клэмп I6), — как в `core-api.md`. Маршруты — `routing.md`.

Требования ТЗ, которые закрывает документ: connector-полосы под разрешённые манёвры; светофоры с
фиксированным планом; «уступи дорогу» и STOP на второстепенных; помеха справа по умолчанию; «не въезжай,
если выезд занят»; машины не проходят сквозь друг друга, в том числе на пересекающихся connector'ах;
s1k — stuck = 0 за 30 мин, tick p95 ≤ 1 мс, 0 B/тик; модель без взаимных блокировок.

## 0. Идея в трёх абзацах

1. **Стоп-линия = конец входной полосы.** Машина, едущая к узлу с правилами, видит в конце полосы
   стоящее виртуальное препятствие (IDM тормозит к нему), пока узел не **выдал ей допуск** (grant).
   Допуск выдаётся в фазе 4 только головной машине полосы и только если выполнены все условия
   §5: сигнал, STOP/yield, gap acceptance по конфликтующим потокам, свободный выезд с учётом длины ТС.
2. **Внутри узла действует один закон — билет.** Вместе с допуском машина получает `Ticket` —
   монотонный номер по узлу. На каждой конфликтной точке своего connector'а машина ждёт только машины
   с **меньшим** билетом, которые эту точку ещё не освободили. Отношение «ждёт» строго упорядочено →
   цикл ожиданий внутри узла невозможен → взаимная блокировка внутри перекрёстка исключена по
   построению, а не по удаче gap acceptance.
3. **Перед узлом действует старшинство.** Статический приоритет (главная/второстепенная, помеха
   справа, левый уступает встречному) определяет, кто кого пропускает *при движении*. Если же
   приоритетная машина сама стоит и ждёт (классический 4-сторонний равнозначный перекрёсток с
   машинами со всех сторон), срабатывает детерминированный тай-брейк по времени ожидания и индексу,
   а при долгом ожидании — инверсия приоритета. Любая машина перед узлом получает допуск за
   ограниченное время, если её выезд не занят.

## 1. Геометрия узла и соглашения

- Плоскость `(X, Z)`, курс `atan2(dz, dx)`. «Справа» от направления `d` — вектор `Right(d) = (d.Z, −d.X)`
  (вид сверху в Godot: +X вправо, +Z вниз экрана; для `d = восток` справа — юг). Для двух единичных
  направлений `cross(a, b) = a.X·b.Z − a.Z·b.X`; `cross > 0` — `b` правее `a`.
- **Рукав** (arm) узла — инцидентный сегмент. `NodeArms[FirstArm .. +ArmCount)` отсортированы по
  часовой стрелке по углу `atan2` направления `ArmDir[a]` — единичный вектор от узла к первой точке оси
  сегмента за пределами узла. Направление въезда с рукава `a`: `In(a) = −ArmDir[a]`.
- **Радиус узла** `NodeData.Radius` — расстояние от оси узла до стоп-линий (концов `Normal`-полос).
  **Реализация этапа 1 (J1): фиксированный отступ.** `AddSegment` обрезает ось сегмента на
  `NetworkOptions.NodeSetback` (7 м) у обоих узлов ещё до того, как известны все рукава узла, поэтому
  `Radius = NodeSetback` для всех узлов, а длина connector'а «прямо» = 2·`NodeSetback` = 14 м. Переменный
  радиус `max_a(HalfWidth(a)) + 1.5 м` потребовал бы отложенной обрезки (перестройки полос при
  `BuildConnectors`). Для генерируемых сетей (улица 1+1: полуширина 3.5 м, артерия 2+2: 7 м) 7 м достаточно —
  стоп-линия не заходит на проезжую часть пересекающей дороги; для дорог шире 2+2 на узле с пересечением
  потребуется переменный радиус (этап 2). Спецификация `Radius = 2 м` для `ArmCount ≤ 2` тоже не применяется:
  у стыков и изгибов connector «прямо» длиной 14 м.
  Концы полос у узла — это стоп-линии.
- Connector — кубическая Безье из `core-api.md` §6.1 (`ConnectorSamples` точек, по умолчанию 8),
  `P0` = последняя точка входной полосы, `P3` = первая точка выходной. Для разворота (`P3 ≈ P0`,
  встречное направление) `d = max(|P3−P0|, 2·LaneWidth)`, чтобы кривая была петлёй, а не вырожденной.
- Лимит скорости connector'а: `SpeedLimit = min(limit входной полосы, sqrt(a_lat · R))`,
  `a_lat = 2.0 м/с²`, `R = chord / (2·sin(|turn|/2))` при `|turn| ≥ 10°`, иначе лимит входа;
  клэмп снизу `2.5 м/с`. Для разворота `R = LaneWidth`.
- **Угол манёвра** connector'а от рукава `a` к рукаву `b`: `turn = atan2(cross(In(a), ArmDir[b]), dot(In(a), ArmDir[b]))`,
  `turn > 0` — направо.

## 2. Генерация connector'ов

`NetworkBuilder.BuildConnectors(node)` вызывается в `Create` для каждого узла после добавления всех
сегментов и повторно для узлов, затронутых `BuildRoad` (их connector'ы перестраиваются; сброс
допусков этих узлов — §5.7). Для каждого рукава `a` с входными полосами (`n_in ≥ 1`) и каждого
рукава `b` с выходными полосами (`n_out ≥ 1`), `b ≠ a` (кроме разворота):

### 2.1 Класс манёвра

| `turn` | Манёвр | Код `Maneuver` |
|--------|--------|----------------|
| `|turn| ≤ 30°` | Straight | 0 |
| `30° < turn ≤ 150°` | Right | 1 |
| `−150° ≤ turn < −30°` | Left | 2 |
| `|turn| > 150°` или `b == a` | UTurn | 3 |

Если на узле с ≥ 5 рукавами в один класс попали два рукава, у рукава с меньшим `|turn|` класс
сохраняется, второй получает «соседний» класс по знаку (`Straight` → `Right`/`Left`; второй `Right`
остаётся `Right`). **J1:** переклассификация дублей `Straight` не реализована (на регулярных 5–6-рукавных
узлах дублей нет, а при двух почти соосных рукавах оба получают `Straight`). Поворот круче 150° остаётся
`Right`/`Left` (не `UTurn`), иначе острые Y-развилки теряли бы связность; на узле из **двух** рукавов
(изгиб/стык) любой проезд — `Straight`. Разворот генерируется **только** на тупиках (`ArmCount == 1`) — иначе машины,
чей маршрут упёрся в тупик, не смогли бы выехать; на остальных узлах разворотов нет (этап 1).

### 2.2 Полоса → полоса

`LaneNo 0` — крайняя правая. `n_in` входных, `n_out` выходных полос на паре рукавов.

| Манёвр | Входные полосы | Выходная |
|--------|----------------|----------|
| Right | `LaneNo 0` | `LaneNo 0` рукава `b` |
| Left | `LaneNo n_in−1` | `LaneNo n_out−1` рукава `b` |
| UTurn | `LaneNo n_in−1` | `LaneNo n_out−1` встречного направления того же сегмента |
| Straight | каждая `i` | `min(i, n_out−1)`; если `n_out > n_in`, полоса `n_in−1` дополнительно получает connector'ы на `n_in .. n_out−1` (diverge) |

На `1+1` единственная полоса делает всё (Straight, Right, Left). На `2+2`: `LaneNo 0` → Right +
Straight, `LaneNo 1` → Left + Straight. На `2 → 1` (артерия в улицу) обе прямые сливаются в одну
выходную (merge — конфликт §3). Узел с `ArmCount == 2` без правил: только Straight `i → min(i, n_out−1)`.

Порядок connector'ов в `LaneNext[FirstNext .. +NextCount)` входной полосы: **Straight, Right, Left,
UTurn** (фиксирует «**[шаг 3]** уточнит» из `core-api.md` §6.1). Connector'ы узла лежат подряд в
`Lanes` (`FirstConnector .. +ConnectorCount`), порядок: по рукавам по часовой стрелке, внутри рукава по
`LaneNo` входной, внутри полосы — порядок `LaneNext`. **Локальный номер** connector'а в узле
`LocalBit = lane − FirstConnector ∈ [0, 64)` — предел 64 connector'а на узел (`core-api.md` §6.7);
`Create`/`BuildRoad` отклоняют узел, где он превышен (`InvalidNetwork` / `CommandRejected`).

Реализация J1: разворот — с левой полосы (`n_in−1`) на `n_out−1`; если правила не дали ни одного
connector'а полосе (средняя полоса на T-образном перекрёстке), второй («relaxed») проход разрешает ей все
направления. Диверж `Straight` при `n_out > n_in` реализован в `NetworkBuilder.PlanConnectors`. Предел 64
connector'ов на узел — статус `TooManyConnectors`.

Инвариант: у каждой `Normal`-полосы ≥ 1 connector (на тупике — разворот). Это нужно фазе 7:
машина без маршрута или промахнувшаяся мимо нужной полосы всегда имеет «connector по умолчанию»
`LaneNext[FirstNext]`.

### 2.3 Второстепенные рукава (`ArmFlags`)

Бит `ArmMinor` рукава определяется при построении и при `SetNodeControl`:

1. Если среди рукавов есть и `Arterial`, и `Street` → minor = все `Street`.
2. Иначе если `ArmCount == 3` и ровно один рукав не имеет «противоположного» (нет рукава с
   `|turn| ≤ 30°` относительно его `In`) → minor = этот рукав («ножка» T-образного перекрёстка).
3. Иначе minor-рукавов нет. Если при этом `Control ∈ {Yield, Stop}` → `Control := RightHandRule`
   (знак без главной дороги бессмыслен; событие не генерируется, это нормализация в `Create`).

`Control == None` допустим только при `ArmCount ≤ 2`; для узла с ≥ 3 рукавами `None` нормализуется в
`RightHandRule`. **J1:** нормализация (п. 3 и `None`) выполняется в `NetworkBuilder` при `BuildConnectors` и
`SetNodeControl` (вместе с пересчётом `ArmFlags`) и только для `ArmCount ≥ 3`; на узлах с ≤ 2 рукавами
`Control` не меняется. Узлы с `Control == None` (стыки, изгибы) **не имеют ворот**: допуск не нужен,
конфликтов нет, фазы 4/5 их не касаются.

## 3. Конфликтные пары

Строятся один раз на узел после connector'ов (`ConnectorStore.BuildConflicts(node)`), O(k²·m²)
при `k ≤ 64` connector'ов и `m = ConnectorSamples − 1` отрезков — только при `Create`/`BuildRoad`.

Для каждой упорядоченной пары `(c, c')`, `c ≠ c'`, обоих connector'ов узла:

- `FromLane(c) == FromLane(c')` → **diverge**, конфликта **нет** (машины идут друг за другом по
  входной полосе и расходятся; порядок задан списком полосы).
- `ToLane(c) == ToLane(c')` → **Merge**: `SMine = Length(c)`, `SOther = Length(c')`.
- Иначе **Cross**, если минимальное расстояние между полилиниями `< ConflictWidth = 2.0 м`
  (половина ширины автобуса + запас): `SMine`, `SOther` — `s`-параметры точки наибольшего
  сближения (для пересекающихся отрезков — точка пересечения). Параллельные connector'ы соседних полос
  (3.5 м) конфликтом не считаются.

**J1 (`ConnectorStore.BuildAll(net)` / `BuildConflicts(net, node)`):** connector'ы регистрируются для
всех узлов (в порядке узлов; `LaneData.ConflictGroup` = индекс в `ConnectorStore`), конфликтные пары
строятся только для узлов с `Control ≠ None`. Для пары с общей **выходной** полосой всегда `Merge` (даже
если кривые пересекаются раньше). Ёмкости: `ConnectorsFull`/`ConflictsFull` → `CreateStatus.NetworkTooLarge`;
`SimCapacities.MaxConnectors/MaxConflicts == 0` в `World` означает значения по умолчанию (`MaxNodes·16`, `MaxConnectors·6`).
`Rel` при `a == b` (два connector'а одного рукава, например слияние 2→1) — ничья. `RecomputeRel(net, node,
minorRules)` пересчитывает `Rel` при смене `Control`; для `Signal` в режиме `Fixed` вызывающий (J2/J3)
сам отбирает пары, зелёные в одной фазе. Реальные числа s1k: 4328 connector'ов, 17 988 записей конфликтов
(не более 30 connector'ов на узел).

Запись (8 байт, арена `Conflicts[MaxConflicts]`, у connector'а диапазон `FirstConflict .. +ConflictCount`,
отсортированный по `SMine` по возрастанию):

```csharp
[StructLayout(LayoutKind.Sequential, Pack = 2, Size = 8)]
internal struct ConflictEntry
{
    public byte OtherLocal;   // LocalBit конфликтующего connector'а (индекс = Node.FirstConnector + OtherLocal)
    public byte Flags;        // бит0..1: Kind (0 Cross, 1 Merge); бит2..3: Rel (0 = я уступаю, 1 = у меня приоритет, 2 = ничья)
    public ushort SMineCm;    // s на моём connector'е, см (connector ≤ 655 м)
    public ushort SOtherCm;   // s на чужом
    public ushort Reserved;
}
```

Дополнительно `ConflictMask[c] : ulong` — биты `OtherLocal` всех конфликтующих connector'ов (быстрая
проверка «есть ли что проверять»).

### 3.1 Статическое отношение приоритета `Rel(c, c')`

Вычисляется при построении и при смене `Control`. `a = FromArm(c)`, `b = FromArm(c')`;
положение `b` относительно `a`: `t = turn(In(a) → ArmDir(b))`; `Opposite` при `|t| ≤ 30°`,
`RightOf` при `t > 30°`, `LeftOf` при `t < −30°`.

1. Узел с minor-рукавами (`Yield`, `Stop`, `Signal` в режиме `FlashYellow`): `Minor(a) && !Minor(b)` →
   **я уступаю**; `!Minor(a) && Minor(b)` → **у меня приоритет**. Иначе — дальше.
2. `b RightOf a` → **я уступаю** (помеха справа). `b LeftOf a` → **у меня приоритет**.
3. `Opposite`: мой манёвр `∈ {Left, UTurn}`, чужой `∈ {Straight, Right}` → **я уступаю**; наоборот →
   **приоритет**; иначе → **ничья** (разрешается динамически, §5.4).

Для `RightHandRule` шаг 1 пропускается. Для `Signal` в режиме `Fixed` таблица применяется только к
парам, зелёным в одной фазе (разрешающий левый поворот, §6.2); пары из разных фаз разделены сигналом.
Таблица антисимметрична по построению (`Rel(c,c') = уступаю ⇔ Rel(c',c) = приоритет`), что проверяется
тестом.

## 4. Структуры данных

Все массивы выделяются в `Create` по ёмкостям; новые ёмкости `MaxConnectors`, `MaxConflicts`
(`core-api.md` §3.1, `scenario-format.md`).

```csharp
namespace Sim.Core.Rules.Intersections;

/// Плотный массив connector'ов (индекс = LaneData.ConflictGroup, 0..Count-1; connector'ы одного узла подряд).
internal sealed class ConnectorStore
{
    public int Count;
    public readonly int[]   Lane, Node, InLane, OutLane;   // статика; InLane = FromLane, OutLane = ToLane
    public readonly byte[]  LocalBit, Maneuver, FromArm, Flags;  // Flags: бит0 FromMinorArm
    public readonly int[]   FirstConflict, ConflictCount;
    public readonly ulong[] ConflictMask;
    public readonly ConflictEntry[] Conflicts;              // MaxConflicts
    public int ConflictsUsed;
}

/// Динамика узлов (в NetworkStore, индекс = Node.Index).
uint[]  NodeTicket;        // следующий билет; ++ при каждом допуске
byte[]  ArmFlags;          // параллелен NodeArms: бит0 ArmMinor
Vec2[]  ArmDir;            // параллелен NodeArms
float[] OutReserved;       // [MaxLanes] Σ длин машин, допущенных/находящихся в узле с выездом на эту полосу

/// Машины (VehicleStore, §6.3 core-api): 
byte[]   GateState;        // бит0 Granted, бит1 StoppedAtLine
int[]    GrantConnector;   // connector допуска (индекс полосы) или -1
uint[]   Ticket;           // билет узла; валиден при Granted
ushort[] WaitTicks;        // тиков подряд кандидатом без допуска

/// Scratch фазы 4 (без аллокаций):
int[] NodeCandHead;        // [MaxNodes], -1; голова intrusive-списка кандидатов узла
int[] CandNext;            // [MaxVehicles]
int[] TouchedNodes; int TouchedCount;   // узлы, у которых есть кандидаты в этом тике
```

`SignalStore` — как в `core-api.md` §6.7 плюс `ulong[] PhaseMask` (`[MaxSignalizedNodes * 8]`) и
`int[] NodeOf`. `SignalStates`/`LaneSignals` публичного API заполняются из него в фазе 4.

Память s1k (≈ 440 узлов, ≈ 5 000 connector'ов, ≈ 5 конфликтов на connector): `ConnectorStore` ≈ 5 000 × 44 B ≈
220 KB, `Conflicts` ≈ 25 000 × 8 B = 200 KB. s1m: ≈ 2 M connector'ов → ≈ 90 MB + 80 MB (приемлемо для
baseline-сценария; при необходимости `Conflicts` можно считать лениво — этап 2).

## 5. Ворота: допуск на въезд (фаза 4)

### 5.1 Кандидаты

Машина `i` — кандидат, если одновременно: живая; `Lane[i]` — `Normal`; конечный узел полосы `n` имеет
ворота (`Control != None`); `Ahead[i] == -1` либо все машины впереди на полосе уже допущены (реализация, см. ниже: очередь на зелёный
получает билеты по порядку); `!Granted`;
`Length − S[i] ≤ DecisionDistance = max(30 м, 3 с · Speed[i])`. Next-connector `c = NextConnector(i)`
(`routing.md` §6: из маршрута, иначе connector по умолчанию). Фаза 4 собирает кандидатов за один
проход по машинам по возрастанию индекса в intrusive-списки узлов (`NodeCandHead/CandNext`, узел при
первом касании кладётся в `TouchedNodes`). У кандидата `WaitTicks++` (насыщение 65535); у не-кандидата
и при допуске — `WaitTicks = 0`.

Порядок билетов на полосе обязан совпадать с физическим порядком машин (иначе взаимная блокировка: лидер ждёт ведомого по билету
(§7.2), ведомый — лидера физически). Поэтому (H-fix 2.4a): **ghost** (машина, уходящая на соседнюю полосу; её основной список — целевая
полоса, допуск она получила там) при проверке «впереди все допущены» **пропускается**, а не считается допущенным; и MOBIL
(`Mobil.Evaluate`) не вставляет машину перед **допущенным** ведомым целевой полосы (расширение §7.1: порядок допущенных у стоп-линии
не меняется ни выходом допущенного, ни входом недопущенного перед ним).

### 5.2 Порядок разрешения

Узлы — в порядке `TouchedNodes` (первое касание по индексу машины — детерминировано). Внутри узла
кандидаты (≤ число входных полос ≤ 64, на практике ≤ 16) сортируются вставками по ключу
`(WaitTicks desc, VehicleIndex asc)` в `stackalloc`-буфер и проверяются ворота по очереди. Допуски,
выданные ранее в этом же цикле, видны следующим кандидатам как «допущенные» (§5.4). PRNG не
используется.

### 5.3 Вспомогательные величины

- `ETA(d, v, a, v0)` — время проехать `d ≥ 0` с текущей `v`, разгоном `a` до `v0`:
  `d_acc = (v0² − v²)/(2a)`; если `d ≤ d_acc` → `(sqrt(v² + 2ad) − v)/a`, иначе `(v0 − v)/a + (d − d_acc)/v0`.
  `a = Accel` типа, `v0 = DesiredSpeed` машины; при `d ≤ 0` → 0. Только `MathF.Sqrt`, без FMA.
- Для кандидата `i` и конфликта `e` connector'а `c`: расстояние до точки
  `d_me = (Length(ℓ) − S[i]) + SMine(e)`, `t_me = ETA(d_me)`, время освобождения
  `t_me_clear = ETA(d_me + Length[i] + ClearMargin)`, `ClearMargin = 1.0 м`.
- Для машины `X` на connector'е `c'` (или допущенной головы входной полосы `c'`, тогда её расстояние
  считается через конец своей полосы): `X` **освободила** точку `e`, если `S_X − Length_X ≥ SOther(e) + ClearMargin`
  (Merge: `X` освободила, когда покинула connector — тогда она уже хвост выходной полосы и видна как
  обычный лидер). `t_X_clear = ETA_X(SOther + Length_X + ClearMargin − S_X)`; если `Speed_X < v_creep = 0.3 м/с`
  → `t_X_clear = +∞`.
- `Stationary(Y)` ⇔ `Speed_Y < v_creep && !Granted_Y`.
- `Senior(i, Y)` ⇔ `(WaitTicks[i], −i) > (WaitTicks[Y], −Y)` лексикографически (старше тот, кто дольше
  ждёт; при равенстве — меньший индекс).

### 5.4 Условия допуска кандидата `i` на connector `c` (входная `ℓ`, выходная `o`)

Все условия должны выполниться; первое нарушенное даёт код отказа для метрик.

1. **Сигнал** (узел `Signal`, режим `Fixed`): `LaneSignals[c] == Green`, либо `Yellow` и машина не может
   комфортно остановиться: `Length(ℓ) − S[i] < Speed[i]² / (2·ComfortDecel)`. `Red`/`AllRed` → отказ
   (`DenySignal`). Режимы `FlashYellow`/`Off` — ворота работают как у `Yield`/`RightHandRule` соответственно.
2. **STOP** (узел `Stop`, рукав minor): требуется `StoppedAtLine` — бит ставится, когда
   `Speed[i] < 0.1 && Length(ℓ) − S[i] ≤ MinGap + 1.5 м` (машина стоит у линии), сбрасывается при допуске и
   при смене полосы. Иначе отказ (`DenyStop`). `Yield` и главная дорога узла `Stop` — без остановки.
3. **Выезд свободен** (don't-block-the-box, с учётом длины ТС):
   `Free(o) − OutReserved[o] ≥ Length[i] + MinGap`, где `Free(o) = LaneTail(o) == -1 ? Length(o) : S[tail] − Length[tail]`.
   Плюс сам connector: `Free(c) ≥ Length[i] + MinGap` (на connector'е нет места — не въезжать, стоп-линия
   остаётся чистой). Иначе отказ (`DenyExit`, счётчик `GateDeniedExit`).
4. **Конфликты.** Для каждой записи `e` connector'а `c` (`c' = Other`, `ℓ' = InLane(c')`):
   - **Внутри/допущенные.** Для каждой машины `X` на `c'` (список полосы, ≤ 3 машины) и для головы `ℓ'`,
     если она `Granted` на `c'`: если `X` не освободила точку `e`:
     `Kind == Merge` → ничего (слияние разрешит билет, §7.2); `Cross` → допуск только если
     `t_X_clear + BoxClearMargin ≤ t_me`, `BoxClearMargin = 0.5 с`; иначе отказ (`DenyBox`).
     (Вне зависимости от приоритета: машина внутри узла проезжает первой.)
   - **Подъезжающие.** `Y = LaneHead(ℓ')`, если `Y` существует, `!Granted_Y` и `NextConnector(Y) == c'`
     (иначе никто с `ℓ'` на `c'` раньше `Y` не попадёт — пропустить). Если узел `Signal/Fixed` и
     `LaneSignals[c'] ∉ {Green, Yellow}` — `Y` не угроза, пропустить. Иначе по `Rel(e)`:
     - **у меня приоритет** → пропустить (`Y` после моего допуска увидит меня как допущенную и уступит);
     - **я уступаю** → отказ (`DenyYield`), **кроме** случаев: (a) `Stationary(Y) && Senior(i, Y)`
       (тай-брейк: стоящий приоритетный, который ждёт меньше меня, пропускает); (b) gap acceptance:
       `ETA_Y(SOther(e) + Length(ℓ') − S_Y) ≥ t_me_clear + YieldGapTime` (`RulesDesc.YieldGapTime`, 3 с);
       (c) инверсия: `WaitTicks[i] ≥ MaxYieldWaitTicks` (20 с) и gap с уменьшенным зазором `1.0 с`;
       (d) `WaitTicks[i] ≥ 2·MaxYieldWaitTicks` — безусловно (`PriorityInversions++`);
     - **ничья** → отказ, если `ETA_Y(точка) < t_me` или (равно и `Y < i`), и не выполняется (a)/(c)/(d).
5. Если всё прошло — **допуск**: `GateState |= Granted; GrantConnector = c; Ticket = NodeTicket[n]++;
   OutReserved[o] += Length[i]; WaitTicks = 0; StoppedAtLine = 0; Counters.Grants++`.

Машины на полосах, ведущих в узлы без ворот, допуска не требуют (ведут себя как на шаге 2).

### 5.5 Почему это свободно от взаимных блокировок

- **Внутри узла.** Единственное отношение ожидания между машинами в узле (и допущенными) — «ждёт
  машину с меньшим билетом, не освободившую общую точку» (§7.2). Билеты узла попарно различны → граф
  ожиданий ациклический → машина с минимальным билетом среди не освободивших ждёт только своего
  выезда. Merge, diverge и обычное следование подчиняются тому же порядку: лидер по списку полосы —
  всегда машина, въехавшая раньше (меньший билет или та же полоса впереди).
- **Перед узлом.** Отказ по п. 4 «подъезжающие» снимается за ограниченное время: движущийся `Y`
  либо получает допуск (и тогда это п. 4 «внутри», который снимается, когда `Y` освободит точку — у `Y`
  нет причин стоять внутри, кроме своих меньших билетов и выезда), либо останавливается у своей линии
  и становится `Stationary` — тогда работает старшинство: в любом множестве взаимно уступающих
  стоящих кандидатов ровно один максимален по `(WaitTicks, −Index)`, он игнорирует своих стоящих
  блокираторов и получает допуск; остальные выстраиваются за ним по билетам. 4-сторонний равнозначный
  перекрёсток с машинами со всех сторон разрешается в том же тике, в котором все четверо встали.
  Непрерывный приоритетный поток без зазоров ограничен инверсией: ≤ 20 с с зазором 1 с, ≤ 40 с —
  безусловно. Итого ожидание у ворот ограничено `max(красный, 40 с) + освобождение узла`, пока
  свободен выезд.
- **Выезд.** Правило п. 3 означает, что коробка узла никогда не является узким звеном цикла: машина
  стоит *перед* узлом, а не в нём, и поперечный поток продолжает идти. Остаются циклы на уровне полос
  (все сегменты кольца заполнены, голова каждой полосы хочет в следующий полный сегмент) — это
  сетевой gridlock при насыщении, его показывает `gridlock_flag`; на s1k (3 маш./полосо-км) он не
  достигается. Противодействие на этапе 2 — маршрутизация с учётом загрузки (`routing.md` §9).
- **Стоп-линия и STOP.** Условие `StoppedAtLine` достижимо всегда: кандидат без допуска тормозит к
  виртуальному препятствию и останавливается у линии за конечное время.
- **Промах полосы** (нужный connector недостижим с текущей полосы) не ждёт — берётся connector по
  умолчанию и перепланируется маршрут (`routing.md` §6.3), поэтому «застрять, ожидая смены полосы»
  невозможно.

### 5.6 Бюджет stuck для s1k (60 с без движения)

План светофора по умолчанию — 2 фазы (§6.2), цикл `2·(24 + 3 + 1) = 56 с`, красный для любого
манёвра `32 с`. Худшая цепочка для головной машины: красный 32 с → ожидание зазора на разрешающем левом
≤ 20 с (инверсия) → освобождение узла ≈ 3–6 с ⇒ ≈ 58 с в самом неблагоприятном сочетании, при этом
очередь за головой трогается раньше (сброс `StillTicks` при `v ≥ 0.1`). На нерегулируемых узлах
ожидание ограничено 40 с + освобождение. Планы с 4 фазами (защищённые левые) на этапе 1 не
используются по умолчанию именно из-за этого бюджета; `SetSignalPlan` их позволяет, но тогда
`stuck` может расти — это «проблема трафика», которую метрика обязана показать (`core-api.md` §11).

### 5.7 Сброс состояния

При `BuildRoad`, перестраивающем connector'ы узла, и при `SetNodeControl`: у всех машин с
`GrantConnector` в этом узле — `Granted = 0`, `OutReserved` выездов этого узла обнуляется и
пересчитывается по машинам на его connector'ах; `NodeTicket` не сбрасывается. Машины уже на
connector'ах этого узла дорожают до выхода (их полосы остаются; перестройка на этапе 1 — только
добавление рукава, `LaneData` существующих connector'ов обновляются на месте, индексы сохраняются).

## 6. Светофоры

### 6.1 Автомат

`SignalStore` на `MaxSignalizedNodes`: `Node, Mode, PhaseCount, GreenTicks[8], YellowTicks, AllRedTicks,
OffsetTicks, Phase, Interval, TicksLeft, PhaseMask[8]`. `Cycle = Σ(Green_k + Yellow + AllRed)`.
Каждый тик (фаза 4, до ворот): `TicksLeft--`; при нуле: `Green → Yellow(YellowTicks) → AllRed(AllRedTicks) →
Phase = (Phase+1) % PhaseCount, Green(Green_Phase)`. Нулевая длительность интервала пропускается.
Начальное состояние при `Create`/`SetSignalPlan`: позиция `p = OffsetTicks % Cycle`, проход по
интервалам с начала цикла (O(24)) — так одинаковые планы со смещением дают сдвинутые копии.

`LaneSignals[c]` для connector'ов регулируемых узлов (только для них; остальные `None`):
`Fixed`: бит `LocalBit(c)` в `PhaseMask[Phase]` → `Green`/`Yellow` по интервалу, иначе `Red`; `AllRed` →
`Red` всем. `FlashYellow` → `Yellow` всем (ворота — как `Yield`, §5.4 п. 1). `Off` → `None`
(ворота как `RightHandRule`). `SignalStates[k] = (Node, Phase, Interval, TicksToChange = TicksLeft)`.

### 6.2 План по умолчанию (генератор и `SetNodeControl(Signal)`)

Рукава группируются в **оси**: обход по часовой стрелке, каждый ещё не сгруппированный рукав
объединяется с ближайшим к противоположному (`|turn| ≥ 150°` между `In(a)` и `ArmDir(b)`), если тот
свободен; иначе образует ось сам. Фаза = все connector'ы, входящие с рукавов оси (прямо, направо,
**разрешающий налево** — левый уступает встречному по таблице §3.1 п. 3, ворота обрабатывают это как
обычный конфликт «подъезжающие»). Число фаз = число осей (4-сторонний: 2; T: 2; 5-сторонний: 3).
`Green_k = 24 с` при 2 фазах, `16 с` при 3, `12 с` при ≥ 4; `Yellow = DefaultYellowTicks (3 с)`,
`AllRed = DefaultAllRedTicks (1 с)`; `Offset = 0`. Внутри фазы отсутствуют Cross-конфликты, кроме
пар «левый/разворот ↔ встречный прямой/правый» и `Merge`.

### 6.3 `SetSignalPlan` и `SetNodeControl`

- `SetSignalPlan`: узел должен быть `Signal` (иначе `CommandRejected(NotSignalized)`); `PhaseCount`
  должен совпадать с числом осей узла (маски в 32-байтный payload не входят; произвольные маски —
  этап 2, `CommandRejected(InvalidPhaseCount)`); `Green_k ≥ 1` тик, `Yellow ≥ 0`, `AllRed ≥ 0`,
  `Cycle ≤ 65535`. Применяется немедленно с пересчётом начального состояния по `OffsetTicks`.
- `SetNodeControl(Signal)`: выделить слот в `SignalStore` (нет — `CommandRejected(Capacity)`), план по
  умолчанию, `Node.Signal = slot`. Переход из `Signal` в другой режим: `swap-remove` слота (у
  переставленного узла обновляется `Node.Signal`), `LaneSignals` connector'ов → `None`. Любая смена
  `Control` пересчитывает `ArmFlags` и `Rel` конфликтов узла и сбрасывает допуски (§5.7).

### 6.4 Уточнения реализации (J2)

- Код: `Rules/Intersections/SignalStore.cs` (хранилище, план, слоты, `InitFromSeeds`), `SignalPhase.cs`
  (`SignalPhase.Run(World)`, пока не в `PhaseList`), `SignalMasks.cs` (маски фаз). Хранилище — `World.Signals`.
- **Тактовая формулировка автомата** (эквивалентна 6.1): на каждом вызове `Run` при `TicksLeft == 0` интервал
  переключается (нулевые пропускаются), затем состояние публикуется (`TicksToChange = TicksLeft`) и `TicksLeft--`.
  Интервал длиной `L` виден ровно `L` вызовов; на `n`-м вызове после (пере)инициализации позиция в цикле = `(Offset + n) mod Cycle`.
- **Оси** (6.2): «противоположный» рукав — тот, у которого угол между `ArmDir(a)` и `ArmDir(b)` ≥ 150° (в 6.2 условие
  записано через `turn`, смысл тот же). Рукав без пары образует ось сам. Для 4-way и T получается 2 фазы, для регулярного
  5-стороннего узла без почти-противоположных пар — 5 осей (фаз), для «крест + диагональ» — 3. Больше 8 осей — узел
  не может стать светофором (`InvalidArgument`).
- **Порядок фаз**: оси сортируются по углу оси, свёрнутому в (−45°, 135°]; ось, ближайшая к X (запад/восток), — фаза 0,
  ближайшая к Z — фаза 1. Это совпадает с `SignalPlanSeed` генератора (фаза 0 — ось X). Угол — `MathF.Atan2` только для
  упорядочивания (при Rust-портировании сравнивать псевдоуглом).
- **Маски не зависят от раскладки connector'ов**: бит = `connector − Node.FirstConnector` (`LocalBit`), рукав connector'а
  определяется по сегменту его `FromLane`, ось — по геометрии сегментов. Любой генератор connector'ов (`NetworkBuilder`,
  будущий `ConnectorStore`) должен держать connector'ы узла подряд и использовать это же соглашение для `LocalBit`.
  Узел с > 64 connector'ов не может стать светофором.
- **`LaneSignals`** пишутся только для connector'ов светофорных узлов (по спеке); входные `Normal`-полосы остаются `None`.
  Цвет входной полосы клиент берёт из её connector'ов (`LaneData.FirstNext/NextCount` → `LaneNext`); у одной входной
  полосы все connector'ы одной оси, т.е. одного цвета.
- **Режимы** `SetSignalPlan`: `Fixed` (проверка PhaseCount = числу осей, `Green_k ≥ 1`, цикл ≤ 65535); `FlashYellow`
  (`LaneSignals = Yellow`, интервал `Yellow`) и `Off` (`None`, интервал `Off`) параметров цикла не проверяют.
  Причины отказа — `RejectReason.InvalidArgument` (`NotSignalized`/`InvalidPhaseCount` в `RejectReason` нет);
  нет места в `SignalStore` — `Capacity`.
- **Команды** применяются в фазе 1 следующего `Step` (до фазы 4), поэтому план действует с тика, в котором команда
  была исполнена. `SetNodeControl` меняет `Node.Control` и `Net.Version`; пересчёт `ArmFlags`/`Rel` и сброс допусков (5.7) —
  за задачей J3 (TODO в `CommandDispatcher.SetNodeControl`).
- **Интеграция**: после построения сети и connector'ов вызвать `w.Signals.InitFromSeeds(w)` (в `WorldBuilder`; он же
  выставляет `SignalCount`), добавить `SignalPhase.Run(w)` в фазу 4 `PhaseList` до ворот, добавить `Signals`
  в хэш состояния (`StateHash`).

## 7. Поведение (фаза 5) — чем дополняется IDM

Фаза 5 остаётся read-only: пишет только `Accel[]` и `LaneChangeDir[]`. Для каждой машины IDM берёт
**минимум ускорения** по всем препятствиям ниже (стандартный приём «несколько лидеров»).

### 7.1 На `Normal`-полосе к узлу с воротами

- `!Granted`: стоящее виртуальное препятствие в `s_stop = Length(ℓ) − StopLineOffset (0.5 м)`:
  gap = `s_stop − S[i]`, `Δv = Speed[i]`. Естественно даёт остановку с передним бампером в `s0` от линии.
  Плюс обычный лидер `Ahead[i]`, если есть (тогда машина не голова и до ворот не доезжает).
- `Granted`: лидер по обычной цепочке (§6.4 `core-api.md`: `Ahead`, хвост `c`, хвост `o`) **и**
  препятствия §7.2 по конфликтам connector'а `GrantConnector` (расстояния считаются через конец полосы:
  `d = Length(ℓ) − S[i] + SMine`).
- Смена полосы запрещена в зоне `NoLaneChangeZone = 30 м` до конца полосы (MOBIL пропускает машину; это
  гарантирует, что порядок у стоп-линии не меняется после выдачи допуска).

### 7.2 На connector'е `c` (и у допущенной машины на входе)

Для каждого `e` с `SMine(e) ≥ S[i]` (точки, которые передний бампер ещё не прошёл; записи отсортированы,
обход прерывается, когда `SMine − S[i] > LookaheadDistance = 60 м`):
- Перебрать машины `X` на `Other(e)` и допущенную голову его входной полосы. Если
  `Ticket[X] < Ticket[i]` (сравнение `(int)(Ticket[X] − Ticket[i]) < 0`, переполнение uint безопасно) и `X`
  не освободила точку → стоящее препятствие в `SMine(e) − ConflictMargin (1.0 м)`; для `Merge`
  (`SMine = Length(c)`) это остановка в конце connector'а до выхода партнёра на `o`.
- Машины с бóльшим билетом игнорируются (они ждут меня). Машины без допуска (на входных полосах)
  игнорируются — они не в узле.
- Обычный лидер: `Ahead[i]`, иначе `LaneTail(o)` (через границу полосы), далее по `LookaheadLanes`.

Стоимость: машин на connector'ах ≈ 5 % живых (доля длины connector'ов), на каждой ≤ ~6 записей ×
≤ 3 машины — пренебрежимо.

### 7.3 Переходы (фаза 7) и инварианты

- Вход на connector: `Ticket` сохраняется, `Granted` сохраняется, `NodeThroughput` не трогается.
- Выход с connector'а на `o`: `OutReserved[o] −= Length[i]` (клэмп ≥ 0), `Granted = 0`,
  `GrantConnector = -1`, `NodeThroughput[node]++`, `ConnectorEntries++`.
- **Переходный клэмп**: при `PushTail(o)` если хвост `T` существует и `s' > S[T] − Length[T] − MinPhysicalGap`
  → `s'` и `v'` клэмпятся, `HardClamps++`. При правилах §7.2 это страховка (две машины с разных
  connector'ов не могут выйти на `o` в один тик впереди друг друга — младший билет ждёт выхода
  старшего), но инвариант порядка списка должен держаться безусловно.
- Смена полосы на connector'е невозможна (`Left/Right = -1`).

## 8. Порядок вычислений и детерминизм

3. Разрешение по `TouchedNodes`; внутри узла — порядок §5.2.

машины в сборе кандидатов, ключ сортировки в узле). Вся арифметика — скалярный `float`, `MathF.Sqrt`.

Хэш состояния (`core-api.md` §9) дополняется: по машинам `GateState, GrantConnector, Ticket, WaitTicks`;
по узлам `NodeTicket`; по полосам `OutReserved`. Без этого два прогона могли бы совпасть по
позициям, но разойтись в следующем тике.

## 9. Сложность и бюджет

| Что | s1k (1 000 машин, ≈ 440 узлов) | Оценка |
|-----|-------------------------------|--------|
| Таймеры сигналов | 25 узлов × O(1) + `LaneSignals` 25 × 16 | < 1 мкс |
| Сбор кандидатов | 1 проход, 4 чтения на машину | ≈ 3–5 мкс |
| Ворота | ≈ 100–200 кандидатов × (≤ 6 конфликтов × ≤ 4 машины) | ≈ 20–40 мкс |
| Фаза 5, connector'ы | ≈ 50 машин × ≤ 6 × ≤ 3 | < 5 мкс |
| Итого | | **< 50 мкс** из бюджета 1 мс |

Масштабирование: всё линейно по числу машин (кандидаты — подмножество голов полос), а не по числу
узлов; память линейна по connector'ам. Для 100k/1M машин алгоритм не меняется; стоимость ворот
растёт с плотностью (больше кандидатов), но ограничена числом входных полос с машинами у линии.
Аллокаций нет: списки intrusive, сортировка в `stackalloc`, ETA — скаляры.

## 10. Метрики

- `NodeThroughput[node]` — как в `core-api.md` (фаза 7).
- Новые счётчики `SimCounters` (§12): `Grants`, `GateDeniedExit` (отказы «выезд занят»),
  `PriorityInversions`, `BoxWaitTicks` (Σ тиков, когда машина на connector'е стоит `v < 0.1`),
  `GateWaitTicksTotal` (Σ `WaitTicks` при допуске — для среднего ожидания у ворот).
- Диагностика в тестах (не в ядре): отказов по кодам `DenySignal/Stop/Exit/Box/Yield`, максимум
  `WaitTicks`, доля инверсий.

## 11. Тест-план

Фикстуры — явные сети (`city.enabled = false`) в `tests/Sim.Core.Tests/Fixtures/*.json` или
построенные `NetworkBuilder` в коде; поездки — `SpawnTrip` с явными `FromLane/ToZone`. Общие
проверки для всех фикстур: детерминизм хэша (2 прогона), 0 B/тик после прогрева, инвариант порядка
списков, **I6 на connector'ах**: для каждой пары Cross-конфликтов `(c, c')` ни в один тик тела двух
машин не покрывают общую точку одновременно (`S − L ≤ SMine ≤ S` на обоих) — O(конфликтов) проверка в тесте.

| # | Фикстура | Сценарий | Ожидаемые свойства |
|---|----------|----------|--------------------|
| T1 | Одиночный светофор, 4-way, 2+2 × 2+2 | потоки со всех сторон 600 маш./ч на рукав, 10 мин | `LaneSignals` повторяются с периодом 1120 тиков; ни одна машина не пересекает стоп-линию на `Red` без допуска (допуск на `Red` невозможен); все connector'ы пусты к концу `AllRed`, кроме ожидающих младших билетов; throughput узла ≈ Σ входящих (без накопления очереди) |
| T2 | 4-way равнозначный 1+1, `RightHandRule` | по 1 машине одновременно с каждой стороны, затем непрерывные потоки 300 маш./ч, 10 мин | первая четвёрка разъезжается, старт первой ≤ 1 с после полной остановки всех; `stuck = 0`, `max WaitTicks ≤ 2·MaxYieldWait`; `PriorityInversions` = 0 при 300 маш./ч |
| T3 | T-junction, артерия 2+2 + улица 1+1, `Yield` | главная 900 маш./ч, ножка 200 маш./ч, 10 мин | машины с главной не тормозят из-за ножки (`HardClamps` у узла = 0, средняя скорость на главной ≥ 0.9 free-flow); с ножки въезжают только в зазоры ≥ `YieldGapTime` (по логу ETA) |
| T4 | То же, `Stop` | | каждая машина с ножки имеет тик с `Speed < 0.1` в пределах 3.5 м от линии до въезда |
| T5 | Насыщение: светофор с притоком > пропускной | 1 полоса, приток 1 500 маш./ч при зелёном 24/56 | очередь растёт линейно; throughput ≈ `g/C · 2 400 · k` (±15 %); `BoxWaitTicks` ≈ 0; `GateDeniedExit = 0` |
| T6 | Gridlock-ловушка: кольцо 2×2 квартала, сегменты 60 м, `RightHandRule`, плюс поперечные потоки | все машины кольца едут по кольцу, приток выше ёмкости кольца | с правилом п. 3: поперечные потоки идут (`throughput` поперечных узлов > 0 весь прогон), `gridlock_flag` может подняться только на машинах кольца; с отключённым п. 3 (тестовый флаг `World.DebugDisableExitCheck`) поперечные потоки встают — дифференциальный тест, доказывающий, что правило работает |
| T7 | Merge: 2 → 1 (артерия в улицу), оба прямых connector'а | насыщенные потоки по обеим полосам | порядок на выходной полосе — по билетам; переходный клэмп срабатывает редко (`HardClamps` < 1 % выходов); нет наложений |
| T8 | Разрешающий левый на светофоре | встречный поток 600 маш./ч, левые 200 маш./ч | левые въезжают в зазоры или по инверсии; `stuck = 0`; max ожидание ≤ 58 с |
| T9 | s1k, 36 000 тиков | полный сценарий | `stuck = 0`, `gridlock_flag = false`, 0 B/тик, tick p95 ≤ 1 мс (bench) |

Юнит-тесты построения: классы манёвров и раскладка полос для `1+1`, `2+2`, `2→1`, тупика (разворот),
5-стороннего узла; антисимметрия `Rel`; число конфликтов 4-way 1+1 (ожидается 12 connector'ов,
Cross-пары — по таблице в тесте); план по умолчанию (2 оси для 4-way и T, 3 для 5-way), стартовое
состояние при `Offset`.
