# Уровни детализации симуляции: micro + meso (шаг 2.6, ADR-0013)

Статус: спека архитектора, 2026-10-24. Решение и варианты — `docs/adr/0013-simulation-levels-of-detail.md`.
Лестница и секция `lod` — `scenario-format.md` §2.1, §2.3. Реализация — после P1–P5 (ADR-0016, `hotpath.md` §5).
Все числа ниже — **оценки** (формулы в §6); реальные — замер верификатора.

## 0. Идея в трёх абзацах
Город режется на квадратные LOD-ячейки (1 км). Ячейка — micro (как сейчас: IDM, MOBIL, ворота каждый тик) или meso
(кинематика первого порядка, без IDM/MOBIL, решения раз в 4 тика). Узел, его входные полосы и connector'ы — всегда в одной
ячейке, поэтому ворота целиком одного уровня; уровень машины меняется только при въезде на полосу или при смене уровня ячейки.

Meso — **не другая структура данных**, а другая формула поведения над тем же состоянием: те же списки полос, `S`, ghost,
окно маршрута, допуски и билеты ворот. Поэтому переход не двигает ни одной машины и не рвёт очередь, бездедлоковость ворот
(`intersections.md` §5.5) и I6 доказываются тем же аргументом, а снапшот meso — настоящие позиции.

Какие ячейки micro, решает детерминированный контроллер раз в 5 с: фокус (камера через команду `SetLodFocus`, выбранная
машина), закреплённые места, пробки — в порядке приоритета, пока машин в micro ≤ `micro_budget`. Камера влияет на состояние
только через команды (лог, сейв, реплей воспроизводимы); на снапшот — через `SetRenderView` (вне хэша).

Сетка: `lod.cell_m` (дефолт 1000), bounding box сети в `Create`, отображение узла → `(cx, cz)` с зажимом к краю — та же
функция, что у ячеек уровня 1 оверлея (`routing.md` §9). `cell = cz · CellsX + cx`, `color = (cx & 1) | (cz & 1) << 1`.

## 2. Meso: поведение и движение

### 2.1 Такт
Meso-машина «думает» (фаза 5) в тики `(Tick & 3) == color(ячейки её полосы)` — 5 Гц, `τ = 4·dt = 0.2 с` — **или** при
`MesoFresh` (тогда флаг снимается). Двигается (фаза 6) каждый тик. Ворота meso-узла (фаза 4) — в тик цвета его ячейки.

### 2.2 Фаза 5 (meso, в свой такт)
Входы — те же, что считает micro (поиск лидера `LeaderSearch` с просмотром ≤ 6 полос / 150 м, `ObstacleGap` ворот с
конфликтами по билетам `ConflictGap`, остановка автобуса, конец маршрута): `g` — минимальный зазор бампер-бампер до любого
из препятствий, `gSafe` — тот же минимум для клэмпа (как `ClampLeadGap/ClampGateGap`, ADR-0016).

```
T  = HeadwayTime · meso_headway_scale        a = Accel · meso_accel_scale       s0 = MinGap        τ = 4·dt
vT = min(v0, max(0, (g − s0) / T))                                   // треугольная ФД: q_max = 1 / (T + (L + s0)/v0)
v' = clamp(min(vT, v + a·τ), 0, MaxSpeed)                            // разгон ограничен, торможение мгновенное
Speed = v';  Accel = 0  (не используется meso)
MesoAllow = max(0, min(gSafe − MinPhysicalGap, v'·τ))                // путь до следующего пересчёта
```
Устойчивость: `τ ≤ T` (0.2 ≤ 1.0–1.5 с) — монотонный подход к препятствию без перелёта. MOBIL не считается.
Смена полосы (в свой такт, намерение `LaneChangeDir`, исполнение — фаза 7, как у micro):
- **вынужденная**: текущая полоса ≠ полосе окна маршрута для следующего connector'а (то же условие, что у MOBIL forced);
- **объезд**: лидер ближе 30 м — автобус `AtStop` или стоящая машина не у ворот, соседняя полоса ведёт по маршруту;
- безопасность: зазоры спереди/сзади на целевой полосе ≥ `L + s0`, задний — ещё ≥ `v_back · 1 с`; запрет вставки перед
  допущенным (`intersections.md` §5.1). Добровольных смен нет.

### 2.3 Фаза 6 (meso, каждый тик)
```
gImm = зазор до непосредственного лидера: Ahead[i] (или GhostAhead), у головы — хвост следующей полосы (NextConn/ToLane)
MesoAllow = min(MesoAllow, max(0, gImm − MinPhysicalGap))           // O(1): новые лидеры появляются только «сразу впереди»
d = min(Speed·dt, MesoAllow);  S += d;  MesoAllow −= d
if d < Speed·dt: Speed = d / dt;  MesoClamps++
StillTicks — как у micro по d
```
I6: лидер не едет назад (`v ≥ 0`), а новый лидер может появиться только вставкой (смена полосы, въезд на полосу) — он
непосредственный и ловится `gImm`. `MesoAllow ≤ v·τ` (≤ 3–4 м), поэтому дальше одной полосы вперёд смотреть не нужно.

### 2.4 Фаза 4 (ворота meso-узла)
Кандидаты с meso-полос собираются только в тик цвета ячейки; `WaitTicks += 4` (единицы — тики, пороги §5.4 прежние);
не-кандидат в чужой такт `WaitTicks` не сбрасывает. Решение — та же процедура §5.2–5.4. Таймеры светофоров — каждый тик
для всех узлов. Допуск в тик цвета → фаза 5 того же тика уже видит `Granted`. 2.5 (ADR-0018): контроллер `Adaptive` тоже каждый тик для всех
узлов; его детекторы читают списки полос и `DenyReason` (устаревание ≤ 3 тиков ≪ `Gap` 50 тиков). Заявка на выезд живёт до
`ExitClaimUntil = tick + 4` — переживает такт meso; смена полосы meso соблюдает keep-clear 15 м заявленной полосы (`intersections.md` §5.4 п. 3-bis).

### 2.5 Фаза 7 (переходы)
Без изменений логики. Дополнительно: при въезде машины на полосу `Lod` ставится по `CellLevel[LaneCell[lane]]`;
micro→meso: `MesoFresh = 1`, `MesoAllow = 0`; meso→micro: `Accel = 0`, `MesoAllow = 0`. При вставке (смена полосы, въезд
на полосу) перед meso-машиной `f`: `MesoAllow[f] = min(MesoAllow[f], S_new − L_new − MinPhysicalGap − S[f])`; у вставленной
meso-машины — `MesoFresh = 1`.

### 2.6 Автобусы
Как машины своего уровня: остановка — препятствие в `g`, `DwellTicks` — в тиках, посадка — та же. Объезд стоящего у
бордюра автобуса — §2.2. `BusBay` (2.5) — обычные полосы.

## 3. Контроллер уровней (фаза 9b, после метрик)

Оценка — в тики `Tick % (eval_s·20) == 50` (смещение от пересчёта весов) или на ближайшем тике после команды фокуса
(не чаще раза в 20 тиков, `LodEvalRequested`).
1. Статистика: один проход по живым — `CellCount++`, `CellWaiting++` при `StillTicks ≥ 600` (стоит ≥ 30 с: дольше любого
   красного по плану §6.2), `CellStuck++` при stuck. Мгновенная «медленность» не годится — у светофора на красном она
   есть всегда.
2. Класс ячейки: 3 — в прямоугольнике слота фокуса (+ кольцо `focus_margin_cells`) или ячейка выбранной машины
   (`follow_selected`); 2 — в слоте закрепления; 1 — пробка: `CellWaiting ≥ max(congestion_min, congestion_share·CellCount)`
   или `CellStuck > 0`, и так `CellCongStreak ≥ 2` оценок подряд; 0 — иначе. Удержание: если `Tick < CellHoldUntil` и ячейка
   micro, а класс вышел 0 — класс 1 с баллом `0xFFFFFF` (выше любой пробки, ниже фокуса и закреплений).
3. Балл: класс 3 — `0xFFFFFF − ` расстояние Чебышёва до центра фокуса; 2 — 0; 1 — `min(Waiting + 8·Stuck, 0xFFFFFE)`.
   Ключ `class << 56 | score << 24 | (0xFFFFFF − cell)` — уникален, сортировка `ulong[]` по убыванию (результат не зависит
   от устойчивости сортировки; Rust — `sort_unstable`).
4. Жадно по ключам: ячейка класса > 0 становится micro, если `Σ CellCount ≤ micro_budget`; не влезла — пропуск
   (`LodBudgetSkips++`), идём дальше. Класс 0 — meso. Выбранной micro-ячейке с причиной (не удержание) `CellHoldUntil = Tick + hold_s·20`.
5. Смена уровня ячейки: обход `CellLanes` → машины полос (списки `LaneHead → Behind` и ghost) → `Lod`, флаги как в §2.5.
   `LodCellFlips++`. Цена — O(машин в ячейке), без аллокаций.

Режимы: `all_meso` — все ячейки meso, контроллер не работает (тесты, замер цены meso); `off` — LOD нет.
`focus_commands = false` — `SetLodFocus` с `Kind = Focus` отклоняется (`RejectReason.NotSupported`): уровень только по состоянию.

## 5. Снапшот и клиент
- Формат и двойной буфер — прежние (ADR-0010). Позиции meso меняются каждый тик — интерполяция клиента без изменений.
- Цена фазы 10 ∝ машинам в `RenderView`: s1m при виде 3×3 км ≈ 2–3 тыс. машин; при виде на весь город (82 тыс.) ≈ +3–4 мс
  — поэтому что рисовать на отдалении, решает ADR-0014 (вопрос владельцу, §11).
- Клиент Godot: прямоугольник проекции камеры на землю → `SetRenderView`; его центр и радиус → `SetLodFocus(slot 0)`;
  инспектор показывает уровень; отладочный оверлей ячеек (цвет micro/meso).

## 6. Бюджет на агента и оценки по лестнице
Тик ≈ `F + c_micro · N_micro + c_meso · N_meso`. `c_micro` ≤ 0.45 мкс (цель ADR-0016: 4 мс / 10 000 = 0.40; на больших
картах кэш хуже). `c_meso` ≤ 0.05 мкс, цель 0.03: движение и проверка конца полосы каждый тик ≈ 5–10 нс, поведение и
ворота ≈ 50% цены micro раз в 4 тика (нет MOBIL и IDM-формулы, тот же поиск лидера) ≈ 0.02–0.04. `F` — маршрутизация
(≤ `work_budget` релаксаций · 3–15 нс), сигналы, метрики, LOD-оценка (O(N) раз в 100 тиков), снапшот вида.

| | машин | micro / meso | F (оценка) | p95 оценка | бюджет p95 |
|---|---|---|---|---|---|
| s1k | 1 000 + автобусы | 100% / 0 | — | 0.48 мс (факт, агент 52) | ≤ 1 мс |
| s10k | 10 000 | 100% / 0 | — | 4.1–4.9 → ≤ 4 мс (ADR-0016) | ≤ 4 мс |
| s10k `all_meso` (диагностика) | 10 000 | 0 / 100% | ≈ 0.3 | ≈ 0.7–1.0 мс | — (критерий §7: ≤ 1/5 от `off`) |
| s100k | 100 000 | ≤ 15k / ≥ 85k | ≈ 2.5 | ≈ 11–14 мс | ≤ 15 мс |
| s1m (1M жителей) | ≈ 80 000 + ≈ 2 000 автобусов | ≤ 15k / ≥ 67k | ≈ 3 | ≈ 10–13 мс | ≤ 15 мс (предложение) |
| stress-1m | 1 000 000 | ≤ 15k / ≥ 985k | ≈ 8–12 | ≈ 60–80 мс (12–16 тиков/с) | нет, отчёт |

Пики p95: оценка LOD раз в 5 с — O(N) проход + сортировка ≤ 2 304 ключей + смена уровня ≤ нескольких тысяч машин
(< 0.5 мс на s1m); цвет ячеек размазывает поведение meso по 4 тикам ровно.

## 7. Тест-план
Каждая задача: `dotnet build -warnaserror`, тесты своей области, `dotnet format`; детерминизм (два прогона — равные
хэши каждые 100 тиков, в т.ч. с `tour`), 0 B/тик (`AllocationProbe`) в `all_meso` и в `auto` **на тиках оценки и смены
уровня**, golden-хэш s1k/s10k при `mode = off` не меняется.

**Эквивалентность потока** (фикстура `Fixtures/Corridor`: явная сеть — артерия 2+2 длиной 3 км, 4 светофора с одним планом,
боковые въезды/съезды; спрос `SpawnTrip` по расписанию 0.5 / 0.9 / 1.2 от пропускной способности, 20 мин игрового времени).
Прогоны `off` (эталон), `all_meso`, `auto` с ячейками через одну (pinned шахматкой) — сравнение с эталоном:

| Метрика | Допуск |
|---|---|
| пропускная способность на выходе (маш./ч, последние 10 мин) | ±5% при 0.5/0.9; ±10% при 1.2 |
| среднее время проезда коридора | ±10% |
| 85-й перцентиль времени проезда | ±15% |
| макс. очередь у первого светофора (машин) | ±20% |
| stuck, gridlock | 0 |
| насыщенный поток одной полосы на зелёном (`Grants`/мин зелёного) | ±5% (калибровка `meso_headway_scale`) |

Город: s10k `off` vs `all_meso`, 30 мин — `TripsCompletedPerMin` ±10%, `AvgSpeedKmh` ±10%, stuck 0 (верификатор).

**Переходы** (s10k, `auto`, `tour`: фокус r 1 500 м обходит карту, шаг 10 с; `micro_budget` 3 000, чтобы ячейки
переключались постоянно; 30 мин): после каждого тика в тесте — I6 (`S[Ahead] − L ≥ S`) и согласованность списков; нет
телепорта: `|ΔS|` за тик ≤ `MaxSpeed·dt + 1e-3` (с учётом смены полосы по длине); `Lod` каждой машины = уровень ячейки её
полосы; `Σ CellCount(micro) ≤ micro_budget` после оценки (кроме удержания); stuck = 0 (верификатор); хэш двух прогонов равен.
Юнит: класс/балл/ключи на синтетической статистике; пробка без stuck не продвигается за один раз; `SetRenderView` с разными
прямоугольниками → равные хэши; `focus_commands = false` → команда отклонена.

## 8. Метрики качества
stuck/gridlock — общие (в тиках). Дрейф meso: `MesoDistanceMm / MesoVehicleTicks` против micro — в bench JSON
(`lod.avg_speed_micro_kmh`, `lod.avg_speed_meso_kmh`), вместе с `micro_vehicles`, `meso_vehicles`, `lod_cell_flips`,
`lod_budget_skips`, `meso_clamps`. Распределение по полосам (2.6c) — отдельно по уровням.

## 10. До этапа 3 (пешеходы, жители)
1. Ячейки — общие для всех агентов: тротуары/переходы получают `LaneCell` так же; пешеход meso — та же кинематика 1-го
   порядка по тротуару, micro — своя модель (ADR этапа 3).
2. ADR-0011: житель вне поездки — запись (агрегат), агент — только в поездке; машина/пассажир/пешеход ссылаются на жителя handle'ом.
3. ADR-0012 (сейвы): уровни ячеек, гистерезис, фокус, `MesoAllow`, `MesoFresh` — в блоках состояния.
4. Bench: цена на агента по виду × уровню (`phase_ms`/агент) — сигнал деградации раньше p95.
5. Многопоточность (ADR-0017): если s1m с пешеходами > 15 мс — фазы 5–6 по диапазонам (обе модели чистые по агенту),
   ворота и переходы по цветам ячеек.
