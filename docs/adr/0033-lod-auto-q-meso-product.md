# ADR-0033: LOD `auto` в продукт — Q-meso по полосе, смена уровня ячейки через кинематику, правки и карманы в micro

- Статус: предложено, 2026-10-28 (задача 5.2, агент 172). Спецификация и план задач: `docs/design/lod-controller.md`.
- **Поправляет**: ADR-0013 п. 7 (переход micro → meso), ADR-0019 п. 2 и п. 4 (Q-meso — модель `auto`; дефолт `micro_budget`), ADR-0029 правило «карман только при
  `Lod.Mode == Off`», `scale.md` §0 K4 (заменён воротами «не хуже»). Остальное в этих ADR — в силе.

## Контекст
- `lod.mode = auto` загрузчик принимает, но контроллера нет: ячейки все micro, `SetLodFocus` не реализован; s100k `auto` = `off` (агент 171). Критерий K1
  (s100k p95 ≤ 15 мс на 4 потоках) задан именно для `auto`; в `off` он недостижим (`routing-parallel.md` §7).
- Q-meso (ADR-0019) работает только в `all_meso`; в мире с очередью отклоняются правки сети игрока, выключены карманы автобусов (ADR-0029), машины очереди
  не видны в доле ожиданий ≥ 60 с, Q + пешеходы — `NotSupported`.
- Решение владельца 2026-10-28: карт-бланш на оптимизации 5.2, но ни одна метрика не хуже прежней; режимы по умолчанию существующих сценариев побитово прежние.

## Решение
1. **Q-meso — модель meso для `auto`.** Уровень решается по полосе (уровень её ячейки): очередь только на обычных полосах meso-ячеек, в micro-ячейках у всех
   машин micro. `all_meso`(queue) остаётся побитово прежним (все полосы meso). M2 (`kinematic`) остаётся: connector'ы, автобусы, допущенные у конца полосы,
   машины пониженной ячейки.
2. **Повышение ячейки** (meso → micro) — материализация членов очереди синтезом позиции (I6 по построению), допуски и билеты не трогаются, ожидание (`StillTicks`,
   `Stuck`) переносится. **Понижение** (micro → meso) — только смена формулы на M2 (`SetLevel`), в очередь машина встаёт при следующем въезде на полосу.
   Формула «micro → Q» из `sim-lod.md` §13.5 не используется (заменяет ADR-0013 п. 7 в части micro → meso: вместо «`MesoFresh`, та же полоса» — M2 до конца полосы).
3. **Контроллер** (фаза 9b) — по ADR-0013 п. 6, статистика ячеек — скользящая по цвету раз в 25 тиков и **входит в состояние** (хэш, сейв `LODS`, `world_version` 11);
   повышений за оценку — не больше `lod.max_promote_vehicles` (дефолт 5 000), остаток — внеочередной оценкой. Дефолт `micro_budget` — 15 000 (как в коде;
   ADR-0019 п. 4 «10 000» снимается: ограничение по одному ядру больше не цель, ADR-0024 и 4 потока).
4. **Правки сети при LOD**: до применения команды ячейки затронутых узлов поднимаются в micro и удерживаются `hold`; операции `Closing/Draining` держат свои ячейки
   micro до конца. Ограничения `NotSupported` из-за очереди снимаются.
5. **Карманы автобусов** работают в micro-ячейках (ADR-0029: условие «`Lod.Mode == Off`» → «ячейка полосы остановки micro»); автобус в кармане не даёт понизить ячейку.
6. **Доля ожиданий ≥ 60 с — по всем уровням**: эпизод машины очереди — по ожиданию без продвижения полосы (`tick − max(QReady, LaneLastExit)`), отдельный счётчик;
   в `off` числа прежние. Метрики «у фокуса» — по виду (`RenderView`), вне хэша.
7. **Ворота «не хуже»** (`lod-controller.md` §4): s100k `auto` против `off` на том же коде, 3 сида, окно 12 000 тиков; медиана `auto` ≤ медиана `off` × 1.10 по ожиданиям ≥ 60 с
   и stuck (если `off` вне бюджета — не выше `off`), поездки и скорость — не ниже 0.97×; у фокуса — то же по виду. Полоса 10% — шум сидов при 3 прогонах.
8. **Q + пешеходы** — по-прежнему `NotSupported` в 5.2; продолжение — отдельной задачей (S4p).

## Альтернативы
| Вариант | Плюс | Минус | Итог |
|---|---|---|---|
| Понижение сразу в очередь (§13.5) | нет кинематики после понижения | очередь со «стоящими в середине» членами, новые правила `Parked`/`Head`, I6 синтеза против живых соседей | отложено (вернуть, если кинематики > 25%) |
| Статистика O(N) в тик оценки, вне состояния | без новых столбцов сейва | пик 2–5 мс раз в 5 с | отвергнуто |
| Скользящая статистика вне сейва | без миграции | решения после загрузки другие — сейв не побитово | отвергнуто |
| Правки при LOD отклонять | ничего не делать | игрок не строит в большом городе | отвергнуто |
| Карманы выключены при любом LOD (как сейчас) | просто | регрессия ожиданий у фокуса | отвергнуто |
| Строгое «не хуже» (без полосы) | буква правила | нужно ≥ 10 сидов s100k (≈ 3 ч на проверку), иначе решает шум | отвергнуто |

## Последствия
- Новые golden `auto`; `off`, `all_meso`(kinematic) и `all_meso`(queue) — побитово прежние (последний — до задач, явно меняющих Q).
- Сейв: `world_version` 11 (миграция — нули), новый файл корпуса — малая фикстура.
- `s100k.json` получает секцию `lod` отдельным коммитом с before/after; нынешний `s1m.json` → `stress-1m.json`.
- Godot должен слать `SetLodFocus` от камеры (S6c); до этого сценарии клиента — без `lod`.
- Rust: плоские массивы статистики ячеек, та же сортировка `u64`.
