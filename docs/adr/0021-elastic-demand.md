# ADR-0021: Эластичный спрос: выбор по обобщённой стоимости из наблюдаемых времён, целочисленный логит

- Статус: предложено, 2026-10-26 (этап 3.2, архитектор, агент #107).
- Спецификация: `docs/design/zoning-demand.md` §5–6, §9–10. Модель жителя — ADR-0011. Маршруты по загрузке — ADR-0006 (не меняются).
  Детерминизм и libm — ADR-0022 п. 3 (новых трансцендентных в хэшируемом состоянии нет).

## Контекст
- Сейчас спрос неэластичен: OD-генератор держит `vehicles.count` машин в пути, сколько бы ни стоила поездка. Новая дорога только
  разгружает сеть — противоречит наблюдаемому «закону» пробок (Duranton & Turner 2011: пробег машин в городе растёт с длиной полос
  с эластичностью ≈ 1, расширение не даёт устойчивого выигрыша по времени). Ради этого закона спрос и делается эластичным.
- Обратная связь «время → решения → загрузка → время» склонна к колебаниям (все сегодня на машине, завтра все в автобусе) и к
  разгону/схлопыванию (урок E3). Нужны сглаживание входов, вероятностный (не argmax) выбор и ограниченные скорости.
- `exp`/`ln` из libm в хэшируемых решениях запрещены (ADR-0022): C# и Rust разойдутся на других ОС.

## Решение
1. **Обобщённая стоимость** ноги/тура, целые децисекунды: `C = T_ivt + w_wait·T_wait + w_walk·T_walk + ASC_m + money/VOT`.
   Веса Q8 (`choice.w_wait` 2.0, `w_walk` 2.0), константы способов `ASC_m`, денежный член в 3.2 = 0 (плата и топливо — этап 4.2).
2. **Наблюдаемые времена (скимы).** `Skim[o, d, mode, period]` — EWMA обобщённой стоимости по LOD-ячейкам (`lod.cell_m`, 1 000 м;
   независимо от `lod.mode`), 6 периодов суток. Наблюдение — каждая завершённая нога (машина: от заявки до прибытия, включая ожидание
   выезда; автобус: ходьба + ожидание + поездка + ходьба; пешком). Сумма и число — целые за период; в конце периода
   `S += (mean − S) >> skim_shift` (λ = 1/4) порциями по тикам. Пара без наблюдений: априорная оценка (свободный поток × коэффициент
   загрузки ячеек из `SegmentLoads`). Плотный массив до s100k (225 ячеек: ≈ 3.6 МБ); для s1m — двухуровневый ским (этап 4.1).
3. **Иерархия выбора (вложенный логит, сверху вниз в плане дня):**
   - частота дискреционных туров 0/1/2 — по logsum доступности C (главный источник индуцированного спроса);
   - цель дискреционного тура — среди K = 8 C-зданий, выборка по гравитации; полезность — привлекательность − θ·C;
   - способ на тур — машина (если `HasCar`), автобус (если есть остановки в радиусе), пешком (если ≤ `max_walk_m`);
   - слот выезда — 5 слотов вокруг желаемого, стоимость = время периода слота + штраф раннего/позднего прибытия (Vickrey: 0.5 / 2.0);
   - маршрут — как сейчас (ADR-0006: веса по загрузке, перемаршрутизация).
   Долгий срок (недели): переезд дома и смена работы (≤ `max_relocate_per_day`), рост зданий по доступности (ADR-0011 п. 6).
4. **Целочисленный логит.** Вес варианта `w = ExpNeg[(ΔC·θ) >> 16]`, таблица `ExpNeg` (1 024 значения, шаг 1/64, Q30) строится
   в `Create` повторным целым умножением на константу `exp(−1/64)` (литерал), без libm; logsum — через обратный поиск по таблице.
   Выбор — `Pcg32` (поток `Demand`) по кумулятивной сумме `ulong`; ничьи — по меньшему индексу варианта. C# и Rust совпадают побитово.
5. **Устойчивость — свойства, а не надежда.** (а) Решения читают сглаженные скимы прошлых периодов (дневное обучение, задержка ≥ 1 день
   для того же периода); (б) логит вместо argmax: доля способа меняется плавно; (в) ограничения скорости долгих решений; (г) ограниченное
   состояние: ≤ 1 рабочий + 2 дискреционных тура на жителя в день, жильё и рабочие места ограничены участками. Инварианты спроса
   (DM1–DM4, спека §10): поездок на жителя в день в коридоре, без колебаний день к дню после прогрева, без схлопывания по лестнице
   s1k-res → s100k-res.
6. **Приёмка закона пробок и парадокса Брайеса.**
   - «One more lane»: перегруженный коридор, +1 полоса в каждом направлении. Через N = 30 игровых дней эластичность машино-км коридора
     по полосо-км ∈ [0.7, 1.3], а пиковое время по коридору съедает ≥ 70% краткосрочного выигрыша. В 3.2 — A/B (два сценария,
     одинаковый seed, равновесие) в micro и динамика в aggregate; динамика в micro — после `UpgradeRoad` (ADR-0023 T5).
   - Брайес (проверяет эгоистичную маршрутизацию ADR-0006, спрос фиксирован): синтетическая сеть «два пути, у каждого узкое и длинное
     звено» плюс короткая перемычка между узкими. С перемычкой перемычкой пользуются, а среднее время S→T в micro растёт (≥ 3%).
   Калибруются `θ`, `ASC`, сила частоты дискреционных туров — не больше 2 итераций (Парето); не сошлось — числа в отчёт, вопрос владельцу.

## Альтернативы
| Вариант | Детерминизм / цена | Эластичность | Итог |
|---|---|---|---|
| Фиксированная цель машин (как сейчас) | — | 0 | отвергнуто |
| Цель машин от средней скорости сети (одно число) | дёшево | грубая, без способов и времени выезда | отвергнуто |
| Argmax по стоимости | целые | есть, но «качели» день к дню | отвергнуто |
| Логит на `MathF.Exp` | libm: расхождение ОС / Rust | есть | отвергнуто (ADR-0022) |
| **Логит на целой таблице + скимы EWMA** | побитово, O(вариантов) на решение | есть, плавная | **выбрано** |
| Равновесное назначение (Frank–Wolfe) по ночам | дорого, вне тика | точная | отвергнуто: не та модель, что в micro |
| Скимы по каждой паре зданий | память O(зданий²) | — | отвергнуто: ячейки 1 км |

## Последствия
- Число поездок, способ и время выезда отзываются на пробки за 2–5 дней (скимы λ = 1/4), размещение — за недели.
- Игрок видит «расширил дорогу — через месяц опять пробка, зато больше людей ездят». Сила эффекта — параметр (вопрос владельцу).
- Скимы — состояние (сейв `SKIM`, хэш); накопители периода — тоже (иначе продолжение после `Load` расходится).
- Цена: решение ≈ 20 обращений к таблице и скимам; ≈ 3–5 событий за тик на s10k-res — микросекунды (спека §11).
- Риски: (1) скимы по 1-км ячейкам грубы для коротких поездок — внутри ячейки поправка по расстоянию; (2) калибровка на синтетике может
  не перенестись на город — отчётный прогон на s10k-res с теми же метриками; (3) колебания при слишком большом θ — тест DM2.

## Уточнения реализации (Z3, 2026-10-26)
- `ExpNeg` и `E1` - в `Demand/DetLogit.cs`; вектор для Rust - `tests/golden/rust-pilot/detlogit.json`. Выбор читает два слова PRNG (старшее первым), `LogSum` квантован шагом `1/(64·θ)`.
- Априорная оценка скима не использует `SpeedRatio` (он вне хэша): свободный поток; нагрузку видят только наблюдения. Веса мест в доступности - ёмкость типа. Подробности и контракт вызова - `zoning-demand.md` §20.2.

## Уточнения реализации (Z4, 2026-10-26)
- План дня выбирает слот выезда перегрузкой `ChooseDepartSlot(w, r, t*, T, fromCell, toCell, mode)`: время ноги кандидата берётся из скима периода слота выезда.
- Рынки (работа, дом) используют тот же `DetLogit` и поток PRNG `Demand` в фиксированном порядке: стоимости ячейка-ячейка - среднее скима по периодам плюс `ASC` (кэш на сутки), вес ячейки `ёмкость · w(C)`, затем логит между K = 8 кандидатами.
- Эластичность по частоте зависит от `asc_freq`: со стартовым `-300 с` средняя частота ≈ 0.03 визитов на жителя в сутки, и расчётный баланс денег (§7.3, 1.2 визита) не сходится; предварительное значение для `s1k-res` - 850 с (≈ 0.96), окончательно подберёт калибровка Z8.
