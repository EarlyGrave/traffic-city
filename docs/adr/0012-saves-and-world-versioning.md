# ADR-0012: Сохранения и версия мира

- Статус: предложено, 2026-10-25 (шаг 2.6b). Номер зарезервирован `docs/design/cs2-lessons.md` (риск №2: S1, E4, P4, S7).
- Спецификация: `docs/design/save-format.md`. Затрагивает `core-api.md` §3 (фасад), §12 (FFI), `sim-lod.md` §10 п.3, ADR-0017 п.4.

## Контекст
- Сохранений нет. Есть `format_version` сценариев и хэш состояния (`core-api.md` §9). Мир пока маленький и структуры ядра ещё
  меняются (2.2–2.6) — формат дешевле зафиксировать сейчас, до долгоживущих городов этапа 3.
- CS2: сейвы ломались от модов/снятого DLC («белые кубы»), Economy 2.0 сломала старые города без миграции, автосейв лагает
  с ростом города. Paradox просит прикладывать сейв к баг-репорту — у нас для этого есть детерминизм, но нет реплея.
- Ядро не знает про файлы (правило 1), формат должна читать Rust-версия (правило 6), детерминизм побитовый (правило 4).
- Разбор кода (`World`, `StateHash`): многие поля, нужные для продолжения, **не входят в хэш** — порядок на полосе
  (`Ahead/Behind`, `Ghost*`), `LaneChangeTicks`, `NextMobilTick`, поля автобуса, `DesiredSpeed`, окна и планы маршрутов,
  матрицы оверлея, `SegCost`, `SegmentLoads`, очередь команд. Значит «хэш после load == хэш до save» — необходимое, но не
  достаточное условие корректности сейва.
- Раскладка части массивов зависит от истории (`BuildRoad` дописывает connector'ы, конфликты и входы оверлея в конец), поэтому
  «пересобрать сеть из узлов и сегментов» даёт другие индексы полос, чем в живом мире.
- Замер прототипом (сырые байты массивов состояния, без заголовков; `save-format.md` §8): s1k — 2.0 МБ, s10k (9 818 машин) —
  9.4 МБ, сжатие deflate ×3.5–4.6; сеть — 54% сейва s10k.

## Решение
1. **Сейв = полный снимок состояния между тиками, самодостаточный.** Пишется всё, что следующий тик читает раньше, чем
   перезаписывает, плюс параметры (`ScenarioDesc` без генератора: ёмкости, правила, маршрутизация, LOD, спрос, типы ТС).
   Сценарий для загрузки не нужен. Не пишутся только **производные** данные — чистые функции сохранённого
   (`LanePieceHeading`, `LaneLength`, `LaneGateNode`, инцидентность и ячейки снапа, граф `RouteGraph` кроме весов, `EntryIdx/ExitIdx`
   оверлея, длины connector'ов, данные спавнера), **scratch** (`Clamp*`, `GateScratch`, задания воркеров) и **выходы для клиента**
   (снапшоты, события). Их строит `Load` тем же кодом, что `Create`. Сомнение → сохраняем.
2. **Критерий корректности** (тесты, `save-format.md` §9): (а) `Save(Load(Save(w)))` побайтно равен `Save(w)`; (б) хэш после
   `Load` равен хэшу до `Save`; (в) продолжение после `Load` даёт те же хэши на каждом контрольном тике, что прогон без
   save/load, при 1 и 2 потоках и с LOD. (а) ловит пропущенные поля, которых нет в хэше.
3. **Сеть пишется как есть** (полосы, точки, connector'ы, конфликты, оверлей с раскладкой): точная, не зависит от версии
   построителя и от истории. Статические блоки сети отделены от динамических — позже можно не писать их и пересобирать
   (режим «компактный сейв», нужен канонический порядок раскладки; этап 3, когда сейвы s100k+ станут нужны игроку).
4. **Формат — бинарный блочный контейнер, little-endian**: заголовок 64 Б → оглавление (FourCC блока, версия схемы,
   флаги, смещение, длина) → блоки → подвал с XXH64 всего файла. Блок — набор именованных столбцов (SoA): каталог столбцов
   (id, тип элемента, длина) + массивы, выравнивание 8 Б, у каждого блока XXH64. Структуры C# (`LaneData`, `NodeData`…) в
   файл **не** копируются — только по полям: формат не зависит от раскладки C# и одинаков для Rust. Мёртвые слоты пишутся
   каноническими значениями (как у свежего слота) — байты сейва детерминированы.
5. **Сжатие — не в ядре.** Ядро пишет и читает только сырой контейнер (канонический, одинаковый у C# и Rust). Хост
   оборачивает его в конверт «заголовок открыто + deflate-поток» (`save-format.md` §7); кодек — поле конверта (zstd — позже).
6. **Версии**: `container_version` (раскладка заголовка/оглавления), **`world_version`** — монотонное целое, растёт при
   любом изменении набора блоков/столбцов/смысла; `schema_version` блока; версия ядра-писателя — справочно.
   Загрузка: `world_version` > текущей → `TooNew` (вниз не мигрируем); меньше → **цепочка миграций `vN → vN+1`** —
   чистые функции над таблицами блоков (без `World`, переносимы на Rust), каждая с golden-сейвом vN в корпусе.
   Правила: новое поле = новый столбец с дефолтом из спеки (миграция не нужна, `world_version++`); смена смысла/единиц/
   типа = новый id столбца или `schema_version++` + функция миграции; смена модели (как Economy 2.0) = смысловая миграция
   с тестом «старый сейв → N дней → инварианты».
7. **Неизвестное**: неизвестный столбец в известном блоке — ошибка (как неизвестный ключ JSON); неизвестный блок с флагом
   `critical` — ошибка `UnknownCriticalBlock`; без флага (моды, данные клиента, превью) — хранится как есть и
   **переписывается в следующий сейв** с отметкой в отчёте. Блоки хоста/модов — свой диапазон FourCC.
8. **Манифест ассетов** (блок `MANI`): вид, индекс в сейве, строковый id (UTF-8 байты, ядро их не разбирает), версия, хэш
   содержимого. **Сейв несёт симуляционные параметры каждого используемого ассета** (типы ТС целиком; будущие здания —
   их данные), поэтому отсутствие пакета ассетов не ломает симуляцию и продолжение побитовое. Недостающий ассет — забота
   клиента: явная заглушка (контрастный бокс по габаритам из сейва с меткой «?») и список недостающих в отчёте хоста.
   Обновлённый ассет: по умолчанию действуют сохранённые параметры; опция — новые параметры для новых спавнов.
9. **API**: `Simulation.MeasureSave` (точный размер), `Save(Span<byte>)` и `Save(SaveSink)` (поток, для > 2 ГБ и FFI-колбэка),
   `Simulation.Load(ReadOnlySpan<byte> | SaveSource, in LoadOptions, in SimRuntimeOptions, out LoadReport)`, `InspectSave`
   (заголовок без загрузки). Вызов — только между `Step`. `Save` в готовый буфер **не аллоцирует** (автосейв в предвыделенный
   двойной буфер, сжатие и запись — потоком хоста); `Load` аллоцирует как `Create`. Ошибки — коды `LoadStatus` + `LoadReport`
   (блок, столбец, строка), никаких исключений наружу и падений: загрузчик проверяет каждую ссылку и каждое число.
   Число потоков, `RenderView`, зонд фаз, `SimWork` в сейв не входят (ADR-0017 п.4).
10. **Реплей** (сейв + лог команд) — **дополнение**, не замена: лог `(tick, Command)` ведёт хост (команды применяются в фазе 1
    следующего `Step`), файл — тот же контейнер (`RPLH` + `CMDL`). Действителен только для той же версии поведения ядра;
    назначение — баг-репорты (автосейв + лог последних минут), регрессии, отладка.

## Последствия
- Размер (`save-format.md` §8): s1k ≈ 2 МБ сырых / 0.5 МБ сжатых; s10k ≈ 9.4 / 2.4–2.7 МБ; s100k ≈ 72 / ≈ 20 МБ (оценка);
  s1m ≈ 0.75–0.8 ГБ / ≈ 0.2 ГБ (оценка). На s1m сеть ≈ 375 МБ сырых — первый кандидат на «компактный сейв».
- Каждое новое поле состояния ядра теперь требует строки в `save-format.md` (столбец, дефолт) и `world_version++`;
  тест (а) упадёт, если поле забыли. Это цена за отсутствие «молча сломанных» сейвов.
- Раскладка сейва повторяет SoA ядра, но не его struct-раскладку: внутренний рефакторинг (AoS → SoA) формат не меняет.
- Автосейв: пауза = копия состояния в буфер (оценка: s10k — единицы мс, s1m — сотни мс); сжатие s10k deflate fastest 98 мс,
  s1m (только сеть) 3.6 с — только в фоне. Для s1m позже — копирование по частям между тиками.
- Rust-ядро реализует тот же контейнер; кросс-тест: сейв C# грузится в Rust и наоборот, сырые байты равны.
- Golden-корпус сейвов в репозитории (≤ 5 МБ, сжатые), CI грузит все версии.

## Альтернативы
| Вариант | Почему нет |
|---|---|
| Только реплей (сценарий + лог команд) | загрузка O(сыгранных тиков): час игры s10k = 72 000 тиков ≈ 4–5 мин; ломается от любого изменения поведения |
| Пересобирать сеть из узлов/сегментов (без полос и connector'ов) | индексы зависят от истории `BuildRoad`; нужен канонический порядок — отложено (п.3), выигрыш на s10k ≈ 50% |
| Копия struct-массивов как есть (memcpy `LaneData[]` и т.п.) | формат = раскладка C# (Pack, порядок полей); Rust и рефакторинг AoS→SoA ломают его |
| JSON/MessagePack/FlatBuffers/Protobuf | медленно и раздуто на миллионах чисел (JSON) или сторонняя зависимость в ядре (ADR); SoA-столбцы проще и mmap-пригодны |
| Сжатие в ядре | `System.IO.Compression` запрещён в ядре (правило 1), сжатые байты C# и Rust не совпадают; хосту проще |
| Хэш состояния как единственная проверка | не покрывает 14 полей машины и ряд массивов (см. Контекст); расширять §9 — ломать golden-хэши без пользы; побайтное сравнение повторного сейва сильнее |
| CRC32 вместо XXH64 | стандартной реализации в ядре нет (System.IO.Hashing — NuGet), XXH64 ≈ 100 строк, тест-векторы, есть в Rust |
| Тихая подмена недостающего ассета (CS2 «белый куб») | игрок не понимает, что сломалось; у нас — явная заглушка + отчёт, симуляция не страдает (п.8) |
