# ADR-0028: Отступ конца полос от узла — по ширине поперечной дороги и `corner_radius`

- Статус: реализовано, ждёт решения владельца по бюджету ожиданий s10k (см. «Последствия»), 2026-10-27 (решение владельца; реализация — агент L8, ветка `local/corner-radius`).
- Затрагивает: `intersections.md` §1 (радиус узла), `core-api.md` §6.1–6.2, `city-generator.md`, `scenario-format.md` §2.1,
  `save-format.md` §12 (`world_version` 6), `rust-pilot.md` §5.2 (`desc_hash`). ADR-0027 зарезервирован под землепользование.

## Контекст
- Полосы обрывались на фиксированном `NodeSetback = 7 м` от оси узла (J1, этап 1): отступ ставился в `AddSegment`, когда рукава узла
  ещё неизвестны. Connector — кубическая Безье между концом входной и началом выходной полосы, лимит скорости — `sqrt(2 · r)`,
  `r = хорда / (2 sin(поворот/2))`.
- Правый поворот из крайней полосы артерии 2+2 (смещение 5.25 м от оси) на узле артерия × артерия: от (5.25, −7) к (7, −5.25),
  радиус лимита 1.75 м, минимальный радиус кривизны Безье 1.10 м (замер `CornerRadiusTests`, s1k, 100 connector'ов). Лимит упирался в пол
  `MinConnectorSpeed = 2.5 м/с`, визуально — поворот «вокруг столба».
- Для дорог шире 2+2 фиксированный отступ ставит стоп-линию на проезжую часть пересекающей дороги (intersections.md §1 это оговаривал).

## Решение
1. **Отступ по рукавам, а не по узлу.** Рукав `a` узла степени ≥ 3: `s(a) = max(NodeSetback, h(a) + CornerRadius)`, где `h(a)` —
   полуширина самой широкой *поперечной* дороги узла (рукав `b ≠ a`, который не продолжает `a` «прямо»: `ArmDir[a]·ArmDir[b] > −cos 30°`,
   тот же порог, что у `ClassifyTurn`). Стоп-линия рукава стоит у начала скругления бордюра радиуса `CornerRadius`, и на прямоугольном
   узле правый поворот из крайней полосы — дуга радиуса `CornerRadius + LaneWidth/2` в обе стороны (артерия → улица, улица → артерия,
   артерия → артерия одинаково). Отступ «на узел» (по самой широкой дороге узла для всех рукавов) даёт тот же радиус, но раздувает
   рукава широкой дороги: на артерия × улица рукав артерии отступал бы на 13 м вместо 9.5 — длиннее connector'ы «прямо» по главной,
   дольше очистка коробки, короче полосы. Per-arm — минимальный отступ, при котором поворот не резкий.
2. **Тупики и изгибы (степень 1–2) — ровно `NodeSetback`** (7 м), как раньше: поперечной дороги нет, раздувать нечего.
3. **Дефолт `corner_radius` = 6 м** (диапазон владельца 6–10 м, берём нижнюю границу): радиус лимита правого поворота артерии
   7.75 м ≥ 6 м (лимит 2.5 → 3.94 м/с); каждый метр сверх этого удлиняет коробку на 2 м (connector «прямо» артерия × артерия — 26 м
   при 6 м, 30 м при 8 м), а с ней время очистки и потери пропускной на светофорах. Городские радиусы бордюра на улицах — 5–9 м.
   Минимальный радиус кривизны самой Безье (ручки `хорда/3` короче окружности) — 4.89 м; лимит скорости по-прежнему считается из
   радиуса хорды (как до ADR, `EmitBezier` не менялся).
4. **Где считается.** Генератор и явная сеть знают все рукава до эмиссии сегментов: `NetworkBuilder.PlanSetbacks` по списку прямых
   сегментов, затем `AddSegment(..., setbackA, setbackB)`. Инструменты игрока (`BuildRoad`, `ToolValidator`) — `IncrementalSetback`:
   новый рукав считает отступ по рукавам, уже стоящим у узла; **существующие рукава не перестраиваются** (на них машины, `Relocate`
   полос по `S` — отдельная задача). `NodeData.Radius` — наибольший отступ рукавов узла (клиент рисует по нему площадку узла;
   констант в `game/` нет).
5. **Короткие сегменты.** `SegmentTooShort` — по-прежнему ось короче `2 · NodeSetback + MinLaneLength` (валидатор инструментов не
   изменился). Если ось длиннее, но не вмещает оба увеличенных отступа и `MinLaneLength`, надбавки сверх `NodeSetback` сжимаются
   пропорционально (`SetbackClampCount`). На s1k/s10k/s100k/*-res сжатий 0, отказов `SegmentTooShort` до и после — 0 (генерация не
   изменила число сегментов: 762 / 2938 / 18003 / 25849 у s100k-res).
6. **JSON.** `city.corner_radius_m` и `network.corner_radius_m` (0..50, дефолт 6). `0` — выключено: фиксированный отступ 7 м, сеть
   побитово прежняя (`CornerRadiusTests.Disabled_ReproducesLegacyNetwork`: `NetworkStore.Hash()` s1k = прежний golden `0x579C25BA8FEB8BC8`).
   В `ScenarioDesc` (`CityGenDesc.CornerRadius`, `NetworkDesc.CornerRadius`) `0` значит «дефолт», `< 0` — выключено (нули структур в тестах
   получают новое поведение). Опция построителя `NetworkOptions.CornerRadius` (0 = выключено).
7. **Без тригонометрии и косых поправок.** Отступ не учитывает угол между рукавами (для узла под углом `φ` точная формула —
   `(h_b + h_a cos φ + R(1 + cos φ)) / sin φ`); на косых узлах генератора (нерегулярные узлы, s1k: 11 connector'ов) правый поворот острее 90°
   остаётся резче: минимальный радиус лимита 1.36 → 3.52 м. Поправка — по запросу владельца.

## Последствия
- **Геометрия и хэши.** Все сети по умолчанию другие: golden `NetworkStore.Hash()` s1k, эталоны хэша состояния `HotPathGoldenHashTests`,
  `AdaptiveGoldenHashTests`, `BasePackageGoldenTests` и golden Rust-пилота (`tests/golden/rust-pilot`, `desc_hash` включает действующий
  `CornerRadius` после `MinLaneLength`) сняты заново отдельным коммитом. Хэш не зависит от числа потоков (1/2/3 — одинаковы).
  `golden_version` Rust-пилота не поднят (общий номер с `detlogit.json`), Rust-порт (`tc-core::network::builder`, `sim`, загрузчик)
  повторяет `PlanSetbacks`/сжатие побитово (`cargo test` зелёный). `headings_hash` в golden снят на Windows — перегенерировать на Linux.
- **Сейвы.** `world_version` 6: столбец `PARM` 185 `NetCornerRadius` (нужен `BuildRoad` после загрузки). `MigrationV6` ставит 0 —
  старые сейвы и после загрузки строят дороги с отступом 7 м; их сети уже лежат в файле и не меняются. Корпус `w6-*` перегенерирован,
  `w1`–`w5` продолжаются прежними хэшами.
- **Поведение.** Длиннее коробки (артерия × артерия «прямо» 26 м вместо 14, улица × улица 19 м): больше время очистки и конфликтов,
  пропускная светофора ниже (коридор micro при загрузке 1.2: 1020 машин/ч на новой геометрии). Калибровка meso (`h`, разгон) и допуски
  «meso против micro» сняты на коробке 14 м, поэтому `Corridor`/`SaturationProbe` и T2 (порог инверсий) закреплены на
  `corner_radius_m = 0`; перекалибровка meso под новую геометрию — отдельная задача.
- **Качество (замер L8, Windows, `bench --ticks 12000 --warmup-until-full`, seed дефолт / 11 / 12).** s1k: доля ожиданий ≥ 60 с
  0.031 / 0.063 / 0 % → 0.031 / 0 / 0 % (медиана 0.031 → 0 %), stuck на конец окна 0 → 0. **s10k: 0.165 / 0.127 / 0.156 % → 0.685 / 0.297 / 0.427 %
  (медиана 0.156 → 0.427 %, бюджет 0.15 %)**, эпизодов 31 / 24 / 29 → 129 / 56 / 80, stuck на конец 3 / 5 / 0 → 0 / 1 / 3, поездки ±1 %.
  Чувствительность s10k к радиусу (медиана): 0 м — 0.156 % (побитово прежнее), 3 м — 0.305 %, 4.5 м — 0.219 %, 6 м — 0.427 % (шум сидов велик).
  Разбор эпизодов (дефолтный сид, 12 000 тиков): рост в основном (а) очереди на крайней полосе артерии за автобусом на остановке посреди
  сегмента (`stop_kind: mixed` даёт артериям `Bay`, но поведение карман не моделирует — автобус стоит на полосе; 25 → ~65 эпизодов) и
  (б) очереди к светофорам артерия × артерия (коробка 26 м вместо 14: дольше очистка, больше `stuck_episodes` светофоров 38 → 130).
  **Бюджет s10k нарушен — решение владельца:** принять с последующими задачами (карманы остановок, интергрин по длине коробки), уменьшить
  дефолт до 4.5 м (радиус лимита 6.25 м) или ограничить надбавку на светофорных узлах.
- **Baseline.** `perf/baseline.json` не менялся: эталон облачный, `update-baseline` после мержа — в облаке, отдельным коммитом.
