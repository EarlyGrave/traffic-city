# ADR-0018: Адаптивный светофор, зелёная волна и справедливость на выезде

- Статус: предложено, 2026-10-25 (архитектор шага 2.5; решение владельца 2026-10-24 — гибрид)
- Спецификация: `docs/design/intersections.md` §5.4 (п. 1, 3-bis, 4b-bis), §6.5–6.9; поправки `core-api.md` §4/§5.4/§6.7,
  `routing.md` §1.1, `city-generator.md` §3.8, `scenario-format.md`, `sim-lod.md` §2.4

## Контекст
- Светофоры этапа 1 — `Fixed` 2 фазы 24/3/1 с разрешающим левым. На плотном s10k левый голодал; правило 4b-bis (2.4a2)
  сняло stuck (35/27/72 → 18/0/4 эпизода за 8000 тиков), но ценой −1…−4% поездок: оно не даёт левому своего времени,
  а лишь перекрывает встречный поток.
- Остаток stuck — `deny=Exit`: очередь со светофора заполняет короткое звено (≈136 м) и запирает соседний узел выше по потоку;
  повороты на забитое звено проигрывают конкуренцию за освобождающееся место (s1k узлы 301/302, s10k 1445/1446).
- Офсеты генератора — волна только на восток по номеру столбца, ось Z не согласована вовсе.
- Защищённые левые «всегда» (4 фазы) отвергнуты в ADR-0004: красный > 60 с.

## Решение
1. **Режим `SignalMode.Adaptive = 3`** (по умолчанию у генератора). Оси обслуживаются по кругу; зелёный оси — от `MinGreen` (7 с)
   до `MaxGreen` (24 с), продлевается, пока к зелёным полосам подъезжают недопущенные машины (gap-out через `Gap` = 2.5 с без спроса,
   max-out при спросе на красных осях). Ось без спроса пропускается, без спроса нигде — зелёный «отдыхает» на текущей оси.
   **Детекторы — чтение состояния ядра** на конец прошлого тика (головы входных полос, `WaitTicks`, `DenyReason`, `NextConnector`),
   без отдельной сущности «петля».
2. **Стрелка по спросу — запаздывающая (lagging)**: после основного зелёного оси, если голова левой полосы рукава уступала
   на зелёном ≥ `ArrowTrigger` (4 с) и не уехала, вставляется подфаза «стрелка» (3…6 с, gap-out 2 с): один рукав со спросом →
   все его манёвры + правые встречного; оба → левые+развороты+правые обоих. Стрелка ⊂ основной фазы, поэтому переход без
   all-red для неё (жёлтый получают только уходящие). Измеряется уступание **на зелёном**, а не `WaitTicks` (в нём красный — иначе
   стрелка включалась бы всегда).
3. **Режимы игрока**: `Adaptive` (параметры или дефолты), `Fixed` (свой цикл; опционально фиксированная стрелка каждый цикл),
   `FlashYellow`, `Off`. Одна команда `SetSignalPlan` (payload растёт 32 → 44 Б, в 56 Б укладывается).
4. **Координация «чередующаяся волна»**: генератор задаёт общий цикл `C = 2·T` (T — время проезда между соседними светофорами
   артерии при скорости волны, s1k: 600 м / 16.7 м/с = 36 с → C = 72 с) и офсет `((x−x₀)+(z−z₀))/v mod C`, ось Z сдвинута на C/2.
   На регулярной сетке это двусторонняя волна по **обеим** осям. Adaptive в координации — «координированный актуированный»:
   окно оси C/2 по часам `(tick + offset) mod C`, раннее завершение (gap-out) и досрочный старт следующей оси разрешены,
   конец окна — force-off. **Приоритет**: безопасность (жёлтый/all-red, красный прямого ≤ 52 с) > 4b-bis > каркас цикла
   координации > адаптация внутри окна. Адаптивная подстройка офсетов на ходу — не делаем (этап 3+).
5. **Анти-спилловер**: (a) светофор — спрос, упирающийся в забитый выезд (`DenyExit` при стоящем хвосте), не продлевает и
   не вызывает зелёный; если весь спрос зелёной оси такой ≥ 3 с — досрочный конец; (b) **заявка на выезд** (п. 3-bis): голова,
   ждущая ≥ 10 с с последним отказом `Exit`, «бронирует» выходную полосу: младшие кандидаты узла на неё получают `DenyExit`,
   а MOBIL не перестраивается в первые 15 м этой полосы, пока заявка жива. Строгий порядок `(WaitTicks, −Index)` →
   новых циклов ожидания нет. Don't-block-the-box (п. 3) уже есть и не меняется.
6. **Правило 4b-bis** остаётся страховкой для `Fixed` и `Adaptive` (раньше — только `Fixed`); порог 20 с. Стрелка срабатывает
   раньше (4 с уступания на зелёном), поэтому 4b-bis должно включаться редко.
7. **Маршрутизация**: штраф узла `Signal` — статическая оценка по плану (Webster `(C−g)²/2C`; для Adaptive `g, C` по
   `(MinGreen+MaxGreen)/2`, в координации — C и окно), плюс измеренная задержка: средний `WaitTicks` при допуске по connector'у
   (EWMA за окна пересчёта весов 30 с, ADR-0006) заменяет статику при ≥ 5 допусках. Клэмп 0…60 с.
8. Детерминизм и 0 Б: контроллер в фазе 4 до ворот, однопоточно, слоты по возрастанию; только целые тики и ETA из §5.3;
   массивы — в `Create` по `MaxSignalizedNodes`/`MaxLanes`; новое состояние — в хэше. Meso (ADR-0013): детекторы читают
   те же списки полос, устаревание ≤ 3 тиков ≪ `Gap`; заявка на выезд живёт до тика `ExitClaimUntil` (переживает такт meso).

## Последствия
- Ожидаемо: среднее ожидание левых ↓, срабатываний 4b-bis ↓, поездок ≥ (стрелка вместо перекрытия встречного),
  `deny=Exit`-эпизоды ↓; на артериях доля остановок ↓ за счёт волны. Проверка — по метрикам ниже, не верой.
- Меняется поведение s1k/s10k по умолчанию → новый golden-хэш (тесты горячего пути закрепляют `signal_mode: fixed`),
  осознанный пересъём baseline s1k отдельным коммитом. Цикл 72 с длиннее 56 с — на слабом спросе Adaptive сокращает его gap-out'ом.
- Цена: ≈ 8–40 чтений на светофор за тик (s10k 100 узлов, s100k 625) — ≪ 1% тика; память ≈ 100 Б на слот + 8 Б на полосу.
- Сейв (ADR-0012) должен включить состояние контроллера и заявок.

## Отвергнутые альтернативы
- **Стрелка всегда (4 фазы)** — красный > 60 с, потеря пропускной способности без спроса (ADR-0004).
- **Опережающая (leading) стрелка** — в координации тормозит взводы, приходящие к началу окна; решение по факту прошлого цикла.
- **Триггер по `WaitTicks` левого** — включает красный, стрелка была бы всегда.
- **Адаптивные офсеты/SCOOT-подобная оптимизация** — нелокальное состояние, сложная проверка детерминизма; не нужно для s10k.
- **Zipper по геометрии на слиянии** — заявка на выезд по старшинству решает то же в рамках существующей модели ворот.
