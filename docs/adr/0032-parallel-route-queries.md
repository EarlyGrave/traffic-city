# ADR-0032: Параллельные запросы маршрутов фазы 3 — спекулятивный пакет и последовательный повтор

- Статус: предложено, 2026-10-28 (задача 5.2, агент 169).
- Спецификация: `docs/design/routing-parallel.md`. Дополняет ADR-0017 (контракт параллельной фазы, `WorkerPool`) и ADR-0009
  (оверлей, `RouteStore`, бюджет работы). Закрывает резерв `scale.md` §7.

## Контекст
- s100k при полной загрузке, 4 потока: фаза 3 занимает **4.76 мс mean / 8.12 мс p95** из 23.4 мс mean тика.
  Это 11.2 запроса и 258 k релаксаций в тик (замер 2026-10-28, `routing-parallel.md` §1). Фаза 3 целиком последовательная.
- Бюджеты (`work_budget_per_tick`) её не ужимают (агент 165). Бюджет 120 k — рампа встаёт на 64 k машин. Бюджет 200 k — `route_deferred` ×130.
- s1m: рампа упирается в фазу 3 (20.5 мс).
- Запрос (`OverlaySearcher.Query` + развёртывание + раскладка) читает граф, оверлей и сеть, которые в фазе 3 до пересчёта весов
  не меняются. Пишет он только scratch поиска. Общее состояние — слоты `RouteStore`, арена плана, `RngRouting`, хэшируемые счётчики,
  очереди — меняется в коротком хвосте `Router.Build` и в цикле `RoutePhase`.

## Решение
1. `Router.Build` делится на две части:
   - **чистый счёт** `RouteCompute.Run(query, net, graph, overlay, scratch, ref result)`: статический, без `World`;
   - **фиксацию** `Router.Commit`: пул слотов, счётчики, `WorkThisTick`, `SetPlan`, окно.
   Scratch (поиск, куча, буферы роутера) — свой у каждого воркера пула. `Build` = счёт на scratch 0 + фиксация (автобусы не меняются).
2. **Фаза 3:**
   - (A) последовательный сбор кандидатов в порядке очередей (`Rerouting`, затем `PendingTrips`) с теми же фильтрами, что до `Build`,
     без изменения состояния; `Destinations.Pick` — на копии `RngRouting`;
   - (B) счёт кандидатов на `WorkerPool`, чанк 1, порядок раздачи — по убыванию оценки цены;
   - (C) **нынешний последовательный цикл** `RerouteVehicles`/`RouteTrips`, где вызов `Build` берёт готовый результат, если ключ
     запроса совпал побитово, иначе считает сам.
3. Бюджет, `Deferred`, доли Timed, `route_deferred` решаются только в (C) по фактической работе зафиксированных. Посчитанное сверх бюджета
   отбрасывается (перенос на следующий тик — не сейчас).
4. Размер пакета (`MaxCandidates` 256, оценка по средней работе запроса) влияет только на скорость. **Хэш не зависит от числа потоков,
   размера пакета и порядка раздачи** и равен хэшу нынешнего кода. Golden и корпуса сейвов не переснимаются.
5. `WorkerPool.Run(job, count, chunkSize)`: запросов в тик ≈ 11, а при чанке 256 весь пакет уходит одному воркеру.
6. Волна кастомизации, пересчёт весов и дозаполнения окон остаются последовательными. Волна и пересчёт идут после фиксации,
   дозаполнения — до сбора. Параллельная волна — отдельная задача для s1m.

## Альтернативы
| Вариант | Детерминизм | Выигрыш | Итог |
|---|---|---|---|
| **Пакет + последовательный повтор (это ADR)** | побитово = последовательный код (повтор того же цикла) | фаза 3 s100k ≈ 4.76 → 2.0–2.3 мс (оценка) | **принято** |
| Статическое деление бюджета между воркерами (каждому `MaxWork / W`) | хэш зависит от числа потоков | — | отвергнуто: нарушает ADR-0017 п. 4 |
| Отбор «первые N запросов по числу», без бюджета работы | детерминирован, но меняет семантику бюджета (H-T10) | тот же | отвергнуто: новые golden без пользы |
| Фиксация в порядке завершения | зависит от потоков | — | отвергнуто |
| Меньше запросов (пороги timed-reroute, −27%) | детерминирован, меняет поведение | ≈ −1 мс | ортогонально; отдельным ADR по замеру |
| ALT/CCH (дешевле запрос) | — | неизвестно, большая работа | позже (ADR-0009, порт на Rust) |

## Последствия
- Новое состояние вне хэша и сейва: `RouteScratch` на воркер, массивы пакета, диагностика `RouteBatchStats` (bench JSON `routing.batch_*`).
  Память: 37 Б × `DirSegCapacity` на воркер — s100k 2.4 МБ, s1m 24 МБ на воркер (+4% и +9% к нынешнему пику).
- Ожидаемо: tick p95 s100k −3…−3.5 мс, то есть `off` 26.94 → ≈ 23.5–24 мс.
  **K1 (15 мс) в режиме `off` недостижим и с этим ADR.** Без фазы 3 тик уже 18.7 мс mean (behaviour 8.6, gate 6.7). Второй рычаг —
  `lod auto` для `s100k.json` (S7, вопрос владельцу, `routing-parallel.md` §9 В1).
- s1m: пропускная способность запросов ×2.3–2.6 на рампе. Следующий потолок — последовательная волна кастомизации (≈ 30 мс на тик волны).
- Тесты: хэш «пакет выключен» = «пакет» при 1/2/3/4 потоках (s1k, s10k, s100k-рампа); независимость от `MaxCandidates`; бюджетные тесты
  (`TimedBudgetTests`, H-T10, `Deferred`) с пакетом; правки сети (`EditFuzz`) при 1 и 4 потоках; 0 B с 1 и 4 потоками.
- Rust: `rayon` `par_iter().map_init(scratch)` по кандидатам + последовательная фиксация; `RouteCompute` — `fn(&Graph, &Overlay, &mut Scratch)`.
