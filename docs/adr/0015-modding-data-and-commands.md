# ADR-0015: Моддинг через данные и команды API

- Статус: предложено, 2026-10-25 (этап 4.5, архитектор). Номер зарезервирован `docs/design/cs2-lessons.md` (риски S2, S3, топ-5 №5).
- Спецификация и задачи M1–M9: `docs/design/modding.md`. Затрагивает `scenario-format.md` (§1, §3, новый `format_version: 3`),
  `save-format.md` §5 (манифест `MANI`, версии параметров типов), `core-api.md` §4 (`BuildRoadCmd.Asset`, `RejectReason.UnknownAsset`),
  ADR-0012 п.8 (опция «новые параметры для новых спавнов» — реализуется здесь). Точка стыковки с ADR-0014 (бюджет рендера и LOD,
  ещё не написан): «ассет без LOD отклоняется», числа задаёт ADR-0014. Команды игрока и их JSON-форма — ADR-0023 (4.3).

## Контекст
- CS2 (S2): редактор ассетов появился через два года и потребовал перевести базу и DLC на новый пайплайн. Пайплайн не
  проектировался под моды. S3: обновления ломают код-моды, потому что моды патчат внутренности. S1: сейв ломается без мода
  («белые кубы»).
- У нас уже есть: ядро без файлов (правило 1), JSON-сценарии и `vehicle-types.json` (правило 6), манифест ассетов `MANI` в сейве,
  `AssetManifestBuilder` (`vehicle:<имя>`, `ContentHash` = xxh64 параметров), сейв несёт параметры типов целиком (`VTYP`),
  `LoadReport.AssetsMissing/Changed`, `Simulation.AssetStates`. Не хватает: пакета (что такое мод), id с пространствами имён,
  зависимостей, дорог и зданий как данных, проверки glTF, «новых параметров для новых спавнов» (бэклог этапа 2, решение
  владельца в `roadmap.md` 2.6b) и пределов против вредных файлов.
- Ядро переедет на Rust. Любая модель модов, которая трогает внутренности ядра (рефлексия, Harmony-патчи, скрипты в фазах тика),
  на Rust не переносится и ломает детерминизм и 0 B/тик.

## Решение
1. **Мод = пакет данных.** Каталог с `package.json` (id, версия semver, `requires`, список файлов контента) и файлами:
   JSON (параметры), glTF/GLB + текстуры (визуал). Исполняемого кода в пакете нет. Своё содержимое игры — пакет `base`
   (`content/base/`), который грузится **тем же загрузчиком**, что любой мод. Отдельного «встроенного» пути нет.
2. **Что мод может на этапе 4:** новые типы ТС (существующие категории `car`/`bus`), типы дорог (комбинации полос, скорости и
   `RoadKind` плюс визуальный профиль), здания (формат зарезервирован, параметры задаст ADR-0011), сценарии (генератор,
   явные сети, спрос, транспорт, доли типов) и **таймлайн команд** в сценарии: список `(tick, Command)` в JSON-форме ADR-0023.
   Таймлайн — это данные, хост ставит команды в очередь `Enqueue`, как это делает игрок.
   **Чего мод не может:** новое поведение (правила IDM/MOBIL/перекрёстков, новые категории ТС, новые виды команд), скрипты,
   правка UI, переопределение чужих ассетов, выход за пределы ёмкостей ядра.
3. **Скриптов на этапе 4 нет.** Причины: (а) S3: скрипт привязан к внутренностям и ломается от обновлений, а команды API
   версионированы; (б) скрипт в тике ломает детерминизм, 0 B/тик и порт на Rust; (в) песочницы для C# в процессе нет,
   а Lua/WASM — это новая зависимость, свой ADR и детерминированный интерфейс к ядру; (г) ни одной задаче этапа 4 скрипт
   не нужен. Вернуться к вопросу можно, когда появится запрос, который не выражается данными и командами. Тогда кандидат —
   WASM в хосте, который только читает снапшоты и ставит команды, и никогда не работает внутри тика.
4. **Стабильные id и пространства имён.** Id пакета — `[a-z][a-z0-9_]{1,31}` (`base` зарезервирован). Id ассета —
   `<пакет>:<вид>/<имя>`, например `base:vehicle/car` или `transit_plus:vehicle/bus_long`. Вид — `vehicle | road | building | prop`.
   Id неизменен для всех версий ассета: переименование — это новый ассет. Мод объявляет ассеты только в своём пространстве
   имён, повтор id — ошибка загрузки. Старые id сейвов `vehicle:<имя>` хост читает как алиас `base:vehicle/<имя>`
   (ядро строки не разбирает, миграция сейва не нужна).
5. **Порядок загрузки детерминирован.** Сначала топологическая сортировка по `requires`, при равенстве — по id пакета
   (ординально), внутри пакета — порядок файлов и элементов в `package.json`. От файловой системы порядок не зависит.
   Индексы типов в `ScenarioDesc` — это порядок всех типов набора в каталоге (как `vehicle_types.types` сейчас),
   поэтому `base` даёт те же индексы `car = 0`, `bus = 1`, и golden-хэши не меняются.
6. **Валидация — в `Sim.Scenarios`** (net8, IO разрешён; ядро файлов не видит): схема каждого JSON (неизвестный ключ — ошибка,
   как в `scenario-format.md` §1), диапазоны параметров, ссылки на id, пределы ядра (`MaxVehicleTypes` = 256 и др.), glTF
   (структура, URI, расширения, наличие LOD-уровней по ADR-0014). Ошибка выдаётся списком `(файл, путь JSON, код)`.
   Пакет с ошибкой не грузится целиком, частичной загрузки нет.
7. **Безопасность.** Белый список расширений (`.json`, `.gltf`, `.glb`, `.bin`, `.png`, `.jpg`, `.ktx2`). Всё остальное —
   ошибка, в том числе Godot-ресурсы `.tscn/.tres/.res/.gd`: они могут содержать скрипты. Пути только относительные,
   внутри пакета, без `..`, симлинков и абсолютных URI. URI glTF — только файлы пакета (`data:` разрешён в лимите).
   Пределы (размер пакета, файла, глубина JSON, число ассетов, размер текстур) — таблица в `modding.md` §7. Пакет
   на этапе 4 — это каталог; архивы (zip-бомбы) появятся позже вместе с пределами распаковки.
8. **Отсутствующий ассет → заглушка + событие, сейв не ломается** (ADR-0012 п.8 без изменений). Сейв несёт симуляционные
   параметры. При загрузке каталог хоста сверяется с `MANI`. Отсутствующий ассет: ядро продолжает по параметрам из сейва,
   клиент рисует контрастный бокс по габаритам с меткой «?», хост выдаёт `AssetNotice` (вид, id, число сущностей) в отчёт
   и UI. Запись `MANI` при пересохранении остаётся: вернули мод — вернулся визуал. **Новый** город (из сценария) с
   отсутствующим id — ошибка загрузки сценария: сохранённых параметров у него нет.
9. **Версии параметров типов: строки `VTYP` только дописываются** (закрывает бэклог «новые параметры только для новых спавнов»).
   Обновлённый ассет (`ContentHash` другой) при `AssetParams = UseCurrentForNewSpawns` получает **новую строку** таблицы
   типов. Спавнер (`TypeMix`) и маршруты автобусов, которые ссылались на старую строку, переключаются на новую. Старая строка
   помечается `Retired` и остаётся, пока её используют живые машины: их параметры не меняются, физика без скачков.
   В `MANI` по записи на строку (тот же id, `Version` = ревизия ассета). Переполнение 256 строк — обновление этого ассета
   не применяется (остаются старые параметры), отчёт это отмечает. Режим по умолчанию: у клиента — `UseCurrentForNewSpawns`
   (решение владельца, 2.6b), у headless/тестов/корпуса — `Saved` (побитовое продолжение).
10. **Дороги ссылаются на ассет.** У сегмента появляется столбец `Asset u16` — индекс в `MANI`, ядро его не трактует.
    Он приходит через новое поле `BuildRoadCmd.Asset`. Хост разворачивает тип дороги из пакета в поля команды
    (полосы, скорость, `RoadKind`). Симуляционные параметры остаются в самом сегменте, поэтому без мода дорога работает,
    а клиент рисует её профилем по умолчанию с меткой. Индекс вне манифеста — `RejectReason.UnknownAsset`.
11. **Детерминизм.** Состояние и продолжение не зависят от набора модов: всё нужное лежит в сейве. Новый город — функция
    `(сценарий, набор пакетов)`. В `MANI` пишутся записи пакетов (вид 4: id, версия, xxh64 симуляционного содержимого) и
    **отпечаток контента** — xxh64 по упорядоченному списку пакетов. Отпечаток входит в результат bench, в заголовок
    реплея (`RPLH`) и в корпус: реплей или golden с другим отпечатком не сравниваются (ошибка, а не ложная регрессия).
    `StateHash` не расширяем (решение владельца 2.6b). Rust-хост строит тот же `ScenarioDesc` по тем же правилам
    (`modding.md` §5), кросс-тест — фикстура пакетов.
12. **Совместимость версий.** У каждого вида JSON свой `format_version`. Загрузчик принимает диапазон версий `[min, текущая]`
    и поднимает старые форматы чистыми функциями «JSON vN → vN+1», как миграции сейвов. `package.json` объявляет
    `content_format` (версию набора форматов). Фикстура-мод прошлой версии всегда грузится в CI (`cs2-lessons.md` №5).
    Версия API команд — `CoreInfo.ApiVersion` (semver), её проверяет таймлайн сценария.

## Последствия
- Базовый контент переезжает в `content/base/`. `scenarios/vehicle-types.json` остаётся для `format_version: 2` (тесты и
  бенчи не трогаем). Сценарии `format_version: 3` ссылаются на пакеты и id типов. Golden-хэши s1k/s10k при загрузке через пакет
  `base` обязаны совпасть побитово: это приёмка M2.
- Изменения ядра маленькие и последовательные: `SEGS.Asset`, `BuildRoadCmd.Asset`, `UnknownAsset` (M4), строки типов с
  `Retired` и перепривязка спавнера при `Load` (M5). Обе задачи поднимают `world_version` после w2 пешеходов (3.1) и
  трогают API ядра, поэтому идут строго после волны 3.1 и друг за другом.
- Модам нельзя переопределять базу. «Улучшенный автобус» — это новый тип, игрок выбирает его в настройках города
  или сценарии. Явная замена (`replaces` с согласия игрока) — позже, отдельным решением.
- Проверка glTF живёт в `Sim.Scenarios` и вызывается в CI (`Sim.Headless validate-package`). До ADR-0014 она проверяет
  только структуру и наличие LOD-уровней, бюджеты треугольников не применяются (предел = ∞, помечено `TODO(ADR-0014)`).
- Ассет без визуала (`visual` не задан) рисуется процедурным боксом, как сейчас. Это не «ассет без LOD»: правило ADR-0014
  относится только к присланным моделям.
- Зависимостей в ядре нет. В `Sim.Scenarios` уже есть `System.IO.Hashing`, glTF разбираем сами (JSON-часть + заголовок GLB),
  без NuGet.

## Альтернативы
| Вариант | Почему нет |
|---|---|
| Код-моды (C# DLL, Harmony) | S3: ломаются от каждого обновления; нет песочницы; на Rust невозможно; детерминизм и 0 B/тик не гарантируются |
| Скрипты Lua/WASM уже сейчас | новая зависимость и ADR, детерминированный интерфейс к ядру; задачам этапа 4 не нужны (п.3) |
| Встроенный контент отдельным путём, моды потом | ровно S2: пайплайн переделывают, когда приходят моды; dogfooding ловит ошибки загрузчика на своём контенте |
| Переопределение чужих ассетов по id (load order) | неочевидные конфликты двух модов, результат зависит от порядка; сейв не знает, чья версия действовала |
| Новые параметры сразу для всех машин | скачок физики живых машин (длина и IDM посреди полосы, нарушение I6); продолжение отличается от «как было» без пользы |
| Сейв хранит только id, параметры берёт из пакета | S1: без мода сейв не грузится или симуляция идёт иначе |
| Id без пространства имён (`car`) | коллизии между модами; перенос ассета между пакетами невозможно отличить от переименования |
| Тип дороги — таблица в ядре | ядру он не нужен: симуляционные поля уже в сегменте; таблица — лишнее состояние в сейве и API |
