# ADR-0041: Службы — записи данных поверх двух механизмов, общий диспетчер, болезнь без связей жителя

Статус: предложено (агент L97, 2026-10-30; спека — `docs/design/services.md`, ждёт утверждения владельцем)

## Контекст
Владелец решил (тема 5 `global-topics.md`): два рода служб — «к ним ходят» (цель поездки + вместимость) и «они выезжают» (диспетчер +
машины), служба — данные, новая служба — новая запись; v1 — ЖКХ, медицина (поликлиника + скорая), пожарные; уровни с ролями, апгрейд
на месте, локальные апгрейды, оплата база + нагрузка + ползунок 50–150 %; отклик зависит от реального трафика, скорая и пожарные —
с частичным приоритетом VC. BL (ADR-0040) уже вводит депо ЖКХ, бригады `CrewStore`, связь машины `Resident ≤ −2` и агрегатный режим.
В ядре нет ссылок жителя на учреждения, туры не переходят через полночь, план дня строится по событию раз в сутки.

## Решение
1. **Запись службы — новый вид контента `services.json`**; поведение — перечисления кода (роли уровней, виды вызовов, поводы визита,
   эффекты апгрейдов). Новая служба на имеющихся поводах — только JSON; новый повод — код + запись. ЖКХ BL становится записью `utility`.
2. **Режим `city.services`** (требует `city.lifecycle`). Без него ЖКХ работает и хэшируется ровно как в BL.
3. **Один диспетчер на все выездные записи:** два кольца на запись (срочные, обычные), до 4 выездов за тик, станция — минимум оценки
   времени в пути по скиму ячеек (с пробками), без поиска пути; машина — BL-бригада со ссылкой на станцию; приоритет — `SetOnCall` по
   признаку вида вызова (у ремонта запрещён валидатором).
4. **Болезнь — байт жителя `Ill`**, бросок хэшем `(seed, сутки, житель)` при составлении плана дня — без PRNG-потока и сейв-состояния.
   Связи житель ↔ больница нет: запись на приём — счётчик визитов здания, койки — счётчик станции с кольцом выписки по суткам, вызов
   скорой держит ссылку на жителя. Выпадение из экономики — отсутствие рабочих туров (существующие пути зарплаты и налога).
5. **Пожар — пул пожаров** с броском хэшем в дневном проходе по зданиям, ущерб — в состояние BL; без распространения в v1.
6. Большой уровень — пристройка до 3 соседних участков (флаг участка), а не слияние геометрии: LP может заменить это позже.

## Последствия
- Плюс: эталоны `*-res`, `*-res-bl`, s1k/s10k, Rust не меняются; горячий цикл машин не трогается; диспетчер — микросекунды в худший тик;
  моды добавляют службы и уровни данными; рассказчик (ST) получает события пожаров и вызовов.
- Минус: стационар — условность (житель дома, койка занята); пристройка — временная модель до LP; оценка по скиму грубая внутри 1-км
  ячейки; выбор станции меняет поведение ЖКХ BL (пересборка эталонов `*-res-bl` в SR2, если владелец выберет вариант А §10.2).
- Отвергнуто: служба — класс кода на каждую (противоречит решению владельца); ссылка жителя на учреждение (+4–8 Б на жителя ради
  долей процента больных); PRNG-поток для болезней (порядок и сейв-состояние); поиск пути от каждой станции на вызов (нагрузка на
  s100k); многодневное пребывание в больнице как тур (ломает инвариант «тур в пределах суток»).
