# ADR-0031: бенч s1k в CI — A/B с базовым коммитом на том же раннере

Статус: принято (владелец, 2026-10-28). Дополняет ADR-0007 (гейт производительности).

## Контекст
CI-job `build-test-bench` сравнивал p95 тика s1k с сохранённым числом `perf/baseline-ci.json` (0.2148 мс, снят один раз на AMD EPYC 7763).
Раннеры GitHub разнородные (AMD 7763/9V45/9V74, Intel 8370C/8573C), скорость одной модели плавает; три попытки `bench-gate` идут на одной ВМ
и расходятся на 1–3 %, поэтому повтор не спасает. Итог 2026-10-27/28: 18 из 37 прогонов `dev` красные при одинаковой работе на тик
(зелёные p95 0.146–0.226 мс, красные 0.275–0.303 мс) — гейт ловит раннер, а не код (разбор — агент 164, `stage4-plan.md`).

## Решение
- В CI бенч s1k сравнивается не с сохранённым числом, а с **базовым коммитом, собранным и запущенным в той же job на том же раннере**.
- База: для `pull_request` — merge-base с целевой веткой; для `push` — первый родитель (`HEAD^1`); для `schedule` и первого коммита — гейт по бюджету (`--budget-p95-ms 1.0`).
- Прогоны вперемешку: B1 H1 B2 H2 B3 H3 (каждый — отдельный процесс с параметрами `bench-gate.sh`), чтобы дрейф раннера ложился на обе стороны.
- Провал: медиана p95 головы > медианы p95 базы × 1.10 **и** минимум p95 головы > максимума p95 базы (множества прогонов не пересекаются);
  любые аллокации на тик у головы; разный `ramp_complete`. Бюджет s1k ≤ 1 мс проверяется всегда.
- Если база не собирается (старый коммит, другой формат) — предупреждение и гейт по бюджету, не провал.
- `perf/baseline.json` и облачный `scripts/bench-gate.sh` (Stop-хук, DoD в облаке) не меняются; `perf/baseline-ci.json` больше не используется CI.

## Последствия
- Ложные красные от раннеров исчезают; реальная регрессия ≥ 10 % с непересекающимися прогонами ловится в том же PR/коммите.
- Время job растёт на сборку базы и 3 лишних прогона (~2–3 мин).
- Медленный дрейф (много мелких регрессий по 5 %) A/B не видит — его ловит облачный `bench-gate` против `perf/baseline.json` и бюджеты.

## Уточнение 2026-10-28
Релизный PR `dev` → `main` и push в `main` (squash-мерж такого PR) гейтятся по абсолютному бюджету (`bench-gate.sh --budget-p95-ms 1.0`), а не A/B: сравнение через целые этапы мерит принятый рост (например, p95 0.167 → 0.220 мс при бюджете ≤ 1 мс), а не регрессию. Рост фиксируется в `REPORT-stage*.md`. Для остальных PR и push A/B без изменений.
