# ADR-0005: Маршрутизация — A* по направленным сегментам, кэш магистралей по парам зон

- Статус: принято, 2026-10-24
- Спецификация: `docs/design/routing.md`

## Контекст
ТЗ: A* с весом = время, кэш по парам зон, бюджет запросов на тик, маршрут на уровне полос (`core-api.md` §5.5),
0 B/тик, детерминизм. Точки старта/финиша случайны внутри зоны — маршрут «зона → зона» буквально не применим.

## Решение
1. **Граф** — направленные сегменты (`seg·2 + dir`), дуги — манёвры (есть connector). В 5× меньше
   вершин, чем у графа полос; штрафы поворотов и узлов — на дугах. CSR, полный rebuild при `BuildRoad`.
2. **Вес** статический: `Length/SpeedLimit` + штраф манёвра (0/3/6/20 с) + штраф узла (светофор —
   средняя задержка `(C−g)²/2C`, yield/stop 6/9 с, помеха справа 3 с). Загрузка — этап 2.
3. **A\*** с евклидовой эвристикой `/VMax` (монотонна), предвыделенная бинарная куча с ленивыми
   дубликатами, штампы `SearchId` вместо очистки, ничьи — по индексу вершины. Нет PRNG.
4. **Кэш** хранит магистраль хаб(A) → хаб(B) по ключу `(FromZone, ToZone)` (`FixedHashMap`, LRU в
   окне пробирования по `LastUsedTick`); маршрут машины = локальный префикс + магистраль + локальный
   суффикс (ограниченные поиски ≤ 512 раскрытий), скопированный в индивидуальную запись `RoutePool`
   (`RefCount = 1`). Инвалидация при `BuildRoad` — ленивая по `NetworkVersion`; индивидуальные маршруты
   не инвалидируются (сеть только растёт).
5. **Раскладка на полосы** обратным проходом: целевая полоса сегмента = входная полоса выбранного
   connector'а; MOBIL получает контракт «подготовка к повороту» (срочность по дистанции, смягчение
   `b_safe`, замедление для поиска окна). Промах полосы → connector по умолчанию + перемаршрутизация
   из очереди; машина никогда не стоит в ожидании перестроения.
6. **Бюджет**: `PathfindBudgetPerTick` запросов и `256×` раскрытий на тик; маршрут строится **до**
   спавна (поля в `PendingTrip`), поэтому машины без маршрута на дороге не стоят.
7. `pathfind_ms_p95` меряет хост через зонд `Simulation.OnPhaseEnd` — ядро не знает wall-clock.

## Последствия
- Маршрут через хабы длиннее прямого на ≤ ~2 стороны зоны; принято ради кэша и предсказуемой нагрузки.
- `max_routes` для s1k → 8 192 (машины + используемые пары зон). Новые поля: `RoutePool.LastUsedTick`,
  `PendingTrip.Route/RouteGen/DestLane/DestS`, `ZoneData.HubNode`, счётчики маршрутизации, зонд `OnPhaseEnd`.
- s1m без иерархии: полный A* по 660 k вершин — только baseline; «хаб → хаб» готов к надстройке (CH) на этапе 2.

## Отвергнутые альтернативы
- **Граф полос** с дугами смены полосы: ×5 вершин; те же решения даёт раскладка после поиска.
- **Кэш полного маршрута по паре зон**: все машины пары стартуют в одной точке; K вариантов не влезают в арену.
- **Поиск на каждую машину без кэша**: для s1k дёшево (0.15 запроса/тик), на s1m — сотни мс/тик.
- **Dijkstra/ALT/CH сразу**: преждевременно для 1.7 k вершин. **`Stopwatch` в ядре**: запрещён; зонд фаз чище.
