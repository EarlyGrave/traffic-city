# ADR-0029: Карманы автобусных остановок — виртуальный карман (вариант A)

- Статус: принято, 2026-10-27 (решения владельца 2026-10-27, см. `docs/design/bus-bays.md` §7); реализация BB1 — агент L12, ветка `local/bb1-bays`.
  Уступка (BB2) и правки сети с автобусом в кармане (BB2) — позже.
- Затрагивает: ADR-0008 (автобусы этапа 1: «карман как обочина»), `bus-bays.md`, `scenario-format.md` §2.4 (`transit`), `save-format.md` §12 (`world_version` 7),
  `core-api.md` §6.3 (флаги машины), снапшот рендера (ADR-0010, двухосная модель L3b).

## Контекст
- Остановка `BusStopKind.Bay` в данных была (генератор при `stop_kind: mixed` даёт `Bay` артериям), поведения — нет: ADR-0008 и `BusStopRules` моделируют `Curb` и `Bay`
  одинаково — автобус стоит на полосе остановки и блокирует её на время стоянки.
- Замер ADR-0028 (s10k, 3 сида, 175 эпизодов ожидания ≥ 60 с): **35 % эпизодов (62) — за автобусом на остановке**; бюджет доли ожиданий s10k (≤ 0.15 %) не сходился
  (медиана 0.336 %). Вторая причина (коробки 26 м на светофорах, очереди к `Yield`) — вне этого ADR.
- `LaneKind.BusBay` объявлен в данных, но ни одной такой полосы сеть не строит.

## Решение
1. **Виртуальный карман (вариант A).** Автобус на остановке `Bay` на время стоянки снимается со списка полосы (`LaneOccupancy.Unlink`, `Lane = -1`), получает флаг
   `VehicleFlags.InBay = 64` (инвариант `InBay ⇒ IsBus ∧ AtStop ∧ Lane == -1 ∧ Ahead/Behind/GhostLane == -1`), стоит в `S = stop.S`; ведомые проезжают мимо без MOBIL.
   Правила только при `transit.bay_model = "virtual"`, `Kind == Bay`, `Lod.Mode == Off`; иначе — как `Curb` (`BayFallbacks++` для `Bay`, когда карман не принял).
2. **Въезд** — условие прибытия прежнее (на полосе остановки, ≤ 3 м, ≤ 0.5 м/с) плюс: карман свободен (`BayUsed == 0`) и точка остановки вне горизонта ворот —
   `LaneLength − stop.S ≥ max(30 м, max_типов(MinGap) + 1.5 м)` (та же оценка, что `farDistance` фазы 4). **Ёмкость — 1 автобус**: второй при занятом кармане обслуживается в полосе.
3. **Выезд — gap acceptance** (`BusStopRules.ExitGap`), каждый тик после конца стоянки: впереди зазор ≥ `s0` автобуса; сзади `b`: зазор ≥ `s0_b + v_b·T_b` и
   `v_b² / (2·(зазор − s0_b)) ≤ b_comf,b` (параметры IDM типа `b`, новых констант нет); `b` не допущен воротами; полоса не `Closed`/`Draining`. Вставка в `stop.Lane` в
   `s = stop.S` (`InsertBetween`, `ChooseConnector`), скорость 0. **Маршрут к следующей остановке строится в тик выезда** (от `(stop.Lane, stop.S)`), а не в конце стоянки:
   пока автобус не выехал, `BusNextStop` остаётся остановкой кармана (инвариант и связь автобус → остановка без обратной ссылки), отложенное построение — повтор на следующем тике.
   На конечной зазор не нужен (автобус исчезает, карман освобождается в `Remove`).
4. **Данные.** `BusStopData`: `ushort Reserved` → `byte BayUsed, byte BayFlags`, новое поле `long BayExitFrom` (−1 — не ждёт; в конце структуры, прежние поля не сдвинуты).
   Производное (вне хэша и сейва, пересобирается после загрузки): `World.BayBus[остановка] → слот автобуса` — нужно только снапшоту вида.
   `SimCounters`: `BayEntries`, `BayFallbacks`, `BayYields` (BB2), `BayExitWaitTicksTotal`.
5. **Снапшот.** Слот `InBay` рисуется на `(stop.Lane, stop.S)` со смещением `LateralOffset = −LaneWidth` (из опций построителя `w.Builder.Options.LaneWidth`, не константа клиента);
   флаги `Active | AtStop`. Вид (ADR-0019) добавляет автобусы из карманов остановок, чья полоса пересекает вид. Двухосная модель L3b (`_rearX/_rearZ`) работает по `(lane, s)`
   носа: при заезде нос сдвигается вбок за один тик, задняя ось остаётся на месте (расстояние до носа уже равно базе), поэтому кузов стоит в кармане под углом
   ≈ `atan(ширина полосы / база)` к оси (≈ 20° у автобуса 12 м); при выезде нос возвращается на ось, задняя ось подтягивается по обычному правилу (`R = F − norm(F − R_prev)·база`).
   Разрыва больше `ResyncDistance` нет, «хлыст» ограничен базой. Если угол окажется заметным — доводка в клиенте (BB2), состояние ядра не затрагивает.
6. **Метрики фазы 9.** Автобус в кармане остаётся живым и учтённым фазой 6 (скорость 0; `Move` для `Lane < 0` не вызывается, `StillTicks` не растёт — `AtStop` и так «обслуживает остановку»):
   `Masks.Remove` на въезде не нужен (он нужен только деспауну).
7. **JSON** `transit.bay_model`: `"virtual"` (дефолт загрузчика, решение 1 владельца) | `"curb"` (прежнее поведение; его же ставит `MigrationV7` старым сейвам) | `"lane"`
   (**зарезервировано** под настоящую полосу-карман `LaneKind.BusBay`, вариант B остаётся на будущее; пока ведёт себя как `curb`). `bay_yield_s` (0..60, дефолт 3) разбирается и
   хранится (`BayYieldTicks`), использует BB2. Нулевая структура `TransitDesc` (программные desc в тестах) — `Curb`: хэши тестов без загрузчика не меняются.
   Поля `BayUsed`/`BayFlags`/`BayExitFrom` и правила въезда/выезда не зависят от того, виртуальный карман или полоса: вариант B потом меняет только «куда уходит автобус»
   (`Lane = −1` → полоса `BusBay`).
8. **Хэш.** Раздел 6a: `BayUsed/BayFlags/BayExitFrom` по остановкам и четыре счётчика — только при `bay_model = virtual` и наличии остановок `Bay`; иначе хэш побитово прежний.
   Флаги машин (с `InBay`) и `Lane = −1` уже в хэше.
9. **Сейв** `world_version` 7: `PARM` 186–187, `BDYN` 10–12, `CNTR` 150–153; `MigrationV7` (`bay_model = curb`, поля кармана нулевые) — корпус `w1`–`w6` продолжается прежними хэшами.
   Валидатор: `Flags ≤ 127`; `InBay` — инвариант п. 1 и существующая целевая остановка; `BayUsed ∈ {0,1}` и равен числу автобусов `InBay` остановки; карман только у `Bay` при
   `virtual`; `BayFlags` — известные биты; `BayExitFrom ∈ [−1, Tick]`, только при занятом кармане.

## Последствия
- **Хэши и корпус.** Сценарии из JSON (`scenarios/*.json`, дефолт `virtual`) получают другое поведение при остановках `Bay`: эталоны `HotPathGoldenHashTests`, `AdaptiveGoldenHashTests`,
  `BasePackageGoldenTests` и корпус `w7-*` сняты заново отдельным коммитом. `NetworkStore.Hash()` и golden Rust-пилота не меняются (сеть та же, транзит в пилоте не портирован).
  Облачный `perf/baseline.json` устарел по хэшам/поведению — `update-baseline` в облаке отдельным коммитом (локально не запускался).
- **Не сделано в BB1 (BB2).** Уступка ведомых автобусу, ждущему выезда (`bay_yield_s`, `BayFlags.Yield`, виртуальная стена в фазе 5): без неё автобус в кармане ждёт честного зазора, и в плотном
  потоке (или при очереди автобусов у остановки) может ждать долго. Правки сети с автобусом в кармане: снос остановки сейчас снимает автобус (`BusStopPhase.Remove`, пассажиры выходят) — защитное
  поведение; снос/дренаж сегмента, `Relocate` и «не считать полосу пустой, пока в кармане её остановки автобус» — BB2. Смещение/анимация въезда в клиенте `game/` — BB2.
- **Известное.** Автобус из кармана вставляется в `S = stop.S`, а заезжал в ≤ 3 м раньше: позиция при заезде/выезде сдвигается не более чем на 3 м. Очередь автобусов у остановки (пачка,
  `headway` меньше стоянки) держит карман занятым: стоящий в полосе на точке остановки блокирует выезд автобуса из кармана, пока не отправится сам.
