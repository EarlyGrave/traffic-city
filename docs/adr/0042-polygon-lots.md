# ADR-0042: Участки — простые многоугольники в целых мм, занятость корзинами 32 м, нарезка по кромке дороги

Статус: предложено (агент L98, 2026-10-30; спека — `docs/design/lots-polygons.md`, ждёт утверждения владельцем).
**Частично заменяет ADR-0030:** пункт «участки всегда лежат на мировой сетке 8 × 8» и `road-profiles.md` §4.2–4.5 (нарезка
прямоугольниками клеток, столбцы `LOTS` 11–15, здания по сетке с уступами). Профили дорог, мировая сетка как привязка дорог и
отсчётов рельефа, генератор на сетке (`road-profiles.md` §1–3, §4.1, §5) остаются в силе.

## Контекст
Владелец решил (тема 2 `global-topics.md`, 2026-10-29): участки в два слоя — кисть (авто-нарезка, дом идёт по кромке дороги,
заполняет уступ, повторяет дугу, скруглённый угол) и крафт (участок любой формы, пятно, отступы, этажность, парковка). Сейчас участок —
прямоугольник `F × D` клеток 8 м по осям `±x/±z` (RP5): на косых и кривых дорогах ступеньки и газонные треугольники, покрытие фасада
диагоналей — 0.80 от ортогоналей (RP8); хранилище только дописывается, поколения нет; сетка занятости 3 Б на клетку 8 м (s1m ≈ 111 МБ);
ёмкость здания не зависит от участка. Детерминизм и перенос на Rust требуют целой геометрии.

## Решение
1. **Участок — простой многоугольник** (3–16 вершин, вогнутые допустимы, без дыр), вершины — `int` мм в общей арене с уплотнением,
   класс каждого ребра (фасад, второй фасад, бок, тыл) и главный фасад — состояние. Фасадная привязка `Seg/Side/S0Mm/S1Mm` сохраняется:
   точки доступа, обочина и перенос участков при правке цепочки работают прежним кодом.
2. **Геометрия только целая:** `int64`/`Int128`, свой `isqrt`, нормали Q16, деление с округлением к −∞; ни float, ни `sqrt` в нарезке,
   пересечении и площади. Тот же код — в Rust (векторы в golden).
3. **Занятость — корзины 32 м со списками + точный целый тест пересечения** многоугольников; поверхность дороги (ленты и площадки узлов)
   строится из тех же целых точек, что фасады, — касание без перекрытия. Сетка клеток 8 м с маской 4×4 удаляется.
4. **Одна нарезка кистью** для режимов с профилями и без: кромочная ломаная, равные куски фасада, бока по нормали (биссектрисе),
   тыл — смещение фасада, глубина подбирается вниз шагом 4 м; угловой участок с дугой Безье при углах 60–135°; продолжение через узел —
   без разрыва. Порядок фиксирован, первый занявший побеждает. Нарезка — главный поток вне параллельных фаз.
5. **Хранилище — пул с поколением**, слоты освобождаются суточным шагом; правки дорог и покраска пересчитывают только затронутые участки.
6. **Ёмкость здания — от площади пятна × этажи** (`unit_m2` типа), пишется в здание; тип подбирается по габариту пятна.
7. **Крафт v1 — шесть команд с payload ≤ 56 Б** (форма, вершина, параметры, разрез, слияние, удаление); пристройки SR заменяются слиянием.
8. Сейв — следующий свободный `world_version`, без миграции (режим прототипа); корпус и эталоны с городом пересобираются.

## Последствия
- Плюс: дом параллелен любой дороге, фасад диагоналей не теряется; у `Lost`-участка есть геометрия; занятость на s1m ≈ 82 МБ вместо
  111 МБ (оценка); крафт и кисть на одном ядре; FR задаёт свои классы нарезки данными; рельеф получает площадку = пятно.
- Минус: участок дороже в памяти (≈ 160 Б против 86 Б, оценка); нарезка s100k-res — оценка ≈ 2 с в `Create` (замер LP8); меняются
  хэш города, сейвы и корпус всех сценариев с городом, калибровка `*-res`; удаляются тесты сетки RP5 и клеточные поля API клиента.
- Отвергнуто: растр 1–2 м (общие рёбра соседей «перекрываются», зависимость от округления); сетка 8 м как широкая фаза (больше памяти
  при той же работе); фиксированный шаг 16 вершин на участок (≈ 144 Б только на вершины); участки только в покрашенной области
  (ломает генератор, службы и автозонирование ради того же результата); `float` с допуском (расхождение платформ и Rust).
