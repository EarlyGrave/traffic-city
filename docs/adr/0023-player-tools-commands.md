# ADR-0023: Инструменты игрока через команды API

- Статус: предложено, 2026-10-25 (архитектор этапа 4.3, агент #97)
- Спецификация: `docs/design/player-tools.md` (задачи T1–T14); поправки (делают задачи): `core-api.md` §4/§5.6/§5.7/§7/§12,
  `routing.md` §9.3/§9.6, `save-format.md` §1/§12/§13 п. 6, `pedestrians.md` §2, `intersections.md` §5.7, `scenario-format.md` (секция `tools`)

## Контекст
- Сеть сейчас **только растёт**: `BuildRoad` в построенный узел → `NotSupported`, сноса нет, connector'ы и входы оверлея лежат
  в каноническом порядке «по возрастанию индекса узла / DirSeg» (save-format §13 п. 5), `IncHead/Cells` производны «в порядке вставки»
  (§13 п. 6 — открыто до появления сноса). `CreateBusRoute/AppendBusStop` отклоняются (`NotSupported`).
- Этап 4 — играбельный срез: игрок строит/сносит дороги, меняет полосы, ставит остановки, светофоры и знаки, отменяет действия.
  Клиент не трогает внутренности ядра (правило 5): всё — `Enqueue(in Command)`, ответы — события и снапшоты.
- Правило проекта: **застрявших не деспауним**. Машина или пешеход на сносимой дороге не может «исчезнуть».
- Урок CS2 T6: граф достижимости проверяется при постройке, а не после того, как сим «вышел и не может вернуться».
- Детерминизм и потоки (ADR-0017): фаза 1 однопоточная; хэш не зависит от числа потоков; 0 B/тик.

## Решение
1. **Один канал — команды.** Новые `CommandKind` (с 25 - 12, 23, 24 заняты `SetPedTarget`/`PaintZone`/`SetTripExecution`; только добавлением, 64 Б, раскладка C ABI): `RemoveRoad`, `UpgradeRoad`,
   `SplitRoad`, `MergeAtNode`, `SetArmControl`, `SetTurnBan`, `SetLaneFlags`, `InsertBusStop`, `RemoveBusStop`, `RemoveBusRoute`, `SetBusRouteParams`,
   реализация `CreateBusRoute`; `BuildRoad` получает кривую (контрольная точка) и врезку в существующий узел. `PaintZone` — номер и
   payload зарезервированы, до ADR-0011 → `NotSupported`. Ссылки на объекты в командах — **handle (index + generation)**, не голые индексы.
2. **Сеть с дырами.** Узлы, сегменты, остановки, маршруты — пулы с поколениями и free-list (LIFO). Диапазоны (`Lanes` блоками
   сегмента и узла, `LanePoints`, `NodeArms`, `LaneNext`, конфликты, `SegmentPoints`, `BusRouteStops`) — **арена блоков** с ёмкостью
   по лестнице и LIFO-free-list на класс; блок не влез — новый в конце, старый → дыра с каноническими нулями. Connector'ы узла остаются
   подряд (`LocalBit < 64`). Компактификации во время игры нет. Свойство «раскладка = построенной заново» (§13 п. 5) **снимается**
   для отредактированных сетей: раскладка — состояние, сейв её хранит (connector'ы и так сохраняются). Все производные определяются
   **по возрастанию индекса живых слотов** (закрывает §13 п. 6), локальные обновления обязаны совпадать с полной перестройкой (тест).
3. **Три механизма правки, без деспауна:**
   - *на месте* — скорость, тип, флаги полос, знаки рукава, режим узла: мгновенно, индексы не меняются;
   - *перенос* (relocation) — правка, при которой у каждой машины есть однозначное новое место (добавить полосы, врезка/разрез
     сегмента, перестройка узла с сохранившимися connector'ами): мгновенно, одна функция переносит все ссылки на полосы
     (`Lane`, `GhostLane`, `DestLane`, окна маршрутов, `NextConn`/`GrantConnector`, остановки, `ZoneLanes`, LOD/Q-meso, пешеходы)
     по таблице `old → new`; полнота проверяется по реестру столбцов-ссылок схемы сейва;
   - *дренаж* (drain) — когда места нет (снос сегмента, убрать полосы, исчезающий занятый connector): элемент **закрывается** для
     въезда (ворота `DenyClosed`, вес `+∞`, MOBIL уводит с закрываемых полос, новые цели/спавн/пешеходные пути его обходят), машины и
     пешеходы на нём доезжают/доходят сами, планы, проходящие через него, перемаршрутизируются; удаление — когда элемент пуст.
     Застрявший дренаж не форсируется: событие `DrainStalled`, элемент остаётся «закрывается», игрок может отменить (undo).
4. **Валидация — коды, не исключения.** `RejectReason` расширяется (короткие геометрия, острый угол, перекрытие, предел узла,
   элемент занят операцией, ловушка, нет денег, маршрут недостижим…). Каждая команда — ровно одно `CommandApplied/Rejected`.
   **Ошибки** блокируют применение; **предупреждения** (тупик, зона теряет доступ, сносимая дорога занята) — только в превью.
5. **Превью = `Simulation.Preview(in Command, …)`** между `Step`: тот же валидатор, что у применения, плюс стоимость (целые деньги
   из `tools.costs` сценария; списание — точка расширения экономики 4.2), список проблем `{Code, Severity, объект, X, Z}`,
   последствия (машины/пешеходы к дренажу, остановки, зоны без доступа), привязка концов. Состояние не меняется (хэш и байты сейва
   до/после равны), 0 Б: scratch выделен в `Create`. Связность: кэш компонент сильной связности по `Net.Version` (scratch, вне хэша),
   у сноса — локальный объезд с лимитом работы, иначе пересчёт компонент.
6. **Undo — логическое, через обратные команды от ядра.** При применении ядро пишет обратную запись (до 32 команд) в буфер
   `Inverses` шага (как события): обратная команда строится из фактического состояния в момент применения. Стек undo/redo живёт
   у **хоста** (по умолчанию 100 записей); undo и redo — обычные команды. Пересозданные объекты получают новые handle:
   команда восстановления несёт `RestoreOf`, ядро шлёт `*Remapped(old, new)`, хост правит handle в стеке. Undo восстанавливает сеть
   и её настройки, а не мгновенное состояние мира (уехавшие машины не возвращаются; откат состояния — это `Load`).
7. **Журнал команд = реплей.** Хост пишет каждую поставленную команду `(Tick, Command 64 Б)` (save-format §10: `RPLH` + `CMDL`,
   контрольные хэши каждые 1 200 тиков); превью не пишется. Ре-сим с тика N = автосейв ≤ N + хвост журнала; баг-репорт = последний
   автосейв + журнал с него + версия ядра. `Sim.Headless replay` ищет первый расходящийся контрольный хэш.
8. **Детерминизм и потоки.** Все правки — в фазе 1, однопоточно, в порядке FIFO; проверка «дренаж окончен» — в начале фазы 1 по
   состоянию конца прошлого тика, операции по возрастанию id. Параллельные фазы 5/6 только читают флаги закрытия. Новое состояние
   (операции дренажа, free-list'ы, дыры, флаги, контрольные точки) — в хэше и сейве (`world_version` следующая после пешеходов);
   без правок хэш прежний (новые поля хэшируются только при непустом состоянии инструментов).
9. **Стоимость пересчётов.** Производные — инкрементально и локально (узел, сегмент, ячейки оверлея); один пересчёт графа
   маршрутов на фазу 1 при любом числе правок; полная перестройка оверлея (s100k 0.25–0.4 с в `Create`) больше не синхронна:
   раскладка — сразу, кастомизация — волной в бюджете, запросы до её конца — плоским A*. Цель: правка одной дороги на s100k ≤ 2 мс
   фазы 1, превью ≤ 0.5 мс (кроме первого после смены версии); цифры — только замером верификатора.

## Последствия
- Снимается `NotSupported` для врезки в построенный узел; дорогу можно провести в середину квартала (разрез сегмента).
- Клиент обязан пропускать мёртвые слоты в `NetworkView` (флаг `Alive`) и показывать закрывающиеся элементы (`Closing`).
- Сейв растёт на free-list'ы и арены (≈ единицы КБ); «компактный сейв» отредактированной сети без перенумерации невозможен.
- Дренаж даёт задержку сноса (десятки секунд на загруженной улице) — это видимое игроку «перекрытие», а не баг.
- Реестр ссылок на полосы становится обязательной частью DoD каждой задачи, добавляющей поле с индексом полосы/connector'а.
- Ёмкости (`MaxSegments`, арены) расходуются дырами; нехватка → `Capacity` с понятным кодом в превью. Дефрагментация — позже.

## Отвергнутые альтернативы
- **Удалять машины со сносимой дороги (как CS)** — нарушает правило «без деспауна» и прячет заторы; оставлено вопросом владельцу.
- **Дренаж для всего (апгрейд и разрез тоже)** — апгрейд забитой дороги ждал бы вечно, хотя чинить нужно именно её.
- **Резерв полос под апгрейд в каждом сегменте** — без переносов, но ×2 по памяти полос на s1m.
- **Undo откатом состояния (сейв на действие)** — выбрасывает прогресс симуляции, сейв s100k — десятки МБ на шаг.
- **Undo в ядре (стек в `World`)** — состояние в хэше и сейве без пользы для симуляции; клиентская политика — у хоста.
- **Превью на теневой копии мира** — память ×2 и копирование на каждое движение курсора.

## Реализация T1 (4.3)
- Номера: `RemoveRoad` 25 ... `MergeAtNode` 35 в порядке таблицы `player-tools.md` §1; 13-22 свободны.
- `EntityRef` (8 Б); в полях `Restore*` `Generation == 0` значит «не задано» (нулевая инициализация безопасна, `EntityRef.None` = {-1, 0}).
- `BuildRoadCmd` 56 Б, `SetSignalPlanCmd` 50 Б, `SetNodeControlCmd` 12 Б, `CreateBusRouteCmd` 20 Б; `Command` = 64 Б. Новые виды и биты
  `AutoSplit`/`Curve`/`RestoreOf` до T3..T5 дают `NotSupported`; `NodeGen` пока не проверяется (проверка - T2).

## Реализация T2 (4.3): пулы, арены, хэш, сейв (`world_version = 4`)
- **Пулы.** `NetworkStore.NodePool/SegmentPool/BusStopPool/BusRoutePool` - `HandlePool` (LIFO free-list, `HighWater`). Поколение слота хранится в `*Data.Generation` (источник правды при загрузке) и
  синхронно в пуле: **нечётное = занят, чётное = свободен**; отдельного массива `Alive` нет (решение пункта «`NetworkView` (`Alive`)»): `NetworkAlive.IsAlive(gen)`, `NetworkView.Is*Alive(i)` и
  `NetworkView.NodeRef/SegmentRef/BusStopRef/BusRouteRef(i)` (индекс + текущее поколение - то, что хосту нужно после `*Remapped`). `NodeCount/SegmentCount/BusStopCount/BusRouteCount` = `HighWater`,
  `AliveNodes/AliveSegments/AliveBusStops/AliveBusRoutes` - живые. `BusStopData.Generation` добавлено в конец структуры (поля не сдвинуты). Полоса: живая `Generation = 1`, мёртвая и запасная - `0`.
- **Мёртвые слоты** хранят канонические значения (ссылки -1, остальное 0): `NetworkStore.DeadNode/DeadSegment/DeadLane/DeadBusStop/DeadBusRoute`; валидатор сейва и `VerifyDerived` требуют именно их.
- **Арены** (`Util/BlockArena.cs`): `Lanes`, `LanePoints`, `SegmentPoints`, `NodeArms` (+`ArmFlags/ArmDir`), `LaneNext`, `ZoneLanes`, `BusRouteStops` в `NetworkStore` и строки/конфликты connector'ов в
  `ConnectorStore` (`RowArena/ConflictArena`; хвосты - `Count/ConflictsUsed`). Арена не владеет массивом, а ведёт хвост, лестницу, LIFO-free-list по классам и битовую карту «блок по лестнице».
  **Отклонение от спеки §3 п. 2:** лестница не `Overlay.CapFor` (там запас `MinSlack` и шаг по 4), а `BlockArena.CapFor`: 1..8 точно, дальше четыре ступеньки на октаву - малые блоки (полосы направления,
  рукава) без лишнего запаса, любое число раскладывается на ступеньки. Ёмкость блока по лестнице - функция числа элементов; блок, записанный генератором или сетью без правок, ёмкости сверх `n` не имеет
  (отсюда битовая карта: она говорит, какая из двух). Освобождаемый блок без запаса раскладывается жадно на ступеньки, поэтому все дыры - ровно ступеньки. Записей free-list `min(длина, max(256, длина/16))`;
  не хватило - дыра теряется (`LeakedElements`, в хэше и сейве), освобождение не проваливается.
- **Выделение** (`NetworkStore.AllocBlock/AllocLaneBlock`): при `ToolsTouched = 0` - подряд в хвосте без запаса (раскладка генератора и `BuildRoad` прежняя, TL1); после первой правки - по лестнице
  (LIFO-дыра класса либо хвост с запасом). `NetworkBuilder.AddNode/AddSegment/BuildConnectorsEx` выделяют слоты и блоки так; запас блока полос получает вид мёртвых полос.
- **Производные «по возрастанию индекса живых»:** `IncHead/IncNext` и `CellNext/Cells` ведутся вставкой/удалением в порядке убывания индекса (`NetworkBuilder.LinkNode/LinkSegment/Unlink*`) = полной
  перестройке; `RebuildIndexes`, `RebuildLaneDerived`, `RouteGraph.Rebuild/RecalcCosts` (мёртвый DirSeg: вершин и дуг нет, вес +inf), `PedNetwork` (`Built` проверяет живость узла), `LodCells.OnNetworkGrown`
  (после правок - полная перепривязка живых, мёртвые -1), индекс `RenderViewState` (по версии сети), `LotBuilder`/`CityGrid` пропускают мёртвые слоты. Оверлей маршрутизации дыр не знает (T3, §12.1).
- **Новые поля и биты** (в хэше и сейве только при `ToolsTouched = 1`, валидатор требует нули при 0): `NodeData.Flags` (`NodeFlags.Quiesce`), `NodeData.TurnBan` (бит `FromArm * 8 + ToArm`, слоты рукавов 0..7),
  `SegmentData.Flags` (`SegmentFlags.Closing/Curve`; бывший `Reserved`, `NetworkHash` читает то же значение), `Cx/Cz`, `LaneFlags.Closed/Draining`. **Кто пишет эти поля, обязан сначала поставить `Net.ToolsTouched = 1`.**
- **Хэш:** раздел 13 `StateHash` (core-api §9) - `ToolsTouched`, пулы, арены, поколения, новые поля; без правок раздела нет. Доказательство TL1: `.json` корпуса `w4-{small,s1k,s1k-peds,s1k-res}` совпали с `w3-*`
  в `state_hash` и `hash_after_continue`; файлы w1-w3 мигрируют и продолжаются прежними хэшами; golden s1k/s10k, `*-peds`, `*-res`, Rust-pilot не менялись.
- **Сейв v4:** `NETW` 13-49, `CONN` 18-25, `NNOD` 13-14, `NSEG` 13-15, `NBUS` 11; `MigrationV4`; корпус `w4-*` + `w4-small-edited-t600`; проверки - `SaveValidator.Tools.cs` (пулы, дыры арен, канон, ToolsTouched).
- **`RefKind`** (`SaveSchema.Refs`, `Save/SaveSchema.Refs.cs`): `Lane, Connector (строка ConnectorStore), Segment, DirSeg, Node, Stop` на столбцах-ссылках; `SaveValidator.ValidateRefs` проверяет диапазон
  (`InvalidReference`); тест `RefKindTests` ловит столбец, похожий на ссылку, без тега и без записи «не ссылка» с причиной. `NextConn/GrantConnector` хранят **полосу** connector'а (`Lane`). Обработчик
  переноса для каждого тега - `Relocate` (T3, `Relocate_Complete`); пешеходные рёбра (`Edge`, `HomeEdge`...) - T11.
- **Структурные примитивы** `Network/NetworkEdit.cs` (`ReleaseSegment/ReleaseNode/ReleaseBusStop/ReleaseBusRoute`, `RefreshDerived`): освобождают слот и блоки с каноническими значениями и ставят `ToolsTouched`;
  условие «пусто, можно» (дренаж), перестройка узлов и перенос - T3. `ReleaseSegment` принимает только сегменты, чьи концы не построены (`NoConnectors`); `World.VerifyDerived()` - сверка производных с полной
  перестройкой (пулы, мёртвые слоты, `Inc/Cells`, `LaneLength/Heading/GateNode`, топология `RouteGraph`, `OccMask`, LOD-привязки, строки connector'ов); оверлей, пешеходы и город - T3/T11.
- **Handle'ы в командах:** `SetSignalPlan`/`SetNodeControl` отклоняются `InvalidHandle` (+`InvalidHandleOps`), если слот узла мёртв или `NodeGen != 0` не равна поколению; индекс вне `[0, HighWater)` -
  `InvalidArgument`, как раньше. `BuildRoad` шлёт `NodeCreated` по порядку создания (`Builder.CreatedNodes`): индекс нового узла может быть меньше старых (дыры).
