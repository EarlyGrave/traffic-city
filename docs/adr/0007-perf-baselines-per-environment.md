# ADR-0007: Perf-baseline на окружение

- Статус: принято, 2026-10-24 (оркестратор)

## Контекст
`compare` падает при регрессии tick p95 > 10% относительно `perf/baseline.json`. Время тика зависит от железа:
облачный контейнер (где работают сессия, хуки Stop и агенты) и раннер GitHub Actions — разные машины.
Один общий baseline даёт ложные регрессии или маскирует настоящие.

## Решение
- `perf/baseline.json` — эталон **облачного контейнера**: по нему сверяются Stop-хук и агенты.
- `perf/baseline-ci.json` — эталон **раннера CI**: по нему сверяется шаг compare в `ci.yml`.
- В CI шаг compare с `perf/baseline-ci.json` заменён A/B с базовым коммитом на том же раннере (`scripts/bench-ab.sh`, ADR-0031).
- Оба файла меняются только командой `Sim.Headless update-baseline --from <result> --baseline <файл>`
  (ручная правка блокируется хуком), отдельным коммитом с объяснением.
- CI печатает JSON результата bench в лог (и кладёт артефактом); CI-baseline снимается из этого вывода.
- Пока `perf/baseline-ci.json` нет, CI проверяет только аллокации (0 B/тик) и абсолютный бюджет p95 ≤ 1 мс для s1k.
- Аллокации > 0 — ошибка в любом окружении.

## Последствия
- Регрессии сравниваются «яблоки с яблоками».
- При смене типа раннера CI baseline-ci обновляется осознанно.
- Шум p95 на общих раннерах остаётся; при ложных срабатываниях — повторные прогоны в bench (медиана из 3).
